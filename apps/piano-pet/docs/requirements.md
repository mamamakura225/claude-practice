# ピアノペット 要件定義書

> **何を・誰のために作るか（WHAT）**の正本。画面・報酬の具体仕様は [features.md](./features.md)、データ構造・同期は [data-model.md](./data-model.md)。
> **更新ルール**: `apps/piano-pet/` のソースを変更したら関連docsへ必ず反映（[CLAUDE.md](../../../CLAUDE.md)）。

## 1. 概要・目的

5歳の子供のピアノ練習を**習慣化**するための PWA。親が練習記録を入力し、子供と一緒に結果を見て楽しむ。猫の育成・きせかえ・えさやり・バッジ収集によるゲーミフィケーションで継続を促す。

## 2. ターゲットユーザー・利用形態

| 項目 | 内容 |
|---|---|
| 親 | 練習記録の入力・編集 |
| 子供（5歳） | 猫の成長・なでなで・きせかえ・バッジを親と一緒に確認 |
| 端末 | スマートフォン中心（PWAでホーム画面に追加）・認証なし |
| 記録単位 | 「1回 = 1曲を1回弾く」。**1日の目標は既定10回**（親ゲート内で 5〜20 に調整可・#238）。ごほうびコインの達成ボーナスは目標に依らず**10回で固定** |

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| データ保存 | localStorage を主とし、Firebase Firestore へクラウド同期（複数端末で共有）。スキーマはバージョン管理しマイグレーション可能（→ [data-model.md](./data-model.md)） |
| 起動速度（#142） | 起動時は localStorage を即読み込みホームを同期描画し、クラウド同期はアイドル時間まで遅延してバックグラウンド実行（朝の忙しい時間でも一瞬で記録を始められる）。初回取り込みは同期完了前のローカル記録を消さないようローカル優先でマージ |
| オフライン / PWA | manifest + Service Worker でオフライン動作・ホーム画面追加に対応。クラウドSDKは動的読み込みで、取得失敗時もローカルのみで起動できる。キャッシュ戦略と起動速度との関係は → [features.md](./features.md)「Service Worker のキャッシュ戦略」 |
| UI方針 | 5歳でも読めるよう**ひらがな主体**。タップ操作中心の大きなボタン |
| サウンド | Web Audio API（効果音）＋録音サンプル（鳴き声）。端末ローカル設定でON/OFF。省電力のためアイドル時・タブ非アクティブ時は AudioContext を自動 suspend（#146） |
| 軽量性（#147 / #284） | 配信アセット（HTML/CSS/JS）の gzip サイズに**パフォーマンス予算**を設け、CI（`perf-budget:check`）で超過を検知して失敗させる。予算は `scripts/perf-budget.mjs` の `BUDGETS_KIB`。JS は**起動をブロックするぶんと遅延読込を分けて**測り、厳しい上限は前者に掛ける。押されるまで不要な機能（きせかえ編集・写真モード・親ゲート/バックアップ）は動的 import にし、クラウド同期は起動をブロックしないよう idle で読む（帯域は毎回かかる）。画像・音声は判定対象外だがレポートには出す（→ [features.md](./features.md)「アセット総量」） |
| プライバシー / 計測 | Sentry・PostHog は鍵未設定なら無効（no-op）。送るのは操作種別と頻度のみで、**曲名・こども名等の内容は送らない** |
| クラウド保存先の保護（#233 段階1） | Firebase config は公開情報のため、**doc ID が固定・推測可能だと認証なしでは第三者が到達できる**。doc ID を初回生成のランダム値にして推測不能化する。**本命の匿名認証＋セキュリティルールは段階2**（匿名UIDは端末ごとに異なり複数端末共有と両立しないため別途設計。ルールは間借り元 `dtask-d08b6` のコンソール管理） |
| 受容しているリスク（→ #258） | 段階1が塞ぐのは「推測して**到達**される」ことだけで、doc ID を知られたときの**改ざん・破壊は防げない**（認証が無く書き込み権限を絞れない）。家庭内ツール前提で段階2まで受容する。ただしアプリ側は state を信頼せず、①**壊れたデータを渡されても起動不能にならない**（`normalizeState` の型矯正・#272）②**innerHTML へ載せる前に必ずエスケープする**（[js/html.js](../js/html.js) `escapeHtml`・#274）を必須とする |
| 品質保証 | 純粋ロジックは単体テスト（Vitest）、主要フローはE2E（Playwright）。CI通過後に Vercel デプロイ。方針と現状の空白は → [features.md](./features.md)「テストの方針とカバレッジ」 |
| アクセシビリティ（#151） | `prefers-reduced-motion` で演出を停止。ダークモード対応（じどう／あかるい／よる） |

## 5. スコープ外（現状）

- 複数の子供プロフィール対応 / 認証 / ユーザー間共有
- 練習曲の動画検索（YouTube API）、天気連動ボーナス（Open-Meteo API）
- 練習リマインダー通知（PWA Push）
- 猫のスタイル切り替え（リアル系 / ほわほわ系 / ドット絵）

将来の拡張は [GitHub Issues](https://github.com/mamamakura225/claude-practice/issues)（`app/piano-pet` ラベル）で管理。初期ロードマップは [backlog.md](./backlog.md)（凍結）。

## 6. 確定事項

| 項目 | 決定内容 |
|---|---|
| 猫の初期名 | きーちゃん |
| 猫の種別 | 3スタイルから選択（#66）：茶トラ（既定・スコティッシュフォールド折れ耳）／白猫（折れ耳）／ロシアンブルー（立ち耳グレー）。きせかえ編集モード内で切り替え |
| 効果音 | あり（Web Audio API + 録音サンプル・ON/OFF設定付き） |
| イラスト方針 | 猫本体は水彩タッチのプリレンダ透過ラスター（style×tier×mood 45枚・#167/#187/#66）。衣装も画風統一のため水彩ラスター（#191 決定・#196 で SVG→ラスター移行）。**画像形式は WebP・作画枠は box×3**（#229 高解像度化＋#234 WebP化）。演出（ハート/きらきら/Zzz/エンブレム）・グラフは引き続きSVG |
