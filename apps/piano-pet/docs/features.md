## ホーム

> Issue: #121 #167 #187 #396 #399 #432 ｜ 実装: [app.js](../js/app.js)・[cat-image.js](../js/cat-image.js)・[child-profile.js](../js/child-profile.js) ｜ テスト: tests/child-profile.test.js・tests/cat.test.js・e2e/child-avatar.spec.js・e2e/navigation.spec.js

**仕様**

| 要素 | 内容 |
|---|---|
| 猫イラスト | なつき度(tier)×mood の画像（`aria-live="polite"`）。装備・演出は別レイヤー |
| 猫の名前 | 初期値「きーちゃん」 |
| きょうの もくひょう | `○ / N かい`（N＝親が決めた目標・#238）＋進捗バー＋メッセージ |
| スタンプの進捗 | 押せるスタンプがあれば強調（→ [ねこスタンプちょう](#ねこスタンプちょう409)） |
| レベル / XPバー | 「あと○かい で レベルアップ」 |
| なかよしレベル | 「💖 なかよしレベル N（名前）」＋次のレベルへの進捗バー |
| ステータスカード | 🪙コイン / 🔥れんぞく / 🎫おやすみけん / 💖なかよし |
| しゃしん | 猫の下の「📷 しゃしん」（→ [写真モード](#写真モード237)） |
| ヘッダー | 左＝こどものアバター、右＝🔊/🔇 と ⚙️（「おうちのひとへ」・親ゲート） |
| 記録ボタン | 「れんしゅうを きろくする」を下ナビの上に `position: sticky` で固定（#399） |

- 記録ボタンを固定しないのは、高さ 600px 未満と きせかえ中（`.is-dressup`）。きせかえ・しゃしん・まえ／うしろパネルに重なるため
- 下ナビは `z-index: 10`（猫の重ね順 2〜6 より上、ポップアップ 50〜 より下）。横向きで猫がタブを覆って押せなかった（#432）
- 猫の上下の余白を詰め、375×740 で「きょうの もくひょう」が固定ボタンに隠れないようにする（きせかえ中は詰めない・#432）
- 幅 420px 以下では名前とタイトルを省略記号で縮め、右端の 🔊/⚙️ を押し出さない（#396）

**設計判断**

- **記録ボタンの固定（#399）**：約2画面スクロールしないと見えず、子どもが記録の入口に気づかなかった。`:has` は古い Safari/Firefox で効かないのでクラスで切り替える
- **記録画面の送信ボタンは固定しない（#399）**：スタンプカードの下段を覆い、マスのつもりのタップで途中の回数のまま記録された。代わりに目標回数に届いたら送信ボタンを画面中央へスクロールする

### こどものアバター（#121）

- home / きろく の両ヘッダの `.child-avatar`。タップで `#avatarOverlay`。本人の操作なので**親ゲートなし**
- 絵文字10種（`CHILD_AVATARS`）。各選択肢に読み上げ名（#397）
- なまえは最大12文字。入力中もヘッダへ反映し、閉じるときに前後空白を落として確定する
- 保存先は [data-model.md](./data-model.md#pet) の `pet.childName` / `pet.childAvatar`。analytics には送らない
- **設計判断**：顔写真は使わない（認証なしの共有 Firestore に置けない）

### 猫の mood

恒常表示は idle/sleep。happy/love/hiss は演出中だけの差し替え。

| mood | 条件 | 表現 |
|---|---|---|
| `idle` | 通常 | ゆっくり呼吸（scaleY） |
| `happy` | 記録直後 | うれしい表情＋ぴょんと跳ねる・ハート |
| `sleep` | 最後の練習から2日以上（`cat-image.js` `moodForState`） | 目を閉じた表情＋Zzz |
| `love` | なでた時 | ハート目＋しっぽふり／喜ぶ |
| `hiss` | なで反応で威嚇を引いた（#187） | 威嚇の表情だけ。喜びの演出は出さない |

## 練習記録

> Issue: #117 #123 #164 #186 #252 #260 #273 #398 #399 ｜ 実装: [record-form.js](../js/record-form.js)（純粋ロジック）・[record-screen.js](../js/record-screen.js)（画面・下書き・送信） ｜ テスト: tests/record-form.test.js・tests/game.test.js・e2e/record.spec.js・e2e/record-date.spec.js・e2e/day-rollover.spec.js

### モードの切り替え

- 「🐾 スタンプ / 📝 まとめて」の切替。既定はスタンプ。日付は両モード共通で既定は今日
- 切り替えると入力途中の内容を「曲×回数」に変換して引き継ぐ
- `aria-pressed` のトグルボタン2つ。`role=tab` は矢印キーの操作を約束することになるので使わない（#397）

### スタンプモード（曲は親・スタンプは子・#117）

| 操作 | 仕様 |
|---|---|
| きょくを えらぶ | 曲名チップを「最近ひいた順（最終練習日）→累計回数」で最大8件（`pastSongNames`・#252）。漏れた曲は新規入力欄の `datalist` から選ぶ。チップに曲の色 |
| いまの曲の表示 | スタンプカードの上に「🎵 いまは「曲名」」（#399。前回の曲のまま押してしまうため） |
| ハンコを おす！ | 選択中の曲の🐾が1つ増え、マスをその曲の色で塗る。マス数は目標ぶん（既定10・5〜20・#238）、埋まったら常に1マス余分 |
| ↩ ひとつ もどす | 直前の1つを取り消す |
| 曲が1つも無いとき | 押すと「おうちの ひとと、うえの らんに きょくの なまえを いれてね」（#399） |
| 当日中の引き継ぎ（#164 #186） | 記録前は下書き、記録後は当日の記録から復元して続きを押せる（→ [data-model.md](./data-model.md#スタンプ下書きstamp-draft)） |

- **設計判断（#252）**：チップを累計順にすると、いま練習中の曲が載らない

### まとめモード（親の後追い入力・#123）

- 1行＝曲名（`datalist` 補完）＋回数ステッパー。「＋ ぎょうを ふやす」と各行の「✕」
- 「ごうけい ○ かい」をその場で表示。集約は `collectSongs`（空名・0以下は除く）
- 1行は99かいまで（`MAX_ROW_COUNT`・入力欄と集約の両方・#428。桁を打ち間違えた記録は、開くたびにその数のスタンプを並べて固まる）。99を超える曲（押し増し・過去日のたしざん）は行を分けて出し、減らさない（`songsToRows`）

### 記録の確定（両モード共通）

- 合計0回は記録できない（`isValidSession`）
- コイン・XP・連続日数・バッジを反映 → ホームへ移動 → 猫の演出 → ポップアップ（→ [記録後のごほうび演出](#記録後のごほうび演出)）
- 何も増えていない（同じ内容の再送信・回数を減らした修正）ときは祝わず「✏️ きろくを なおしたよ」（#396）

### 日付と、同日・過去日の扱い

| ケース | 扱い |
|---|---|
| 今日 | 記録画面は「その日ぜんぶ」を表す。submit は追記ではなく**置き換え**（#186）。判定は「当日ぶんを復元した日」（`restoredDate`）で、開いたまま日付をまたいでも復元した日の記録を置き換える（#428） |
| 同日に既存の記録がある | 統合して全再計算（`recomputeState`）。目標達成ボーナスの二重取りを防ぐ |
| 過去日（最終練習日より前） | 挿入＋`recomputeState` で連続日数を保つ（#260）。「きょうのおまけ」は抽選しない |
| 記録済みの過去日を選んだ | 「この ひは もう Nかい きろく してあるよ。いれた ぶんは たしざん されるよ。」を出し、合算する（#398） |
| 未来日 | 選べない（`max=今日`）。手入力で入っても submit で今日へ丸める |
| 日付をまたいで戻った（#428） | 復帰時に描き直す（`refreshOnNewDay`。ホーム・カレンダーの月）。レッスン日の取りこみは保存・送信を伴うので、クラウドを取り込んだ後（`resyncAndSettle`）に回し、取れなければ次の再同期まで待つ（先に送ると #242 と同じく他端末の記録を消す）。記録画面は書きかけ（編集中・まとめ・未送信のスタンプ）があれば触らない |
| ひづけ欄を変えた（#273） | 今日＝当日の記録／下書きから復元、今日以外＝空のカード（`onRecordDateChange`）。過去日の間は当日の下書きを書き換えない |

- 同日同曲は合算する（`combineSongs`・#186）。既存の分割データも表示時にまとめる

**設計判断**

- **当日は置き換え（#186）**：全内容を復元しているので、追記では押し増しが二重に数えられる
- **過去日は全再計算（#260）**：`applySession` は日付順に届く前提の逐次更新で、過去日を流すと連続が1に戻る。旧バグで戻った既存データは、次の記録・編集・削除か初回 reconcile で自己修復される
- **日付の変化を起点に作り直す（#273）**：復元した当日ぶんを持ったまま過去日にすると二重に数えられる（実測：今日5かい → おとといへ → 5+5 の2件）

### 曲の色（#122 #165）

> 実装: [song-color.js](../js/song-color.js) ｜ テスト: tests/song-color.test.js

**仕様**

- 曲名（前後空白は無視）の FNV-1a ハッシュで色相を出す。彩度・明度は固定（`songColor` が `fill`/`tint`/`ink` を返す）。空名はグレー
- **保存しない**。`sessions` が同じならどの端末でも同じ色
- **色かぶりの回避（#165）**：`assignSongColors(names)` が、既出の色相に **25°未満**の曲を隣へずらす。並びは `songTotals` の順
- `songTotals` の同数の並び（#326）：最終練習日が新しい順 → 曲名のコードポイント昇順

**設計判断**

- **同数の並びを `sessions` 内の値で決める（#326）**：配列位置で決めると、並びが経路で変わり同期のたびに色が入れ替わる
- **端末間で一致しない例外**：記録画面の `buildSongColors(chipNames)` は未保存の曲名を末尾に足すので、記録するまではずれうる（許容）

### スタンプ音（#139 #154 #238）

- 押すたびに**ドレミ…と上がり**（1マス目＝ド）、目標マスは **Cメジャー主和音**で解決してレベルアップ音を鳴らす。目標を超えても主和音のまま（`stampSemitone`）
- 途中のマスは目標数に合わせて1オクターブ内へ割り振る

**設計判断（#238・目標回数の可変化 `pet.dailyGoal`）**

- **保存先は同期される `pet`**：進捗・達成演出・マス数・音程は全端末でそろえる
- **達成ボーナスは10回で固定**（`GOAL_BONUS_THRESHOLD`）：`recomputeState` は全履歴に `calcRewards` をかけ直すので、可変の目標に連動させると**過去の記録のコインまで増減する**
- **音程の正規化**：オクターブを無制限に積むと goal=20 で +31 半音になる。分母 `(goal-1)` で 0..6 の音度に収める

### 記録の動画クリップ演出（#227）

> Issue: #227 #296 #300 #303 #305 #400 ｜ 実装: [cat-video.js](../js/cat-video.js)・[popups.js](../js/popups.js) `celebrateRecord`・`primeCatVideo` ｜ テスト: tests/cat-video.test.js・e2e/clip.spec.js・e2e/reward-popup.spec.js・e2e/sw-clip-cache.spec.js

**素材**

| 項目 | 内容 |
|---|---|
| 形式 | 720×720・1:1・muted・約4秒。**2回ループで約8秒**見せる（#296） |
| 本数 | 猫スタイル3色 × 3本 = 9本（#300）。`video/cat_<style>_record_v<n>.mp4` |
| 動き（3色共通） | v1＝跳ねてバンザイ＋ハート／v2＝くるっと回る／v3＝大きくのびをする |
| 始まりと終わり | 同じ座りポーズ（畳んだ瞬間に静止画へ自然に戻る） |

**出る確率**（`recordClipChance`・[feed.js](../js/feed.js)・#296）

| なかよしLv | 1–3 | 4–5 | 6–7 | 8 |
|---|---:|---:|---:|---:|
| 確率 | 25% | 40% | 55% | 70% |

**再生の仕様**

| 項目 | 仕様 |
|---|---|
| 選び方（#300） | `pickClip` は bag shuffle。3本を配り切ったら詰め直し、先頭が直前と同じなら末尾と入れ替える |
| 2回ループ（#296） | 通常は `ended` で巻き戻す。`ended` が来ない端末は `duration + 0.4s` のタイマー、最終保険は `duration * 2 + 1s` |
| 終了 | タップでスキップ。再記録したら前を畳んで次へ（`teardown`）。ホームを離れたら畳む（#400） |
| フォールバック | 未ロード／自動再生拒否／1000ms 以内に `playing` が来ない／`prefers-reduced-motion` なら CSS 演出 |
| ホームを離れた | 畳む（#400）。読み込み中に離れたときも、始まった時点で畳む（#428） |
| 先読み | 記録ビューかショップに入ったとき idle で `cat-video.js` を動的 import し、**次に出る1本だけ**を読む（`peekClip`） |
| キャッシュ | SW が cache-first で返す（→ [Service Worker](#service-worker-のキャッシュ戦略)） |
| 音 | 常に muted（効果音は `sound.js` に任せる） |
| DOM | `#catVideo` は `#catStage` の**外**。`renderHome` が `#catStage` を `innerHTML` ごと差し替えるので、中だと他端末の保存で動画が消える |
| 見た目 | `.cat` とサイズ指定を共有し猫に重ねる。夜モードは不透明な動画（背景 `#FCF2EC`）を角丸＋影の「絵本のページ」として見せる |

**設計判断**

- **頻度と尺を上げた（#296）**：利用者の「もっと見たい」「短くて見逃す」を受け、確率 12/20/30/40% → 25/40/55/70%、視聴1周 → 2周
  - `video.loop` は使わない。`ended` が来ず、終了検知と世代管理（`_clipGen`）が崩れる
  - Lv1 から出す（始めたばかりの子が一度も見られないのを避ける）
- **1スタイル3本（#300）**：確率を上げた結果、同じ映像ばかりになった。追加2本は**シルエットの動く軸**で選んだ（小物を浮かべる案は小画面で見分けがつかず不採用）
  - 目標達成と通常記録は同じプール（分けると専用素材がさらに3本要る）
  - 先読みは1本だけ（3本で約 390 KB）。そのため `pickClip` は**バッグを消費し、再生に失敗しても巻き戻さない**（先読みした1本とずれるため）
- **節目は状態でなくイベントで見る（#305）**：連続日数の値だけで判定すると、節目の日は全記録が節目扱いになりクリップが出なかった。`commitState` 前の `prevStreak` と比べて「この記録で伸びたか」（`streakAdvanced`）を渡す
- **透過動画は使わない**：Chrome（VP9 alpha）と iOS Safari（HEVC alpha）で形式が割れる
- **リポジトリ同梱＋静的配信**：Firebase Storage 配信は不採用（Blaze 課金とルールの版管理 #266 が増える。`video/` はプリキャッシュにも予算にも載らないので SW は太らない）。18本・約 3.8 MiB で `img/` と同程度。次に足すときに再検討する
- **ファイル名の `_v1`〜`_v3` は動作の種類**で、キャッシュ更新の版ではない（#318）

### ポップアップ演出

> Issue: #261 #294 #309 #320 #323 #396 #400 ｜ 実装: [popups.js](../js/popups.js) `showPopup` ｜ テスト: e2e/reward-popup.spec.js・e2e/shop.spec.js

**種類**：獲得コイン（レベルアップもここに出す） ／ えさやり ／ きょうのおまけ ／ お休み券キープ ／ バッジ獲得

**仕様**

| 項目 | 内容 |
|---|---|
| 記録後の順番 | コイン → おまけ → お休み券 → 新しいバッジ。2.2秒おき。全再計算で確定する記録（同日の更新・過去日・レッスン日がらみ）はコインとバッジだけ |
| クリップとの順番（#400） | クリップが終わる（スキップ含む）まで出さない。`celebrateRecord` が返す Promise を `tryPlay(style, onDone)` が解決する |
| バッジが複数（#400） | 2つまでは順に、3つ以上は2つ目以降を1枚にまとめる。表示中に次の獲得が来たら後ろに並べる（`badgeQueue`・#428。置き換えると読む前に消え、続きも失われる） |
| 記録以外のバッジ | 購入の300ms後、えさやりポップアップが閉じた後 |
| タップで送る（#400） | 表示中（`.coin-popup--show`）だけ `pointer-events: auto`。タップで閉じて次へ。下のボタンには届かない |
| 前のポップアップ | 残っていれば即座に畳む（`dismissOtherPopups`・#396）。クリップ再生中のえさやりカードは畳まない |
| 確定 | `duration` 経過後、`transitionend` と 400ms の保険タイマーの早い方で `hidden` にする。`showPopup` は早く閉じる関数を返す |
| 記録クリップ中の重ね順 | `body.cat-clip-playing` の間は `#feedPopup` 以外の暗幕を透明にする |
| 再記録したとき | 前の記録の「見終わった」通知も呼ぶ（`startClip` が前の `_clipDone` を呼ぶ）。前の記録のポップアップは次のクリップの裏に回る |

**設計判断**

- **クリップの後に出す（#400）**：並べて出すと、動画が覆う約8秒の間に 2.2秒のポップアップが流れ去る。ホームを離れたら畳むのは、移った先の画面にまとめて出ていたため
- **`showPopup` に一本化（#261）**：once リスナーを素朴に張ると、連続表示で前回のリスナーが新しいポップアップを途中で消す。要素ごとにタイマー・リスナーを張り替え、連続表示は `onHidden` の連鎖にした
- **畳んだ側の後続を回す（#396）**：重ねると読めず、畳むだけだと `onHidden`（バッジの連鎖・えさやり後の告知）が失われる。畳んだ側の `onHidden` は新しいポップアップの cycle（`deferred`）へ移し、閉じた後に実行する。全体のキュー直列化は作り直しが大きく不採用
- **`[hidden]` を CSS で明示する**：`.coin-popup` の `display:flex` が UA 既定の `[hidden]{display:none}` を上書きし、`role="status"` の5要素が常にアクセシブルツリーに出ていた（`getByRole('status')` 実測：5件 → 表示中の1件）
- **保険タイマー**：`prefers-reduced-motion`（`transition: none`）では `transitionend` が来ず、`hidden` が立たずバッジの連鎖も止まる。再現は `page.emulateMedia({ reducedMotion: 'reduce' })`（`test.use({ reducedMotion })` は `matchMedia` に反映されない）
- **未検証**：各 `show*Popup` はテキストを入れてから `hidden=false` にする。スクリーンリーダーが live region として読み上げるかは実機で確かめていない

**設計判断**

- **カレンダーは保存しない（#236）**：`sessions` から導出。セルが多いので SVG でなく CSS grid
- **カレンダーの色（#407）**：白抜きは淡いピンクと見分けるため。先の日を `opacity` で薄くすると 1.75:1 で読めなかった
- **praise と tempo は同じ作り（#239）**：`setSessionMark`/`markRowMarkup` を共用（#261）。報酬に関係しないので再計算しない。統合・マージでの扱いは [data-model.md](./data-model.md#session)（#315）
- **一覧は14件ずつ（#360）**：全件だと1件約 290px・14日で 4,500px（実測）
- **操作の対象は日付で持つ（#314 #428）**：一覧のボタンも編集中の記録もカードの `data-date` で引く。index だと、開いている間の同期や猶予中の削除の確定で並びが変わり**別の日の記録を開く・上書きする**。index を補正する案は並び替え経路が増えるたびに漏れるので不採用
- **削除の確定を遅らせる（#398）**：すぐ確定すると、墓標が取り消しの猶予（5秒）より先に他端末へ届き（送信待ち2秒）、戻した記録が union で消し直される
  - 画面移動で確定するのは、記録画面に消した当日分が復元されるため。せっていを開いたら確定するのは、アカウント切替等の reload で別アカウントの保存先へ確定してしまうため

**設計判断**

- **買う前に確認する（#421・ユーザー決定）**：#398 の「買った直後に5秒間取り消せる」方式では、子どもがトーストを読まず戻せなかった。のこりコインを見せて判断材料にする。値段で確認の有無を分ける案は「ときどき聞かれる」方が分かりにくいので不採用。えさは安く何度も使うので確認しない
- **ロック品を後ろへ（#399）**：序盤は45品中7品しか買えず埋もれていた。ごほうび一覧を畳むのは、きせかえ アイテムを約1.5画面押し出していたため
- **「あと ○ コイン」（#360）**：1かい＝1コインなので、不足額が「あと何回れんしゅうすれば買えるか」の目安になる
- **価格は一律半額（#250）**：1日15コイン前後の獲得に対し、旧価格では最初のリボンに3日超・王冠に20日かかった。`spentCoins` は現行価格から導出するので、既存ユーザーには差額が自動で返る（えさ `foodSpent` は返さない）
- ⚠️ **価格は下げる方向にしか変えない**：`SHOP_ITEMS` / `FOODS` の値上げは**既存ユーザーのコインを黙って減らす**。必要なら支払額のフィールドと[移行](./data-model.md#5-マイグレーション)をセットで行う
- **受容した過渡期のリスク（#250・topic_1784289217445）**：新旧価格の JS の端末が混ざる間はコインが行き来する。sessions・inventory は無傷で、両端末が新しい JS になれば収束する。購入価格を state に固定する案（`spentCoinsTotal`）は、旧 JS の push での欠落が自己修復しないので不採用
- **アイテムを廃止するとき（#326・方針だけ）**：定義から消すと `spent` が下がりコインが増える。消さずに `retired: true` を立てて `price` を残す（未実装）

### 画像の作画枠（`cat-image.js` `ITEM_BOX`・#196）

| 項目 | 規則 |
|---|---|
| 形式 | 透過 WebP（quality75・alpha 90・#234 #431）。背景に薄い膜（alpha 24 以下や孤立した薄い線）を残さない。アセットは `img/cat/items/{id}.webp`・`img/cat/scene/{id}.webp` |
| 大きさ | box（`ITEM_BOX` / `SCENE_BOX` の描画座標）の**3倍**（#229）。縦横比を box に合わせる（`xMidYMid meet`） |
| 原点(0,0) | 装着アンカー。head＝下端中央、neck・back＝上端中央、face＝中央（例外は各 box の値が正）。置物は中央 |
| 納品 | 全枚数が揃ってから `gen-sw` を再生成してマージする（未納品だと代替表示になる） |

- **box は生成画像の縦横比に合わせて決める**（先に箱を決めると画像が箱の中で小さくなる）
- 透過は**外周から繋がる白だけ**を抜く。内側の穴を透かすもの（`bandana`/`lantern`/眼鏡類）だけ内側の白も抜く（全点にかけると淡色の面に穴が開く）
- アイテム画像に猫の顔やチャームを描き込まない。環状のもの（`collar`/`bell`/`flowerCrown`/`pearls`）は**前から見える弧だけ**描く（#241。全アイテム前面なので背面の帯が手前に出る）
- 平置きの商品写真調にせず、アンカー原点基準の構図で描く（#213）。眼鏡のつるは描かない（耳掛けが欠けに見える）
- 生成は Google Flow（Nano Banana 2.1・1:1）で水彩の単体画像 → 白背景を透過

**設計判断**

- **box×3＋WebP（#229 #234）**：ピンチ最大3.0倍で 2x では粗が出る。PNG の box×3 は約5.2 MiB、WebP 化で 4.82 → 3.60 MiB（全61枚）。iOS Safari 14+ が対応するので `<picture>` のフォールバックは置かない
- **再圧縮（#431）**：猫・アイテム・置物の WebP を quality85→75、鳴き声をモノラル VBR、`record_v1` 3本を crf 29 で作り直した（img 4.2→2.6 MiB・sounds 110→52 KiB・video 3.76→3.57 MiB）。2倍拡大で見分けがつかないことを目視。猫の解像度は 1024 のまま（896/768 への縮小は同じ容量で画質が劣る）。他のクリップは縮んでも 3〜6% で世代劣化に見合わず据え置き。スタンプは元から小さいので対象外
- **アイテム29点の追加（#299）**：新規追加は既存ユーザーのコインに影響しない（#250 の⚠️の対象外）。`bandana` は `cap` と絵文字が重ならないよう 🔺

### 自由配置（ドラッグ #168・ピンチ #205）

> 実装: [dressup.js](../js/dressup.js)（pointer 追跡）・[cat-image.js](../js/cat-image.js) `itemGroup`/`itemAnchorPct`/`itemAnchorScale` ｜ テスト: tests/cat.test.js・tests/dressup.test.js・e2e/dressup.spec.js

ホームの「👗 きせかえ」で編集モードに入り、**1本指ドラッグで移動・2本指ピンチで拡縮**する。「✅ できた！」で抜ける。

| 項目 | 仕様 |
|---|---|
| 配置データ | `pet.itemLayout`（.cat 枠の%）。座標が無ければ既定アンカー・基準スケールで描き、初めて触ったときに記録する |
| 位置 | 落とした座標をそのまま記録。範囲外はステージ内へ clamp。スナップは**廃止**（#214） |
| ピンチ（#205） | `scale` は**絶対値**で `0.3〜3.0`。基準の ±5% 以内なら基準へ吸着。2本指の距離が **10px** 動くまで拡縮しない。ピンチ中は位置を固定 |
| 押せる大きさ（#215） | 透明なヒット矩形（`.cat__item-hit`）を**逆スケール**で入れ（`MIN_HIT_UNITS`=44）、拡縮後も約66px 以上を保つ |
| なでとの競合 | 編集中は `petCat` を止め、猫の周りを点線で囲う |
| 指が取り上げられた（#428） | `pointercancel` も指を離したのと同じに扱う（放置すると消えた指が残り、次のドラッグがピンチになる） |
| スクロール中のドラッグ（#288） | `pointermove` ごとに `getBoundingClientRect()` を取り直す（キャッシュすると落とす位置がずれる） |
| 掃除 | `commitState` の `cleanItemLayout` が、付けていないものの座標を消す |
| 編集モードの開始 | `cat-stage--editing` は `dressup.js` を読み込んでから付ける（#284。クラスが「使える」合図になる） |

**設計判断**

- **座標は `itemLayout` に分ける（#168）**：`equippedItems` に埋め込まず、装備ロジックとテストを残す
- **scale は絶対値（#205・topic_1782030433684）**：乗数だと、アセットを直して基準を変えたとき配置済みのサイズまで変わる
- **位置スナップの廃止（#214・topic_1782394334271）**：「勝手に戻る」が操作ミスに感じられた。サイズの吸着は残す
- **ヒット領域はマークアップ（#215）**：JS の最近傍探索より、標準のポインタイベントと描画順にそのまま乗る
- **cape を前面へ（#211）**：背面だと不透明な本体に隠れて見えず掴めない。アンカー種別（`back`）は変えない

### まえ／うしろの切り替え（#270）

> 実装: [app.js](../js/app.js) `renderLayerPanel`・[cat-image.js](../js/cat-image.js) `itemLayer` ｜ テスト: tests/cat.test.js・e2e/dressup.spec.js

編集モード中だけ出るパネル（`#layerPanel`）に、付けている装着＋置物が2段に並ぶ。チップをタップすると反対の段へ移り、効果音を鳴らす。何も無いときは案内と「🛍️ ショップへ」（編集モードを終えてから移る・#399）。

**設計判断**

- **ジェスチャでなく一覧パネル**：ダブルタップ／長押しはドラッグ・ピンチとぶつかり「裏に回って戻せない」に直結する。パネルは全アイテムを並べるので**必ず戻せる**。タップ選択＋反転ボタンは dressup.js の改修が見合わず不採用

## ねこスタンプちょう（#409）

> Issue: #409 #410 #413 #415 #417 #419 #423 ｜ 実装: [stamp-book.js](../js/stamp-book.js)（ロジック）・[stamp-view.js](../js/stamp-view.js)（画面）・[stamp-settings.js](../js/stamp-settings.js)（せってい）。3つとも遅延読込 ｜ テスト: tests/stamp-book.test.js・e2e/stamp-book.spec.js

1日10回以上ひいた日に猫スタンプが1こもらえ、親が決めた個数がたまったら**現実のごほうび**をもらう。保存先は [data-model.md](./data-model.md#stampbook409) の `pet.stampBook`。

**仕様**

| 項目 | 仕様 |
|---|---|
| もらえる日 | その日の合計が **10回以上**（固定 `STAMP_THRESHOLD`）。**1日1こ** |
| 数える範囲 | カードの開始日〜今日。古い順に、カードの個数で打ち止め。後から入れた過去日も開始日以降なら入る |
| レッスン日 | **数えない**（`sessions` に記録がない日は対象外） |
| 記録の修正・削除 | 10回を下回ればそのスタンプも消える（`pressed` は残る） |
| 押す | 「🐾 おしてね」を**子がタップ**。**画面いっぱいの大きさで**肉球が降りて「ぺたっ」（約0.4秒・効果音 `peta`）→ 縮みながらマスへ収まる（計 約1.6秒）。押し忘れた日は後からでも押せる |
| ごほうび | 個数ぶん押し終えると**全画面のお祝い**（#419）：跳ねる「ごほうび ゲット！」・ごほうびの なかみ・「おうちの ひとに みせてね」・5色の紙吹雪・ファンファーレ `fanfare`。「やったね！」かどこかのタップ・Esc・戻るで閉じる。カードには「🎉 ごほうび ゲット！ おうちの ひとに みせてね」が残る |
| 絵柄 | 猫の姿10種（`STAMP_DESIGNS`）。日付だけから決まる（`designForDate`）。[一覧](#ねこスタンプの絵柄410413) |
| ホーム | 進捗行（`#stampHomeLink`）。押せるスタンプがあれば「🐾 スタンプを おしてね！（n/N）」で強調。カードが無ければ出さない |
| おわった カード | スタンプタブの下に一覧（ごほうび・こすう・もらった日） |

**せってい（親ゲートの内側）**

- ごほうびの なかみ（20文字）・えもじ（8種・`REWARD_EMOJIS`）・なんこで ごほうび（**5〜60**）を決めて「カードを つくる」。進行中は「なおす」（開始日は変わらない）
- うまったら「ごほうびを あげた」で おわった カードへ移し、次を作れる。同時に進めるカードは1枚

**設計判断**

- **しきい値は10回固定**（ユーザー合意）：もらえる日は導出なので、`pet.dailyGoal` に連動させると過去のスタンプが付いたり消えたりする（#238）
- **もらえる日は導出、押した日だけ保存**：修正・削除・マージの整合処理が要らない
- **カードは開始日から数える**：作る前の記録で一気に埋まらない。次のカードの開始日は**前のカードの最後のスタンプの翌日**（親が作り忘れても子のがんばりが消えない）
- **おわったカードは日付ごと固定**：あとで記録を直しても崩れない
- **絵柄は日付から決める**：単純なハッシュだと同じ絵が続くので、10日ごとのブロックの中で全種を種付きシャッフルして配る。種類数が変わると過去の絵柄も振り直される（互換は作らない）
- **押したら先に保存し、演出は後**：途中でタブを移っても消えない。演出中はクラウドからの再描画を止める
- **「おしてね」は影の明滅**：拡大縮小だとボタンが動き続け、子どもにも Playwright にも押しにくい
- **押す演出（#415 #417）**：マスの中（約60px）だけでは手応えが弱かった。等倍の0.6倍速（`playbackRate`）。`peta` は頭に0.25秒の間があるので、タップ時に `unlockAudio()` し 160ms 後に鳴らして着地に合わせる
- **CSS を足さない**：当時の css 予算の余白が 0.1 KiB だったので、既存のキーフレームの使い回しとインラインスタイル＋Web Animations API で書く（押す演出・お祝いとも）
- **お祝いは閉じるまで出す（#419）**：子が「おうちの ひと」を呼びに行って見せられる。音は `levelup` を使い回さず達成専用
- **ごほうびの絵文字はお祝いに出さない（#423・ユーザー判断）**：なかみとの結びつきが弱く、大きく出しても意味が伝わらない
- **`prefers-reduced-motion` で止めるのは明滅だけ**：ぺたっとお祝いは遊びの手応えなので残す
- **古い せってい画面からは確定しない**：ボタンにカードの `id` を持たせ、押した時点のカードと違えば描き直すだけにする（他端末の新しいカードを終わらせてしまうため）。`redeemCard` も、うまっていないカードは終わらせない
- **実在しない日付は数えない**：入口（`normalizeState`）で落とすほか、絵柄の計算が NaN になるので判定でも捨て、押す処理は `finally` で必ず解除する
- **個数を減らしたとき**：枠から外れた押印は残り、次のカードで数える
- **同期**：realtime は `pet` ごと cloud-wins。初回マージは [data-model.md](./data-model.md#63-初回取り込みのマージmergecloudinitialローカル優先)

### ねこスタンプの絵柄（#410・#413）

- `img/stamp/{id}.webp`（192×192・透過・色を焼き込み済み）。描画は `stampFace` の `<img>` 1つ
- 肉球 `paw.webp`（`#e0577a`）は「ぺたっ」で降りてくる `.sb-paw`

| 色（`STAMP_INKS`） | 値 | 姿（id） |
|---|---|---|
| あか | `#e0574f` | ねこパンチ（`punch`）・ジャンプ（`jump`） |
| あお | `#3d86d4` | なべねこ（`nabe`）・おさかな（`sakana`） |
| みどり | `#3a9e68` | のび〜（`nobi`）・ふみふみ（`fumifumi`） |
| むらさき | `#9563cc` | おじぎ（`ojigi`）・しっぽハート（`heart`） |
| ちゃいろ | `#b5793f` | けいとだま（`keito`）・はこ（`hako`） |

**設計判断**

- **黒インクで描き、輝度からアルファを抜いて色を焼き込む（#410）**：色インクで直接描くと色相がぶれ、白フチが残る
- **CSS の `mask-image` で塗る案は不採用**：css の余白が無い。5色はライト・ダーク両方の `--surface` に 3:1 以上（最小 3.35＝みどり/ライト）なので、テーマで色を変える必要も無い
- **`STAMP_INKS`／`ink` は描画に使わない**が、「姿ごとに1色・5色×2種」をユニットテストで固定し、作り直すときの色の正として残す
- **192px**：マスは 375px 幅で約60 CSS px。10種＋肉球で 215 KiB
- **作り方**：Google Flow（Nano Banana 2.1・1:1。「濃いベタ塗り」は版画調になるので「水っぽいインク・灰色のにじみ」）→ 紙の明るさ（輝度90パーセンタイル）とインク（1パーセンタイル）で正規化してアルファ化（0.10 未満は捨てる・γ0.6）→ 外接矩形＋余白10%（肉球22%）の正方形 → 192px・WebP q80（alpha_quality 90）→ ライト/ダーク・60px 縮小で目視

## 育成・報酬ロジック

> Issue: #148 #167 #238 #393 ｜ 実装: [game.js](../js/game.js)（純粋関数） ｜ テスト: tests/game.test.js・e2e/record.spec.js・e2e/reward-popup.spec.js・e2e/lesson.spec.js

### コインと XP

| 条件 | コイン | XP |
|---|---:|---:|
| 1回練習（1曲1回） | +1 | +1 |
| 目標達成（その記録の合計10回以上・固定 #238） | +5 | +3 |
| 連続がちょうど3日に届いた | +10 | — |
| 連続がちょうど7日に届いた | +30 | — |
| レッスン日（#393・1日につき） | +10 | +5 |
| きょうのおまけ（当たったとき） | +3 | — |

- 必要累計 XP：Lv2=20 / Lv3=50 / Lv4=90 / Lv5=140 / Lv6 以降は前のレベル +60 ずつ

### きょうのおまけ（#148）

- その日の**最初の記録**で `BONUS_CHANCE`（20%）の確率で `BONUS_COINS`（3コイン）。当たったら専用のポップアップ（🎁）
- 抽選は record-screen.js（`rollDailyBonus`）。額は記録の `bonusCoins` に保存する（→ [data-model.md](./data-model.md#session)）
- **設計判断**：練習しなくても得するログインボーナスは習慣化と矛盾するので不採用

### ストリーク（連続練習）とお休み券

- 前日に練習していれば連続。同じ日の二重記録では増えない
- **お休み券（`streak.freezes`）**：ちょうど3日、および7日ごとに +1枚（**上限2枚**＝`MAX_FREEZES`）
- 間が空いたとき、抜けた日数ぶんの券があれば使って連続を保ち、ポップアップで知らせる。足りなければ1に戻るが**券は没収しない**
- **設計判断**：コインの節目は3日・7日に届いたときだけ（インフレを抑え前倒し）、お休み券は7日ごとに出し続ける（長く続ける動機）

### レッスン日（#393）

親が登録した日（`pet.lessonDates`）は、記録の有無によらず**練習した日として連続に数える**。

| 項目 | 仕様 |
|---|---|
| 登録 | せってい →「ピアノの レッスンび」で「いれる」、「×」で取り消し（5秒間「もとに もどす」・#398）。過去日・先の日付（「よてい」）も入れられる |
| 一覧の表示 | 先の予定はすべて、過去日は新しい順に3件。「もっと みる」で12件まで（#401） |
| 反映 | 今日以前の登録日だけ。起動時に登録日があれば毎回再計算し、数値が動いたときだけ確定してコインポップアップ。登録・解除も全再計算 |
| 報酬 | 1日につき `LESSON_COINS`(=10)・`LESSON_XP`(=5)。自宅練習の報酬とは別に上乗せ（連続は二重に数えない）。連続の節目コインは練習を記録した日だけ、おやすみけんの付与はレッスン日でも付く |
| 表示 | ホームに「🎹 きょうは レッスンび！」、カレンダーに🎹 |

**設計判断**

- **`sessions` には入れない**：偽の記録にすると曲別集計・バッジ・同日1件の統合・墓標と干渉する。日付だけ持ち、`recomputeState` が記録と日付順に並べて再生する。報酬は `coinsEarned` に含めない
- **未反映のレッスン日があるときは全再計算**：`submitRecord` は `hasUncreditedLesson`、または `date === lastPracticeDate`（レッスンだけ反映済みの当日。逐次更新だとおやすみけんが二重に付く）なら全再計算で確定する（`finishRecord`）
- **曜日の固定登録にしない**：補講・休講で崩れ、いつから有効かの版管理も要る
- **おやすみけんの自動付与は不採用**：上限2枚では毎週のレッスンを賄えない
- **解除は墓標（`pet.lessonRemoved`）で伝える**：登録は union なので、墓標が無いと他端末の古い登録が戻る
- **プライバシー**：曜日パターンの推定に使えるので analytics には送らない
- **既知の限界**：日付をまたいで表示したままだと、連続・コインは次の記録・再読込・復帰（いったん裏へ回して戻る）まで反映されない。全再計算の記録では「つかったよ」（お休み券）と おまけ のポップアップが出ない（コインには含まれる）

### 猫の見た目（なつき度 tier・#167）

猫本体は **スタイル3種 × tier 3段階 × mood 5種 = 45枚**の透過画像（`img/cat/cat_{style}_{tier}_{mood}.webp`）。

| tier | なかよしレベル | 見た目 |
|---|---|---|
| low | Lv1〜2 | 控えめな表情 |
| mid | Lv3〜7 | リラックス |
| high | Lv8 | デレデレ |

- 読み込みは今の tier の5 mood を先に、次の tier の境界の3pt手前（えさの最大増分ぶん・#326）で `requestIdleCallback` 先読み
- **設計判断（#167）**：見た目の軸は level でなく**なつき度**に一本化。閾値は新しく作らず既存のレベルを3 tier にまとめる

## アクセシビリティ・表示テーマ（#151）

> Issue: #151 #359 #397 #400 ｜ 実装: [css/style.css](../css/style.css)・[css/cat.css](../css/cat.css)・[dialog.js](../js/dialog.js) ｜ テスト: e2e/a11y-dialogs.spec.js・e2e/reward-popup.spec.js

### 動きを減らす（prefers-reduced-motion）

- 止める：猫の呼吸/ジャンプ/ハート等、スタンプの登場・オンボーディングのポップ・各種バーの伸び。動画クリップは出さない

- ハンコの登場は、いま押したマス（`.is-new`）だけに付ける（#400）

### ダークモード

| 項目 | 仕様 |
|---|---|
| 色の構造 | 構造色は `:root` のセマンティック変数（`--surface`/`--cream`/`--ink`/`--shadow` ほか）。ダークではこの変数だけを上書き。アクセント色は共通。`color-scheme: dark` で日付アイコンなどもダークにする（#432） |

## app.js の分け方（#439〜）

`app.js`（もとは約2,370行）を画面・役割ごとのモジュールへ分けている。挙動は変えない。

| モジュール | 持つもの |
|---|---|
| `state.js` | アプリ全体の `state`（live binding）・`setState`・`recomputed`、登録式の `commitState`（実体は app.js が `onCommit` で登録・#442） |
| `cloud-sync.js` | クラウドとの接続・初回取り込み・realtime・復帰時 resync・上書きの送信（#439） |
| `settings.js`（遅延） | 親ゲート・バックアップ／復元・初期化・がぞくコード・アカウント切替（#440）。目標回数・レッスン日・テーマは起動時やホーム・記録画面でも使うので app.js に残す |
| `popups.js` | ごほうびのポップアップ（`showPopup` 系）・バッジ告知の順番待ち・記録後の猫の演出（`celebrateRecord`）・動画モジュールの先読み（#441）。ホームにいるかは呼び出し側が `isHome` で渡す |
| `record-screen.js` | 記録フォーム・スタンプの下書き・まとめモード・送信（`submitRecord`/`finishRecord`）・「なおす」の開始（#442）。曲の色の割り当て（`buildSongColors`）と目標回数（`currentGoal`）はきろく・ホームでも使うので export する。画面の切り替え・きろくの描き直し・保存失敗の有無は `initRecordScreen` で受け取る |
| `html.js` | エスケープに加えて `setText`・`downloadBlob`（分けたモジュールが共通で使う DOM の小道具） |

**設計判断**

- **state は live binding で共有する（#439）**：`export let state` を読む側は常にいまの値を見るので、移したコードの `state.x` をそのまま残せる（`getState()` に書き換えると移動の差分が読めなくなる）。代入は `setState` だけで、取り込んだ側で `state = …` と書くと TypeError になり、書き漏れが黙って古い値を作らない
- **分けたモジュールは app.js を import しない**：循環 import を作らない。描画や保存など app.js 側の仕事が要るときは、`initLessonSettings({...})` と同じく起動時に関数を受け取る（`startCloudSync({ adopt, settled })`）
- **クラウドの順序は app.js から持ち込まない（#242）**：休んでいた間のレッスン日の取りこみは、`resyncAndSettle` がクラウドを取り込み終えてから `settled` を呼ぶ。app.js 側は「取りこむ日があるか」だけを見る
- **確定（`commitState`）の実体は app.js に残す（#442）**：取り消し待ちの削除（#398）・トースト・下書きの消去・きろくの描き直しと絡むので、手順ごと動かさず state.js には登録口だけ置く
- 分けるとファイルごとに gzip するぶん `js-entry` がわずかに増える（#439 で 33.5→34.1、#441 で 32.2→32.9、#442 で 32.9→34.1 KiB）。app.js は 2,374→1,174 行
- **せっていは丸ごと遅延にした（#440）**：⚙️ を押すまで要らない。`backup.js`・`dialog.js` は settings.js から静的に読むので、以前の「backup は読めたが dialog だけ読めない」ときの素の `hidden` 切り替えは無くなった（どちらも SW がプリキャッシュするので、読めないときは設定ごと開けない＝以前の backup 失敗時と同じ）。`js-entry` 34.1→32.2 KiB・`js-lazy` 16.4→19.0 KiB。E2E で `#importFile` に直接ファイルを渡していた復元のテストは、利用者と同じくせっていを開いてから渡す（開くまで受け口が無い）

## Service Worker のキャッシュ戦略

> Issue: #259 #289 #303 #317 #318 ｜ 実装: [sw.js](../sw.js)（`gen-sw` が生成）・[scripts/gen-sw.mjs](../../../scripts/gen-sw.mjs) ｜ テスト: tests/assets.test.js・e2e/sw-clip-cache.spec.js・`gen-sw:check`（CI）

`gen-sw` が作る `APP_SHELL`（コード）と `MEDIA_SHELL`（メディア）を install 時にプリキャッシュし、fetch は次の3通り。

| 対象 | 戦略 |
|---|---|
| コード（下記以外の同一オリジン） | **network-first**（`cache: 'reload'` で HTTP キャッシュも通さない）。**`response.ok` のときだけ**キャッシュを更新（#317）。ナビゲーションの代わりは `./index.html` |
| メディア（`img/` `icons/` `sounds/` `video/`・`isMedia`） | **cache-first**（#259 #303） |
| 外部オリジン | `caches.match` → 無ければ `fetch`。キャッシュに入れないので実質は素通し |

- キャッシュは `CODE_CACHE` と `MEDIA_CACHE` の2つ。名前はそれぞれの中身のハッシュで、`activate` は現行の2つ以外を捨てる。コードだけの変更では画像（約2.7MiB）を取り直さない（#259）
- `video/*.mp4` はプリキャッシュと予算の列挙（`listAssets()`）には入れず、`listHashOnlyAssets()` で**メディアのハッシュにだけ**載せる（#318）。初回再生時に `MEDIA_CACHE` へ入る

**設計判断**

- **network-first＋`cache: 'reload'`**：ES モジュールの `import` には `?v=` を付けられず、HTTP キャッシュが効くと古い版が残る。代償はシェル取得が毎回ネットワーク待ちになること。#142 の「ローカルファースト」は state の話で、シェル配信とは別
- **失敗レスポンスを焼かない（#317）**：5xx/404 をキャッシュするとオフライン時だけ白画面になる
- **外部オリジンは素通し**：Google Fonts はオフラインで取れずフォールバックのフォントになる（機能は落ちない）
- **キャッシュを2つに分けた（#259）**：全画像のオフライン保証を保ったまま再取得をなくす。画像を `MEDIA_SHELL` から外す案（保証が弱まる）と、旧キャッシュから1件ずつ引き継ぐ案（ファイル別のハッシュが要る）は不採用。install はメディアの無いものだけを `cache: 'no-cache'` で取る（古い版を焼かない）。代償はメディアを1つ変えると全メディアを確かめ直すこと（304 で済みうる）
- **クリップを cache-first にした（#303・のち #259 で全メディアへ）**：network-first では先読みがオンラインで効かず、1秒のタイムアウトに間に合わなかった。`PLAY_TIMEOUT_MS` の延長（間延び）と、先読みの `<video>` の使い回し（世代管理に手が入る）は不採用
- **動画もハッシュに載せる（#318）**：URL に `?v=` を個別に付ける案は `CLIPS` に版管理が戻るので不採用。代償は #259 と同じ

## アセット総量とパフォーマンス予算

> Issue: #147 #275 #284 #324 #430 ｜ 実装: [scripts/piano-pet-assets.mjs](../../../scripts/piano-pet-assets.mjs)（列挙・JS 分類）・[scripts/minify.mjs](../../../scripts/minify.mjs)・[scripts/build.mjs](../../../scripts/build.mjs)（配信物）・[scripts/perf-budget.mjs](../../../scripts/perf-budget.mjs)（予算 `BUDGETS_KIB`） ｜ テスト: tests/assets.test.js・`perf-budget:check`（CI）

**仕組み**

- 配信は `npm run build` が作る最小化済みの `dist/`（ソースは書き換えない）。予算も同じ変換（`minify.mjs`）を通した**最小化後**の gzip で測る。CI の E2E と Lighthouse も `dist/` を見る（`E2E_DIST=1`）
- 配信アセットの列挙は `piano-pet-assets.mjs` が唯一の正。`gen-sw` と `perf-budget` が**同じ集合**を見る。どのカテゴリにも入らないファイルがあれば失敗する
- JS は**起動をブロックするぶん（`js-entry`）**と**遅延読込（`js-lazy`）**に分ける。`classifyJs()` が `js/app.js` の import 文から導出する。どこからも import されない JS（`orphan`）は CI を落とす
- `total` は **html＋css＋js-entry**（初回ロードで必ず落ちてくる量）
- 判定は gzip が効くテキスト資産だけ。画像・音声はレポートにだけ出す。`video/` は列挙に含めない（18本・約 3.6 MiB）

**現状（2026-11-26 実測・`npm run perf-budget`）**

| html（`index.html`＋`manifest.json`） | 2 | 6.4 KiB | 7 KiB | 0.6 |
| css | 2 | 8.7 KiB | 10 KiB | 1.3 |
| js-entry（起動をブロック） | 22 | 34.1 KiB | 36 KiB | 1.9 |
| js-lazy（遅延読込） | 16 | 19.0 KiB | 21 KiB | 2.0 |

- 計測は LF で行う（`.gitattributes` で固定・#324）。既存のクローンは pull だけでは LF にならないので、未コミットの作業を退避して `git rm --cached -r . && git reset --hard` を一度実行する

**設計判断**

- **ファイル単位で最小化し、バンドルしない（#430）**：コメントごと配信していて total は 109.7→48.5 KiB。SW のプリキャッシュ・`classifyJs`・E2E の `page.route` は、ファイル名と import の形がソースと同じことに乗っている。`?v=` はソース由来のまま（minify の設定だけ変えても、コードは network-first なので最新が届く）
- **列挙を共有モジュールにした（#275）**：PNG→WebP 後に画像が**0件（実体 3.6 MiB）と報告され続けた**。同じ列挙を2つのスクリプトに書いていたのが原因。0件チェックでは部分的なずれを拾えない
- **起動ぶんと遅延ぶんを分けた（#284）**：丸ごと合計していると、動的 import へ移しても数字が動かない。分類を import 文から導出するのは、手書きのリストが実体とずれるため
  - `js-lazy` には**操作するまで読まない**ものと、**idle で必ず読む**もの（`cloud.js`）が混ざる。idle 読みを増やしても total は動かない点に注意
  - 遅延モジュールも SW のプリキャッシュには入れる（オフラインで動く）
- **history.js の遅延化（#324）**：枠を上げるだけの案は、遅延化できる候補が残るうちは不採用。`shop.js` は `game.js` が静的 import するので分けられず、`analytics.js`/`sentry.js` は起動時のエラーを捕まえる目的が薄まる
- **history-view.js（#382）**：state も DOM も触らない HTML 組み立てだけを遅延へ移した。`history.js` を re-export し、app.js はこれだけを読む
- **起動ぶんを遅延へ移したら、両方の枠を動かす（#440）**：せってい（親ゲート・バックアップ・がぞくコード・アカウント）を `settings.js` へ分けて遅延にしたら、js-entry 34.1→32.2・total 49.2→47.3 と起動ぶんが減った一方、js-lazy は 16.4→19.0 で枠（18）を超えた（LF・最小化後 gzip）。予算の目的は起動の軽さなので js-lazy を 21 に上げ、同時に js-entry を 37→36 へ締めた（実測の約1割増し）。遅延の枠だけ上げると、枠が緩む一方になるため。total 53 は据え置き
- **予算を上げるときの約束（CLAUDE.md ④）**：まず最小構成を徹底し、それでも超えるときだけ枠を動かす。`CLIPS` の9件をループ生成に畳む案は、パスが grep できなくなるので不採用

| 経路 | spec |

- WebKit は `playing` を出さないので、クリップは**フォールバックが壊れないこと**だけを見る

**設計判断**

- **クラウド同期は偽モジュールで通す（#277）**：`cloud-sync.js` が `cloud.js` を動的 import するので、`page.route` で差し替えれば本番コードを変えずに実経路を通せる（`window.__cloudDoc`・`window.__onRemote`）。他の spec は Firestore を遮断している。エミュレータは CI の起動コストが高く、見たいのはマージ規則なので不採用
- **#261 の退行ガードはページ内で観測する（#323）**：再現には、1回目のフェードアウト開始直後（約250ms の窓）に2回目を重ねる必要がある。固定の `waitForTimeout` は CI の遅れで静かに空振りするので、`MutationObserver` で「`--show` が外れた瞬間」を見る
- **E2E の準備は `e2e/helpers.js` に寄せる（#429）**：spec は `@playwright/test` でなくここから `test` を import する。Firebase の遮断とオンボーディング済みが自動で効き、遮断の書き忘れで本番 doc に触れることがない
- **「動画が出ない」はコインのポップアップで見る（#429）**：ポップアップは動画を見終わるまで出ない（#400）ので、固定時間を待たずに「出さないと決まった」ことが分かる
- **定数表は写さず突き合わせる（#429）**：バッジの判定⇔カタログ、ショップ⇔猫の描画⇔画像の実体のように、実体どうしを比べる。一覧を写したテストは、追加のたびに直すだけで事故を捕まえない
- **ローカルの workers は4まで（#325）**：既定のままだと http-server を奪い合って flaky になり、かえって遅い
- **`Math.random` のモックは値域 `[0,1)` の中で**：`() => 1` は Fisher-Yates の範囲外スワップでバッグを壊す。`0.999` にする

**まだ埋まっていない空白**

- **オフライン / SW**：ほとんどの project は `serviceWorkers: 'block'`。担保は `gen-sw:check` と `sw-clip-cache.spec.js`（install・オフライン起動・index.html への代替・コードだけ／メディアだけの更新・失敗レスポンスを焼かない）。オフラインでの記録と WebKit の SW は未検証（#289）
- **`prefers-reduced-motion`**：ポップアップの確定と、えさやりクリップを出さないことは検証済み。CSS だけの停止（猫・スタンプ・バー）は E2E なし
- **えさやりクリップの WebKit 実再生**：「読めるが `playing` が来ない」経路と実機 iOS は未検証（#294）
- **サウンド**：計算は単体テスト、威嚇の出し分けは E2E。鳴った音そのものは未検証
- **曲の色**：単体テストのみ
- **ダークモード**：切り替えと保存値、目標達成カードのコントラストは E2E（`layout-theme`）。ほかの見た目は未検証
