## 画面とナビゲーション

ハッシュベースのSPA（[router.js](../js/router.js) / [app.js](../js/app.js) `render`）。

- ボトムナビ4タブ：**ホーム / きろく / ショップ / バッジ**
- 練習記録入力（record）はナビに出さず、ホームの「れんしゅうを きろくする」ボタンから開く（ナビ上はホームを選択状態に保つ）
- UI文言はひらがな主体（5歳でも読める表記）
- **アプリアイコンのショートカット（#235）**：`manifest.json` の `shortcuts` に「れんしゅうを きろくする」を1件登録し `./index.html#/record` へ直行させる（朝の忙しい時間に1〜2タップ短縮）。アイコンは `icons/icon-96.png`。

> **設計判断（#235）**: **router 側の改修は不要**だった。起動時に `app.js` が `router.syncFromHash()` を呼び `viewFromHash('#/record')` が `record` を返すため、ショートカットURLで起動すればホームを経由せず記録画面が開く（＝ディープリンクは既存実装で成立）。追加したのは manifest の `shortcuts` と 96px アイコンのみで、専用アートは起こさずアプリアイコン（`icon.svg`）から生成＝ブランド一貫・最小構成。**iOS/iPadOS は manifest `shortcuts` に非対応**のため、この短縮は Android/デスクトップPWA 限定（iOS は従来どおりホームのボタンから入る＝機能欠落ではなく1タップ多いだけ）。

### こどものアバター（#121）

ヘッダ左隅にこども本人のアイコンと名前を常設表示する（home / きろく の両画面ヘッダに `renderChildAvatar` が `.child-avatar` を一括更新）。「いま自分が操作している＝自分が主役」の自己効力感を与え、本番（こども用）とテスト用アカウントを画面上で見分ける役割も兼ねる。

- **アイコンはタップで選択**：選択オーバーレイ（`#avatarOverlay`）が開く。こども本人が選ぶ操作なので**親ゲートは挟まない**。絵文字10種（🐥🐰🐻🐼🦊🐸⭐🌸🦄👑・[child-profile.js](../js/child-profile.js) `CHILD_AVATARS`）から選び、なまえ（最大12文字）も入力できる。
- **顔写真は不採用**：認証なしの共有 Firestore に保存するため、子の顔写真はプライバシー上不可。絵文字なら軽量・クラウド同期可・PII を増やさない。
- 名前は入力中もヘッダに即反映し、閉じるときに前後空白を落として確定保存する。analytics には名前・アイコンを送らない（PII規約）。保存先・フォールバックは [data-model.md](./data-model.md) の `pet.childName` / `pet.childAvatar`。

### 猫のmood

プリレンダ画像の表情。恒常表示は idle/sleep、happy/love/hiss は演出中の一時差し替え。

| mood | 条件 | 表現 |
|---|---|---|
| `idle` | 通常 | ゆっくり呼吸（画像を scaleY でふくらませる） |
| `happy` | 練習記録直後 | うれしい表情に差替＋ぴょんと跳ねる・ハートが飛ぶ |
| `sleep` | 最後の練習から2日以上経過 | 目を閉じた表情＋Zzz |
| `love` | なでた時の反応 | だいすき（ハート目）表情に差替＋しっぽふり／喜ぶ |
| `hiss` | なで反応で威嚇（シャー）を抽選した時（#187） | 威嚇表情に差替のみ。喜び演出（ハート・しっぽふり）は出さない |

## 初回オンボーディング（猫の吹き出し紙芝居・#141）

初回起動時、猫の**吹き出し3画面の紙芝居**で「①れんしゅうを きろく → ②ごほうび → ③きせかえ・ごはん」を案内し、最初の成功体験で初期離脱を防ぐ。実装は [onboarding.js](../js/onboarding.js)（紙芝居データ＋フラグ）と [app.js](../js/app.js)（DOM 制御）。

- **新規アセットは持たない**。既存の猫SVG（`catMarkup`・若猫）をカードに流用し、上向きしっぽの吹き出しで説明する
- ひらがな主体・大ボタン（「スキップ」「つぎへ／はじめる！」）。進捗ドット3つで現在地を示す。最後の画面ではボタンが「はじめる！」に変わる
- **スキップ可**。「スキップ」または「はじめる！」で `piano-pet-onboarded='1'` を立てて閉じ、以後は出さない（端末ローカルの単独フラグ）
- localStorage が読めない環境（プライベートモード等）では「見た」扱いにして案内を抑止する（うるさく出すより無害側に倒す）

## 練習記録入力（2モード：スタンプ / まとめて）

日付の下に「**🐾 スタンプ / 📝 まとめて**」のモード切替タブがある。既定はスタンプモード。実装は [record-form.js](../js/record-form.js)（純粋ロジック）と [app.js](../js/app.js)。日付は両モード共通でデフォルト今日。モード切替時は入力途中の内容を「曲×回数」として相互変換して引き継ぐ（`stampsToSongs` / `collectSongs` / `songsToStamps`）＝取りこぼしなし。

### スタンプモード（親=曲えらび／子=スタンプ・#117）

タイル状の「ハンコ」を押して回数を数える、子供にも押せるUI（役割ガイドの文言は #189 で削除し、チップとハンコだけのシンプルな画面にした）。

- **きょくを えらぶ**：曲名チップ（過去の曲を「最近ひいた順（最終練習日）→累計回数」で最大8件サジェスト＝`pastSongNames`・#252）。**練習する曲は移り変わるため累計回数ではなく直近に弾いた曲を上位に出し**、いま練習中の曲が必ずチップに載るようにする。漏れた曲も新規曲入力欄の `datalist`（過去の全曲名）から選べる。「＋」で候補に追加。各チップには曲の色スウォッチが付き、選択中はチップ全体がその色になる（#122）
- **ハンコを おす！**：タップで選択中の曲のハンコ（🐾）が1つ増える。最低「目標マス」ぶん（既定10・親が5〜20で調整 #238）、超過時も常に1マス余分に出して押し続けられる。「○こ / もくひょう Nこ」表示、「↩ ひとつ もどす」で直前を取り消し。**押したマスは押下時に選ばれていた曲の色で塗られる**
- **当日中はスタンプカードを引き継ぐ（#164/#186）**：押したスタンプは下書きキーに一時キャッシュされ、ホームに戻って開き直しても0からリスタートしない（打鍵ごとの Firestore 同期はしない）。**記録を確定した後でも当日なら引き継ぐ（#186）**：当日セッションが既にあれば下書きではなくそのセッションからスタンプを復元（`songsToStamps(combineSongs(...))`）し、続きを押せる。日付が変われば下書きは破棄して0スタート（→ [data-model.md](./data-model.md) の `stamp-draft`）
  - **当日の記録画面は「その日ぜんぶ」を表す（#186）**：当日セッションの全内容を復元しているため、submit 時は追記ではなく**置き換え**る（`isToday` 分岐）。当日中の押し増しが二重計上されず、同日同曲が1レコードに収まる。日付欄を過去日に変えた場合のみ従来どおり合算する
  - **同日同曲の合算表示（#186）**：きろくタブの表示は `combineSongs` で同名の曲を1行に合算（既存の分割済みデータも表示時に合算）。`mergeSameDaySessions` も統合時に `combineSongs` する

#### 曲の色（決定的ハッシュ＋衝突回避・#122/#165）

曲名→色は [song-color.js](../js/song-color.js)。曲名を FNV-1a ハッシュして色相（0〜359）を取り、彩度・明度は固定（`songColor` が `fill`/`tint`/`ink` を返す）。**保存しない**ので `sessions` さえ同じならどの端末でも同じ曲は同じ色。空名は無彩色グレー、前後空白は無視して同一視。

- **色かぶり回避（#165）**：ハッシュだけだと別の曲の色相が近接して同じ色に見えることがある。`assignSongColors(names)` は曲名リストを先頭から走査し、既に割り当てた色相に近すぎる（**最小ギャップ 25°未満**）曲は隣の色へずらす。並びは累計回数順（`songTotals`）で決定的なので #122 の「端末間で一致」は維持される。スタンプ／チップ／コレクションは同一マップ（`buildSongColors`）を基準にする。

#### スタンプ音（#139 / #154 / #238）

スタンプを押すたびに音程が**ドレミ…と上がる**（1マス目＝ド）。目標マス（最後の1マス）は **Cメジャー主和音（ド・ミ・ソ）**で「シャラーン」と解決し、同時にレベルアップ音が鳴る。目標マス数は可変（#238）で、途中マスは目標数に応じて1オクターブ内に再配分される（→ サウンド節）。

> **設計判断（#238・1日の目標回数を可変に）**: 固定10だった目標を親ゲート内で **5〜20** に調整可能にした（`pet.dailyGoal`）。
> - **保存先＝クラウド同期される `pet` 配下**：進捗リング・達成演出・スタンプのマス数/音程は全端末で一貫すべきなので、端末ローカルの `settings` ではなく同期対象の `pet` に置く（`childName`/`catStyle` と同じ扱いで CLOUD_FIELDS・マージ規則の追加は不要）。
> - **達成ボーナス（コイン）は目標から分離し閾値10で固定**（`GOAL_BONUS_THRESHOLD`）：`recomputeState` は全履歴に `calcRewards` を再適用するため、報酬を可変目標に連動させると**過去の記録のコインまで遡って増減**する（下げれば水増し・上げれば娘のコインが減る）。表示上の目標だけ可変にし、報酬計算は固定閾値で安定させる。
> - **スタンプ音程のマス可変対応**：旧 `stampSemitone` は `12*floor(i/7)` でオクターブを無制限に積み上げ、goal=20 では途中が +31 半音まで甲高くなっていた。分母 `(goal-1)` で 0..6 のダイアトニック度へ正規化し、途中マスを**1オクターブ内に再配分**（+12 を超えない）、目標マスは高いド（+12）＝主和音で解決。goal=8 のとき途中がちょうど ド レ ミ ファ ソ ラ シ に一致する基準ケース。

### まとめモード（親の後追い入力・#123）

その場でスタンプを押さなかった日を、**親が後からまとめて記録**するための入力。

- **きょく＋かいすう を まとめて**：1行＝曲名（`datalist` で過去曲を補完）＋回数ステッパー（− / 数値 / ＋）。「＋ ぎょうを ふやす」で行追加、各行の「✕」で削除
- 「ごうけい ○ かい」をライブ表示。集約は `collectSongs`（空名・0以下の行は除外）

### 記録の確定（両モード共通）

**きろくする**：合計0回（有効な入力なし）は記録不可（`isValidSession`）。スタンプモードで曲未選択ならヒント表示。

記録後の動作：

1. コイン・XP・ストリーク・バッジを計算して反映（`applySession`）
2. ホームへ遷移、猫が喜ぶアニメ。節目（レベルアップ／新バッジ／連続日数の節目）は特別演出 `playCelebrate`、それ以外はランダムな日常のお祝い `playHappy`（`celebrateRecord` が出し分け / #81）
3. 獲得コインのポップアップ（レベルアップ時はその旨も表示）
4. 効果音：記録完了音 →（レベルアップ時）レベルアップ音
5. お休み券で連続を守った場合 → お休み券ポップアップ、新規バッジ獲得 → バッジポップアップ（複数は順番に）
6. **同じ日付に既存記録がある場合は統合して全再計算**（`recomputeState`、目標達成ボーナスの二重取りを防ぐ）
7. **過去日（最終練習日より前）の新規記録も全再計算経路で確定**（#260）。`applySession`→`updateStreak` は日付が時系列順で届く前提の逐次更新のため、過去日をそのまま流すとストリークが1に巻き戻り `lastPracticeDate` も過去へ戻る。挿入＋`recomputeState`（日付昇順の再生）で連続日数を保つ。後追い入力では「きょうのおまけ」（#148）は抽選しない（`bonusCoins: 0`）
8. 日付欄は**未来日を選べない**（`max=今日`。手入力等で入っても submit 時に今日へ丸める。未来日レコードは 7. と同種の時系列破壊を起こすため）

> **設計判断（#260）**: 本修正は新規汚染の防止であり、旧バグで巻き戻った既存データの自動修復は行わない（起動時 recompute は同日重複マージ時のみ）。クラウド同期の初回 reconcile または次回の記録・編集・削除で全再計算され自己修復される。

## 記録履歴（きろく）

- 連続記録カード：いまの れんぞく / さいこう きろく
- **今週の ふりかえりカード**（#144）：今週（月曜起点）の「かいすう／きょく数／れんしゅうした日数」を集計表示（[history.js](../js/history.js) `weeklySummary`）。「せんせいに おくる」共有ボタンは #192 の閉塞を経て**削除済み（#261）**（`shareReview`/`reviewShareText`/計測 `review_shared` もコードごと撤去）
- 週ごとの合計回数の棒グラフ（直近8週、SVG・外部ライブラリなし＝`weeklyChartModel`）
- **れんしゅうカレンダー**（月間ヒートマップ・#236）：日ごとの練習量を色の濃淡で見せる草式ヒートマップ。日曜起点の CSS グリッド、濃淡は**4段階**（0／目標の半分未満／半分以上目標未満／目標達成）で、**達成閾値は可変目標（#238）に追従**（`heatLevel(count, goal)`）。前月・翌月ボタンで移動（`shiftMonth`）。今日はアウトライン強調、未来日は淡く表示
  - **設計判断**: 曲別コレクション（#122）と同じく専用データを持たず `sessions` から都度導出＝同期・マイグレ不要でズレが原理的に起きない。描画は SVG ではなく CSS grid（セルが多くグリッドの方が軽量・レスポンシブ）。日タップで該当日へスクロールは俯瞰が主目的のため MVP では見送り
- **きょくべつ コレクション**（#122）：曲ごとの累計回数を「多い順→新しさ」で一覧（`songTotals`）。決定的ハッシュ色のスウォッチ＋「○かい」。回数0や空名は出さない
- **曲マスター👑**（#149）：累計が `SONG_MASTER_COUNT`（=50）回に達した曲に👑を表示（`isSongMaster`）
- 記録一覧（新しい順）：日付「M月D日（曜）」・曲名・回数・合計。各記録に「✏️ なおす」「🗑️ けす」
- **はなまるスタンプ**（#145）：各記録にワンタップで評価スタンプ（💮はなまる／🌟じょうず／👍がんばった）を付与・表示。同じスタンプの再タップで解除。固定絵文字のみで自由記述は持たない
- **練習の質メモ**（#239）：はなまると同型で「どう弾いたか」（🐢ゆっくり／🎵ふつう／🚀はやく）を追加。付与／解除→保存→クラウド即送信・`renderHistory` 再描画（実装は praise と共通の `setSessionMark`/`markRowMarkup`・#261 で設定駆動に統合）。報酬非依存で再計算不要。ゆっくり練習→仕上げの流れを親子で見返せる
  - **設計判断**: praise を素直にテンプレ流用（Session への1フィールド追加・merge/recompute はスプレッドで自動保持）し、CSS も共通ルール化。自由記述は持たず analytics へも絵文字種別以外を送らない（PII規約準拠・#145 と同方針）

**編集・削除**
- 「なおす」：record 画面に切り替え、スタンプカードへ内容を復元して編集モード（`songsToStamps`）
- 「けす」：確認ダイアログのうえ削除
- 編集・削除後は **sessions を唯一の正として XP・レベル・コイン・ストリーク・バッジをゼロから全再計算**（`recomputeState`）。報酬演出は出さない

## ショップ

### ごはんを あげる（えさやり・消費型）

実装は [feed.js](../js/feed.js)。

| アイテム | 価格 | なかよし |
|---|---|---|
| 🐟 おさかな | 5コイン | +1 |
| 🥛 ミルク | 7コイン | +1 |
| 🍰 ケーキ | 15コイン | +3 |

- 「あげる」でコインを消費し `pet.affinity` が上がる → もぐもぐポップアップ。えさは別タブ（ショップ）であげるためホームの猫が見えないので、ポップアップ内でえさアイコンが もぐもぐ揺れて → 食べられて消え、なかよし💖が弾む演出を付ける（CSS `coin-popup--feed`・#217）
- 消費コインは `pet.foodSpent` に累積し、記録の編集・削除時の全再計算でも所持コインが復活しないようにする
- 見出しに現在の「なかよしレベル」名を表示し、下に**なかよし ごほうび解放リスト**（Lv1〜8・🔒/💝）を並べる（#124）

#### なかよしレベルとご褒美（#124・#216）

`affinity` のしきい値でレベルが上がりご褒美が解放される（[feed.js](../js/feed.js) `affinityLevel` / `affinityRewards` / `bondCelebrateChance`）。**#216 で 5→8段階に細分化**し刻みも詰めた（えさやり等の成果が「すぐ見える」ように）。番号で報酬を判定する消費側（`unlockLevel` / `bondCelebrateChance` / `tierFromBond` / エンブレム）は旧しきい値と**等価な affinity 値の新レベルへ再マップ**してあり、既存ユーザーの解放状態は退行しない。

| Lv | 名前 | 必要 affinity | ご褒美 |

> **検討して受容した過渡期リスク（複数端末×バージョン差でのコイン振動）**: デプロイ直後、旧価格JSの端末と新価格JSの端末が混在する期間は `spentCoins` が端末ごとに異なり coins が振動しうる。realtime の `mergeCloud` は cloud-wins で受信 coins をそのまま採り、起動・復帰時の `reconcileInitialCloud`/`resyncFromCloud` は現行価格で再導出するため、旧JS端末が低く push → 新JS端末が高く push、を交互に繰り返す。ただし **(1) sessions・inventory（唯一の正）は無傷でデータ消失なし、(2) 両端末が新JSになった時点で恒久収束する自己修復性がある**。購入価格を state に固定する対案（`spentCoinsTotal` 追加）は、旧価格を知らない新JS側で移行基準値を作れず、旧JS push での新フィールド欠落が自己修復しないため、**自己修復する一過性の問題を自己修復しない恒久リスクに置き換える**として不採用。運用上はデプロイ後に各端末で一度アプリを開けば過渡期は即終了する（bridge-chat topic_1784289217445 で合意）。

> **設計判断（#126・解放ゲート）**: 解放判定は購入時（`canBuy`）のみ参照する。装備・描画は現在Lvを一切見ず inventory/equippedItems の所属だけで判定するため、affinity 低下で再ロックされても**所持品は外れず・消えず・装備継続**（全再計算でも不変）。既存ユーザーは現在の affinity から相応に解放済みで始まるためマイグレーション不要（導出の詳細は [data-model.md](./data-model.md)）。

### きせかえ アイテム 品質基準（#191・#126へ引き継ぎ）

既存・新規を問わず衣装が満たすべき基準。子供＝「一目で何かわかる・買った絵文字と一致」、親＝「コイン（練習の努力）の対価として段階的に豪華」を両立させる。新規アイテムはこの基準を満たしてから追加する。

0. **描画方式＝本体と同じ水彩ラスター**：衣装は猫本体（プリレンダ水彩画像）と画風を統一するため透過ラスターで用意する。**A（SVG）とB（ラスター）の混在は禁止**（猫の上で水彩とベクターが同居すると画風が割れ本基準の目的に反する）。色違い展開は行わず、必要な色は個別の画像として作成する。装備時は dressup の `<g transform>` 内を `<image href>` に差し替えて重ねる（ドラッグ・アンカー・スナップは無改修）。画像は `img/` 配下でSWプリキャッシュ対象だが perf-budget（html/css/js のみ判定）の対象外。
1. **絵文字一致（第一条件）**：ショップアイコン（絵文字）と装備後のシルエット・主色が同系統に見える。買った🎀が猫の上で🎀と認識できること。
2. **小サイズ可読**：猫装着サイズ（scale≈0.8）で、塗りの面＋2〜3色で「何か」が判別できる。細い線画だけに依存しない。
3. **顔・表情を残す（バランス）**：neck/face は猫の目・口にかからない配置・サイズを既定とする。王冠・はなかんむり等の head 上位アイテムは、目を残す範囲なら頭頂〜額の装飾が多少かかってもよい。
4. **スロット内の差別化**：同一スロットのアイテムは形か主色で明確に別物とわかる（neck4・head4 が過密で被りやすい点に留意）。
5. **価格＝豪華さの段階性**：高価格ほど面積・装飾・きらめきを増やし、価格順に視覚的グレードが上がる。

> **設計判断（#191）**: 着せ替えは「拡充（#126）の前に既存品質を上げる」順序とする。絵文字を事実上の完成イメージとして基準1に据えるのは、5歳児にとってショップ選択時の期待（絵文字）と装着結果の不一致が最も混乱・がっかりにつながるため。描画方式を手書きインラインSVGから水彩ラスターへ移行した（基準0）理由は、猫本体が「SVGでは水彩品質に届かない」としてラスター化済みで、衣装だけSVGだと画風が割れること。ラスターの弱点である色違いの量産は**色違いを行わない**方針で割り切る。衣装は mood/tier 非依存で1アイテム1枚で済み、perf-budget 対象外なので肥大化リスクは小さい。

> **設計判断（#229＋#234・高解像度化とWebP化を同時実施）**: ピンチ拡縮（#205・絶対スケール最大3.0倍）で 2x ソースが引き伸ばされアラが出るため、装着14点＋置物2点＋本体45枚の作画枠を **retina 2x → box×3** に引き上げた。PNG のまま倍率を上げると SWプリキャッシュ・初回DLが線形に増える（box×3 で ~5.2 MiB）ため、**同一ブランチで PNG→WebP 化**（`cat-image.js` の href 拡張子・`gen-sw.mjs` の収集拡張子を `.webp` に、全61枚を quality85 で変換）。結果 **4.82 MiB（従来PNG）→ 3.60 MiB（box×3 WebP）** と、解像度を上げつつ総量を約25%削減。WebP は iOS Safari 14+（2020〜）でネイティブ対応し 2026 時点で旧版シェアが実質消滅のため `<picture>` フォールバックは設けない（#167 の PNG統一判断を反転）。全61枚のブラウザデコードを実測確認。演出・グラフSVGは対象外。

> **設計判断（#210・拡充／#213・装着感／#241・環状アイテム）**:
> - **#210**：手薄だった face / back を中心に4点追加（`beret`/head・`sunglasses`/face・`bell`/neck・`wings`/back）。新規スロット・置物系は導入せず既存アンカーと描画パイプラインを流用＝最小構成。差別化（基準4）として `sunglasses` はレンズ色付き（めがね＝透明と区別）、`bell` は鈴チャーム（星の首輪と区別）。
> - **#213**：一部アイテムが「平置きの商品写真」調で猫に重ねると浮いて見えたため5点（`bowtie`/`ribbon`/`scarf`/`flowerCrown`/`glasses`）をアンカー原点基準で身につけた構図に再作画。原点ルール＝neck系は y0 に巻き帯→真下に蝶結び、`scarf` は上端の輪を y0・フリンジを y>0 に垂らすU字、`flowerCrown` は y0 を頭頂としアーチ内側が頭に沿う環状（このため box を 96×40→96×48 に拡張）、`glasses`（#212 統合）はブリッジ(0,0)中心で左右対称・正面向き・レンズ透明＋フレーム視認可。**テンプル（つる/耳掛け）は描かない**＝丸まった耳掛けがフレーム欠けに見えたため、レンズ2枚＋ブリッジの正面フレームのみ。**アイテム画像は衣装単体（中央は透過）で、猫の顔・チャーム等を描き込まない**（重ねたとき二重に見えるため）。
> - **#241**：首輪(`collar`)・鈴の首輪(`bell`)・花冠(`flowerCrown`)は本来 首／頭を一周する輪だが、#211 で全アイテムを前面へ一律描画したため**輪の背面の帯まで猫の手前に出て前後関係が不自然**だった。背面帯を別レイヤーで首の裏に描く案は本体画像が不透明で隠れる（#211 の断念理由）ため不採用。対応は**アート差し替えのみ**＝3点を「前面から見える弧だけ」に再作画し背面帯を描かない。`ITEM_BOX` 据え置きでコードは無改修。

### きせかえ 自由配置（ドラッグ・#168／ピンチ拡縮・#205）

ホームの「👗 きせかえ」トグルで編集モードに入ると、装備中の衣装を**1本指ドラッグで移動・2本指ピンチで拡縮**できる。実装は [dressup.js](../js/dressup.js)（pointer追跡）＋ [cat-image.js](../js/cat-image.js) `itemsSvg`/`itemAnchorPct`/`itemAnchorScale`。

- **配置データ**：`pet.itemLayout`（.catコンテナ基準の%・ビューポート非依存）。`pet` 内なので Firestore へ自動同期。`shop.js` の装備ロジックは無改修
- **フォールバック二段構え**：座標が無い衣装は既定アンカー位置・基準スケール（`a.s`）で描画し、初操作で記録する
- **位置スナップは廃止（#214）**：ドロップ時は常にその座標を記録する。範囲外はステージ内に clamp、スロット跨ぎはしない。座標を持たない旧データはフォールバックで従来どおり描画（後方互換・マイグレ不要）
- **ピンチ拡縮（#205）**：2本指の距離比で `scale` を更新。**絶対値**で `0.3〜3.0` に clamp。基準スケール `a.s` の ±5% 以内に入ると `a.s` へ吸着し「元のサイズ」へ戻しやすくする。2指間距離が **10px** 動くまでは拡縮を始めない（誤操作・ガタつき防止のデッドゾーン）。ピンチ中は位置を固定
- **最小タッチ領域（#215）**：アイテムは `<g scale>` で縮むと `<image>` のヒット領域も縮み掴みにくいため、各 `<g>` に透明ヒット矩形（`.cat__item-hit`）を**逆スケール**で内包する（`width=max(box, MIN_HIT_UNITS(44)/scale)`）。scale 適用後の画面サイズが常に約66px以上になる。見た目は不変
- **なで競合の回避**：編集モード中は `petCat`（なで演出）を無効化。猫の周囲を点線で囲う。「✅ できた！」で抜ける
- **ゴーストデータ掃除**：`commitState` の `cleanItemLayout` が、装備していない衣装の座標を除く（同期ペイロード健全化）

> **設計判断（#168）**: 配置座標は `equippedItems`(id配列) に埋め込まず**別フィールド `pet.itemLayout`** に分離した。`shop.js`/`equipItem` 系の装備ロジックとテストを温存し、状態遷移へのバグ混入を避けるため。
>
> **設計判断（#205・Antigravity対称レビュー topic_1782030433684 で合意）**: ①`scale` は**乗数でなく絶対値**で保存する。乗数（`a.s × k`）だと将来アセット更新で基準スケール `a.s` を調整した際、すでに自由配置済みの衣装サイズまで勝手に変わり配置と齟齬が出る。絶対値ならユーザーの意図したサイズが守られ `pos?.scale ?? a.s` で完全後方互換。②**定位置に戻しても実座標は焼き込まず** `{scale}` のみ保持し、位置は描画時にアンカーから引く。③5歳児UXの補助は**「基準スケール吸着」と「ピンチ開始デッドゾーン(10px)」の2点のみ採用**。clamp で上限下限は安全に頭打ちになるので、枠線の状態別色分け・clamp 到達時の色シグナルは最小構成のため見送り。
>
> **設計判断（#214・topic_1782394334271 で合意）**: 位置スナップ（既定アンカーへの吸着）を**廃止**。「思った位置に置けず勝手に戻る」操作ミスのように感じられ自由配置の意図に反するため。**サイズの基準スケール吸着（#205）は別物**（行き過ぎた拡縮を綺麗なサイズへ戻す補助）なので温存する。
>
> **設計判断（#215・同 topic）**: ピンチ縮小時のヒット領域確保は、JS側の最近傍アイテム探索ではなく**マークアップ側の逆スケール透明矩形**で行う。理由は①ブラウザ標準のポインタイベントとSVGの描画順（DOM順＝上層優先）にそのまま乗れて重なり時の挙動が素直、②位置・サイズを別途同期して距離計算するコードが不要で `cat-image.js` 内にロジックを閉じ込められ保守性が高い。`MIN_HIT_UNITS=44` は実機で微調整可能な単一定数。ライブのピンチ中はヒット矩形を再描画せず確定時の再レンダで更新。
>
> **設計判断（#211・同 topic）**: cape を背面レイヤー（`cat__back`）から**前面へ移し** `cat__back` SVG 自体を撤去した。背面だと不透明な本体画像に完全に隠れて「見えない・掴めない」ため。代替案（背面のまま端だけ覗かせ＋本体 `pointer-events:none`）は可視性を解決できず、なで反応にも影響するため不採用。cape の**アンカー種別（`back`＝位置・基準スケール）は不変**で、変わるのは描画レイヤーのみ。前面化で旧アートが前掛けに見える点は #213 へ申し送り。

### 写真モード（きせかえ猫のスナップ・#237）

ホームの「📷 しゃしん」で、飾った猫を**1枚の画像**にして共有／保存できる。きせかえ遊びに「見せたい・残したい」出口を作り、祖父母への共有動線にもなる。実装は [cat-snapshot.js](../js/cat-snapshot.js)（canvas 合成）と [app.js](../js/app.js) `shareCatPhoto`。

- **合成**：`renderCatCanvas(catEl, 600)` が 600×600 の canvas に、画面と同じ z 順（背面置物 z1 → 本体 z2 → 装備 z3 → 前面置物 z5）で描く。**演出SVG（`cat__fx`）は初期スコープ外**
- **共有/保存**：`navigator.canShare({files})` が使えれば Web Share、非対応なら `a[download]` にフォールバック。**端末内完結・サーバ不要**
- **PII**：共有ペイロードに曲名・こども名を含めない。タイトルは固定文言「ピアノペット」、ファイル名も固定 `pianopet.png`、`text` は付けない。計測は操作フラグ（`cat_photo_shared` / `cat_photo_saved`）のみ
- **背景**：透過のまま共有すると環境により黒背景になるため、アプリのクリーム色（`#fff6ee`）で塗ってから合成する

> **設計判断（#237）**: 合成位置は cat-image.js のレイアウト数式（ANCHORS/ITEM_BOX/SCENE_BOX＋`itemLayout`）を**再実装せず**、実際に描画されている **DOM の `<g transform>` と `<image>` の box をそのまま読み取って** canvas に落とす。数式を二重管理すると #168/#205 や box 変更のたびに画面と写真がズレるため、「画面の DOM が唯一の真実」にして一致を保証する。画像はすべて同一オリジンなので canvas が汚染されず `toBlob` が使える。SVG を丸ごと data URL 化して描く案は、`<image>` の外部参照が「画像として読み込んだ SVG」ではブロックされるため不採用。

### 猫スタイル切り替え（#66）

きせかえ編集モード中だけ猫の下に**スタイルピッカー**（`#stylePicker`）が出る。ちゃとら／しろ／ぐれー（ロシアンブルー）の3種から選べ、`pet.catStyle` に保存して Firestore 同期。未定義は 'tora' フォールバック＝既存ユーザー後方互換。

- サムネイルは本番の `cat_{style}_low_idle` をそのまま使う。**ピッカーを開いた時点で各スタイルの idle が自動ロードされる**ため切り替え時のチラつきがない
- 切り替えは `commitState` → `renderHome` が本体画像・preload を新スタイルで引き直す
- スタイル別の衣装アンカー補正は `STYLE_ANCHOR_OFFSETS`（cat-image.js）

> **設計判断（#66・Antigravity対称レビュー topic_1781184658026 で合意）**: ①スタイル切り替えUIは**きせかえ編集モード内**（「見た目を変える」文脈で5歳児が自分で発見できる。ショップ解放は #126 と被るので将来拡張）。②命名は既存も含め **`cat_{style}_{tier}_{mood}` に全リネーム**（特例分岐を残さない。SWは gen-sw 再生成で旧キャッシュを自動破棄。茶トラ15枚は中身同一でもURL変更により一度だけ再DLされるが許容）。③**JSの preload は選択中スタイルのみ**。SW は `img/cat` 全45枚（~3.8MiB）をプリキャッシュするため、これはネットワークではなく**デコード/メモリの抑制**であり、オフライン中のスタイル切替も保証される。④立ち耳ロシアンブルーの衣装アンカーずれは生成側でポーズを無理に揃えず（体格バランスが崩れる）`STYLE_ANCHOR_OFFSETS` で吸収する。納品画像の実測では頭頂が tora/shiro=viewBox y31・russianblue=y35 と差4ユニット（ステージ2%）で軽微だったため**オフセットは空のまま**（手動ドラッグ #168 でも調整可）。

### 置物・小物系 アイテム（シーン配置型・#226）

装着型（猫アンカー基準・slot排他）とは別カテゴリの、**ペットに着せず猫の前後シーンに置く装飾アイテム**。実装は [shop.js](../js/shop.js)（`slot:'scene'`＋配置ロジック）と [cat-image.js](../js/cat-image.js)（`SCENE_BOX`／前後2層）。MVPは2点：🧶 けいとだま（前面）・🛋️ クッション（背面）。

- **データ**：配置中IDは `pet.placedItems`（`equippedItems` とは別配列・排他なし複数配置）。購入は装着と共通（`buyItem`・slot非依存）
- **描画（前後2層）**：`catMarkup` が `.cat` 正方枠に `cat__scene--back`(z1・本体の背後) と `cat__scene--front`(z5・演出の手前) の2つのSVGを最初から持ち、`SCENE_BOX[id].layer` で振り分ける。画像は `img/cat/scene/{id}.webp`（透過・box×3・中心原点）
- **配置/ドラッグ**：置物も `.cat__item`＋`<g transform>` なので dressup（#168/#205）が**無改修で**ドラッグ・ピンチできる。装着アンカーを持たないため既定（`SCENE_DEFAULT_PCT`＝足元寄り50%,64% / 基準スケール1）を返し、描画の初期位置と掴み開始位置を一致させて初回ドラッグのジャンプを防ぐ。座標は `itemLayout` を装着系と共用
- **背面置物の選択（#240）**：背面置物は不透明な本体img(z2)の下にあり、img が矩形全体で `pointerdown` を奪うため掴めなかった。**編集中だけ本体を pointer 透過**（`.cat-stage--editing .cat__body { pointer-events: none }`）にして下の `.cat__item` まで pointer を通す。なで（本体タップ）は非編集時のみなので無影響
- **同期**：`pet` 配下で同期。初回マージ規則と、復帰時の上書き対策（#242）は [data-model.md](./data-model.md)

> **設計判断（#226・Antigravity対称レビュー topic_1782737748350 で合意）**: ①装着の「slot排他1点」を置物に流用すると `equipItem`/`spentCoins`/`cleanItemLayout` が汚染されるため **`placedItems` を新設**して装備と完全分離した。②前面/背面の2層を**最初から**用意し `layer` で振り分ける——後から前面層を足すと catMarkup/DOM/dressup を再改修するコストが大きく、背面+前面の2点で z5 までMVPで実証できるため。③座標は新フィールドを作らず `itemLayout` を共用（IDが装着系と重複しない前提でマージ規則の追加が不要）。
>
> **設計判断（実装時の精緻化）**: 合意時は「`.cat` の兄弟としてステージ全面に scene-SVG を張る」案だったが、実装で `.cat-stage` が高さ指定の無い flex で**ステージが非正方（横長）**である一方、dressup の%基準と装着系の描画枠は正方 `.cat` であることが判明。ステージ全面に張ると `preserveAspectRatio` で画像が歪むかドラッグ追従がズレるため、**scene-SVG を正方 `.cat` 内に置き**装着系と同一の viewBox/座標系に乗せた。前後はDOM順＋z-index で表現する。

### きょうのおまけ（#148）

- **練習を記録した日だけ**、その日の**初回記録**（同日に既存記録がないとき）に低確率（`BONUS_CHANCE`＝20%）で猫が `BONUS_COINS`＝3コインのプチ報酬をくれる。当選時は専用ポップアップ（🎁「ねこからの きょうの おまけ！」）
- 「練習しなくても得するログインボーナス」は習慣化と矛盾するため**不採用**。練習行動に連動させる
- 抽選は app.js（`rollDailyBonus`）、付与額は記録の `bonusCoins` に保存され `recomputeState` で復元される（→ [data-model.md](./data-model.md)）。同日2件目以降の統合記録では再抽選しない（1日1回）

### 猫の見た目（なつき度 tier・#167）

猫本体は **スタイル3種 × なつき度3段階(tier) × mood5種 = 45枚**のプリレンダ透過画像（`img/cat/cat_{style}_{tier}_{mood}`）。tier は「なかよしレベル」(#124)から導出する。

| tier | なかよしレベル | 見た目 |
|---|---|---|
| low | Lv1〜2（ともだち／なかよし） | 控えめな表情 |
| mid | Lv3〜7（だいすき〜さいこうのなかま） | リラックス |
| high | Lv8（えいえんのきずな） | デレデレ |

> **設計判断（#167）**: ①旧 SVG 数式描画（kitten/young/adult のレベル連動ステージ）を**廃止**し、見た目の軸を **level → なつき度(affinity tier)** に一本化した（Issue要件「なつき度3段階で表情・ポーズが変化」に忠実。level はレベルバー・XP表示で存続）。②画像形式は当初 **透過PNG統一**（旧 iOS Safari の互換リスクを避け `<picture>` フォールバック不要にするため）→ **#234 で WebP へ移行**（上記 #229/#234 の判断で反転）。③閾値は**新設せず**既存レベルを3 tier に集約して #124 を温存。④衣装・演出は猫本体に焼き込まず別レイヤーで重ねる（#168 きせかえの土台）。ロードは現 tier の4mood先行＋次 tier 境界の2pt手前で `requestIdleCallback` 先読み。

### ストリーク（連続練習）とお休み券

- 前日に練習していれば連続。同日の二重記録はストリークを増やさない
- **お休み券（`streak.freezes`）**：ストリークがちょうど3日、および7日ごと（7・14・21…）に到達したとき +1枚付与（**上限2枚**＝`MAX_FREEZES`）
- 練習に間が空いたとき、抜けた日数ぶんのお休み券があれば消費して連続を維持（救済できなければ1からリセット）。**リセットされてもお休み券は没収されず維持される**
- お休み券で連続を守ったときは専用ポップアップで通知

> **設計判断**: ストリーク報酬は非対称。コインのマイルストーンボーナス（+10/+30）は **3日・7日に到達した瞬間のみ**で14日以降は付かない（インフレ抑制／オンボーディングの前倒し）。一方お休み券は **7日ごと**に供給し続ける（長期の維持モチベーション）。コインは `calcRewards`、お休み券は `isFreezeMilestone` と別ロジック。

## 猫の表示とインタラクション（[cat-image.js](../js/cat-image.js)）

- コンテナ `.cat` に `img.cat__body`＋衣装（`cat__front`・全種前面 #211）＋演出（`cat__fx`：ハート/きらきら/Zzz/なかよしエンブレム）を別レイヤーで重ねる（衣装は #196 で SVG→水彩ラスター、演出は引き続きSVG）
- 演出クラス（`cat--happy` 等）は `.cat` に付き、本体は CSS アニメ（呼吸＝scaleY、跳ね、しっぽふり）、ハート等は fx 内で再生。happy/love/hiss は演出中だけ本体画像を一時差し替える
- **なでなで**（猫タップ）：記録に影響しない安全な操作
  - 反応の種類（約15%で「シャー」＝威嚇、残りは「ニャー」）は `rollCatVoice()` が**音設定に依存せず**抽選する。鳴き声の再生（`playCatVoice`）は別関数で、サウンドOFFなら無音
  - 威嚇でなければ喜ぶ／しっぽふりの反応アニメ（ランダム）。**威嚇のときは喜び演出を出さず `playHiss` が威嚇表情への一時差し替えだけ行う**（#187。抽選を再生から分離しているためミュート中でも出し分けは同じく効く）
  - なかよしレベルが高いと、威嚇でないとき `bondCelebrateChance(level)` の確率で**特別演出**に格上げされる（#124）

## サウンド（[sound.js](../js/sound.js)）

- **効果音（シンセ）**：Web Audio API で生成。コイン獲得 / レベルアップ / 記録完了 / アイテム購入
- **スタンプ音階（#139, #154）**：ハンコは固定SEではなく `playStamp(index)` で鳴らす。ド=C4 を基準に Cメジャー音階で音程が上がり、目標マスは **Cメジャー主和音** で解決する。周波数は平均律で計算（`stampSemitone`/`stampFrequency`、追加アセット0）、和音は `stampNotes(index)` が組み立てる（主音＝高いドに長三度・完全五度・1oct下ボディを重ねる）
  > **設計判断**: issue #139 の実装例は半音上昇（`2^(index/12)`）だが、それでは「ドレミの音程感覚を養う」狙いが満たせないためダイアトニック（メジャー音階）を採用。目標マスは当初 単音の高いドで解決させていたが、半音オフセット列が index8→9 で 14→12 と逆行し、最も興奮する最終タップでピッチが下がる違和感があった（Antigravity 対称レビュー topic_1780484001568 で指摘）。**主和音化**で「豪華なごほうび演出」へ昇華させ違和感を解消（#154）。pure 層（`stampSemitone`/`stampFrequency`）は主音=高いドのまま維持し、和音合成は再生側に閉じて責務分離を保つ。
- **鳴き声（録音サンプル）**：なでた時のみ。`meow1〜3.mp3`（通常）/ `hiss1.mp3`（威嚇）
- ヘッダーのトグルでON/OFF（設定は端末ローカル `settings.soundOn`）。AudioContext はユーザー操作後に解錠（自動再生ポリシー対策）
- **省電力・自動 suspend（#146）**：効果音が鳴り終わってアイドルが続いたら（`IDLE_SUSPEND_MS`）AudioContext を `suspend()` し、音声ハードウェアを起こしっぱなしにしない。タブ非アクティブ時も `suspendAudio()`、復帰時に `resumeAudio()`。次の再生で `getCtx()` が `resume()` するため状態は失わず体感遅延もない

## アクセシビリティ・表示テーマ（#151）

- **prefers-reduced-motion 対応**：OSの「視差効果を減らす」設定時、猫の呼吸/ジャンプ/ハート等の演出（[cat.css](../css/cat.css)）に加え、スタンプの登場・オンボーディングのポップ・各種バーの伸び（[style.css](../css/style.css)）も停止する。ご褒美フィードバック（ハート/きらきら）は静止表示で残す。CSSのみで完結、JS不要
- **ダークモード（夜の練習配慮）**：構造色を `:root` のセマンティック変数（`--surface`/`--surface-soft`/`--surface-mute`/`--pink-soft`/`--cream`/`--ink`/`--shadow`/`--text-muted`）に集約し、ダーク時はこの変数群だけを上書きする。ピンク/ゴールド等のアクセント色は両モード共通
  - **切替**：せってい（親ゲート内）の「がめんの あかるさ」で **じどう / あかるい / よる** の3択。`じどう` は `@media (prefers-color-scheme: dark)` でOS設定に追従（`data-theme` 属性なし）、他は `data-theme="light"/"dark"` で明示固定
  - **保存**：テーマは端末ごとの好みなのでクラウド同期せず `localStorage['pp-theme']`（`settings.soundOn` と同じ端末ローカル方針）
  - **チラつき防止**：`index.html` の `<head>` インラインスクリプトで保存値を描画前に `data-theme` へ適用。`auto` は属性を付けずCSSのメディアクエリに委ねる
  > **設計判断**: 既存CSSは `#fff` 等のリテラル色が散在していたため、ダーク化はセマンティック変数への置換で実現。ライトでは各変数を従来リテラルと同値に定義し見た目を完全維持（差分は無リスク）。`auto` で属性を外す方式により、JSでの `matchMedia` 監視なしにOSのライト/ダーク切替へ即時追従できる。

## せってい（親ゲートの内側）

ホーム ⚙️ →「おうちのひとへ」オーバーレイ。子の誤操作を防ぐため、まず簡単な掛け算（1桁×1桁の九九・`makeGateProblem`）の**ペアレンタルゲート**を出し、正解時のみメニューを開く（足し算だと子に突破されやすいため九九に変更・#166）。専用ナビ画面は増やさず、以下のセクションを1つのオーバーレイに置く。

| セクション | 操作 |
|---|---|
| アカウント（#182） | 有効アカウントと一覧を表示（有効は「いま これ ✓」、他は「きりかえる」）。切替は `setActiveAccount(id)` → リロード |
| きょうの もくひょう（#238） | 1日の目標回数を 5〜20 で調整 |
| がめんの あかるさ（#151） | じどう / あかるい / よる |
| クラウドの ばしょ（#233） | 「🔒 あんぜんな ばしょに うつす」／他端末は「🔗 この コードに つなぐ」／全端末合流後に「🧹 ふるい ばしょを からにする」（確認ダイアログ付き） |
| データを ほぞん（#140） | 現行 state をラップ JSON 化して `piano-pet-backup-YYYY-MM-DD.json` をダウンロード。無害なので確認なし |
| データを よみこむ（#140） | ファイル選択 → `parseBackup()` で検証 → 上書き確認 → 復元。検証 NG はひらがなで理由表示（壊れ/別アプリ/必須キー欠落/未来バージョン） |
