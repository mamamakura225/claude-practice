## 画面とナビゲーション

ハッシュベースのSPA（[router.js](../js/router.js) / [app.js](../js/app.js) `render`）。

- ボトムナビ4タブ：**ホーム / きろく / ショップ / バッジ**
- 記録入力（record）はナビに出さず、ホームの「れんしゅうを きろくする」から開く（ナビ上はホームを選択状態に保つ）

- **アプリアイコンのショートカット（#235）**：`manifest.json` の `shortcuts` に1件登録し `./index.html#/record` へ直行。アイコンは `icons/icon-96.png`

> **設計判断（#235）**: router の改修は不要。起動時の `router.syncFromHash()` → `viewFromHash('#/record')` が `record` を返すので、ディープリンクは既存実装で成立する。追加は manifest と 96px アイコンのみで、専用アートは起こさず `icon.svg` から生成。**iOS/iPadOS は `shortcuts` 非対応**のため短縮は Android/デスクトップ限定（iOS は1タップ多いだけで機能欠落ではない）。

### こどものアバター（#121）

home / きろく の両ヘッダに `renderChildAvatar` が `.child-avatar` を一括更新。「自分が主役」の自己効力感を与えつつ、本番アカウントとテスト用の見分けも兼ねる。

- **タップで選択**：`#avatarOverlay` が開く。こども本人の操作なので**親ゲートなし**。絵文字10種（🐥🐰🐻🐼🦊🐸⭐🌸🦄👑・[child-profile.js](../js/child-profile.js) `CHILD_AVATARS`）＋なまえ（最大12文字）
- **顔写真は不採用**：認証なしの共有 Firestore に置くためプライバシー上不可。絵文字なら軽量・同期可・PII を増やさない
- 名前は入力中もヘッダに即反映、閉じるときに前後空白を落として確定。analytics には送らない（PII規約）。保存先は [data-model.md](./data-model.md) の `pet.childName` / `pet.childAvatar`

### 猫のmood

恒常表示は idle/sleep、happy/love/hiss は演出中の一時差し替え。

| mood | 条件 | 表現 |
|---|---|---|
| `idle` | 通常 | ゆっくり呼吸（scaleY） |
| `happy` | 記録直後 | うれしい表情＋ぴょんと跳ねる・ハート |
| `sleep` | 最後の練習から2日以上 | 目を閉じた表情＋Zzz |
| `love` | なでた時 | だいすき（ハート目）＋しっぽふり／喜ぶ |
| `hiss` | なで反応で威嚇を抽選（#187） | 威嚇表情のみ。喜び演出は出さない |

## 初回オンボーディング（#141）

初回起動時、猫の**吹き出し3画面の紙芝居**で「①きろく → ②ごほうび → ③きせかえ・ごはん」を案内する。実装は [onboarding.js](../js/onboarding.js)（データ＋フラグ）と [app.js](../js/app.js)（DOM）。

- **新規アセットなし**。既存の `catMarkup` をカードに流用
- ひらがな主体・大ボタン（スキップ／つぎへ・はじめる！）＋進捗ドット3つ
- **スキップ可**。どちらで閉じても `piano-pet-onboarded='1'` を立てて以後は出さない
- localStorage が読めない環境（プライベートモード等）は「見た」扱い＝うるさく出すより無害側へ倒す

## 練習記録入力（2モード：スタンプ / まとめて）

日付の下に「🐾 スタンプ / 📝 まとめて」の切替タブ。既定はスタンプ。実装は [record-form.js](../js/record-form.js)（純粋ロジック）と [app.js](../js/app.js)。日付は両モード共通で既定は今日。モード切替時は入力途中の内容を「曲×回数」として相互変換し引き継ぐ（`stampsToSongs` / `collectSongs` / `songsToStamps`）。

### スタンプモード（親=曲えらび／子=スタンプ・#117）

タイル状の「ハンコ」を押して回数を数える、子供にも押せるUI（役割ガイドの文言は #189 で削除）。

- **きょくを えらぶ**：曲名チップを「最近ひいた順（最終練習日）→累計回数」で最大8件（`pastSongNames`・#252）。**練習する曲は移り変わるため累計順ではなく直近順**にして、いま練習中の曲を必ず載せる。漏れた曲は新規入力欄の `datalist`（過去の全曲名）から選べる。各チップに曲の色スウォッチ、選択中は全体がその色（#122）
- **ハンコを おす！**：タップで選択中の曲の🐾が1つ増える。マス数は目標ぶん（既定10・親が5〜20で調整 #238）＋超過時も常に1マス余分。「↩ ひとつ もどす」で直前を取消。**押したマスは押下時の曲の色で塗る**
- **当日中はカードを引き継ぐ（#164/#186）**：スタンプは下書きキーに一時キャッシュされ、ホーム往復でも0に戻らない（打鍵ごとの Firestore 同期はしない）。**記録確定後も当日なら引き継ぐ**＝当日セッションからスタンプを復元（`songsToStamps(combineSongs(...))`）して続きを押せる。日付が変われば下書きは破棄（→ [data-model.md](./data-model.md) の `stamp-draft`）

**当日の記録画面は「その日ぜんぶ」を表す（#186）**：全内容を復元しているため、submit は追記ではなく**置き換え**（`isToday` 分岐）。当日の押し増しが二重計上されず、同日同曲が1レコードに収まる。日付欄を過去日にした場合のみ合算。

**日付を変えたらフォームを入れ直す（#273）**：ひづけ欄が変わると、その日付が本来始まるべき内容へ戻す（`onRecordDateChange`）。**今日**＝当日セッション／下書きから復元、**今日以外**＝空のカードから。過去日を選んでいる間は当日の下書きも書き換えない。

> **設計判断（#273）**: #186 の復元と「過去日は合算」の分岐は、日付欄が変わらない前提で噛み合っていた。復元済みの当日ぶんを持ったまま過去日にすると**もう一度計上される**（実測：今日5かい → 日付をおとといへ → セッション 5+5 の2件・コイン/XP とも 10）。後追い入力の導線は本来まとめモード（常に空）だが、スタンプモードのままでも操作できてしまうため、モードではなく**日付の変化**を起点に作り直す方へ倒した。

**同日同曲の合算表示（#186）**：きろくタブは `combineSongs` で同名の曲を1行に合算（既存の分割データも表示時に合算）。`mergeSameDaySessions` も統合時に `combineSongs` する。

#### 曲の色（決定的ハッシュ＋衝突回避・#122/#165）

[song-color.js](../js/song-color.js) が曲名を FNV-1a ハッシュして色相（0〜359）を取り、彩度・明度は固定（`songColor` が `fill`/`tint`/`ink` を返す）。**保存しない**ので `sessions` さえ同じならどの端末でも同じ色。空名は無彩色グレー、前後空白は無視。

- **色かぶり回避（#165）**：`assignSongColors(names)` が曲名リストを先頭から走査し、既出の色相に近すぎる（**最小ギャップ 25°未満**）曲を隣の色へずらす。並びは `songTotals` 順で決定的。スタンプ／チップ／コレクションは同一マップ（`buildSongColors`）を基準にする
- **端末間で一致しない例外**：記録画面の `formSongColors()` だけは端末ローカルの `chipNames`（未保存の新規曲名）を末尾に足す。**未保存の曲が並びに混ざっている間は、ずらし方が端末ごとに変わりうる**。記録が確定して `sessions` に載れば一致する。保存フィールドを持たない方針（#122）を崩さないための許容範囲

#### スタンプ音（#139 / #154 / #238）

押すたびに音程が**ドレミ…と上がり**（1マス目＝ド）、目標マスは **Cメジャー主和音（ド・ミ・ソ）**で解決＋レベルアップ音。途中マスは目標数に応じて1オクターブ内へ再配分。**目標を超えても主和音のまま**（`stampSemitone` は `index >= goal-1` を一律で解決音扱い）＝「目標より先はぜんぶごほうび」。

> **設計判断（#238・1日の目標回数を可変に `pet.dailyGoal`）**
> - **保存先＝同期される `pet` 配下**：進捗リング・達成演出・マス数/音程は全端末で一貫すべき。端末ローカルの `settings` ではなく `pet` に置く（`childName`/`catStyle` と同じ扱いでマージ規則の追加不要）
> - **達成ボーナスは閾値10で固定**（`GOAL_BONUS_THRESHOLD`）：`recomputeState` は全履歴に `calcRewards` を再適用するため、報酬を可変目標に連動させると**過去の記録のコインまで遡って増減**する（下げれば水増し・上げれば娘のコインが減る）。表示上の目標だけ可変にする
> - **音程のマス可変対応**：旧実装は `12*floor(i/7)` でオクターブを無制限に積み上げ、goal=20 では +31 半音まで甲高くなっていた。分母 `(goal-1)` で 0..6 のダイアトニック度へ正規化し1オクターブ内に収める。goal=8 のとき途中がちょうど ド〜シ に一致

### まとめモード（親の後追い入力・#123）

その場でスタンプを押さなかった日を、親が後からまとめて記録するための入力。

- 1行＝曲名（`datalist` で過去曲を補完）＋回数ステッパー（− / 数値 / ＋）。「＋ ぎょうを ふやす」で追加、各行の「✕」で削除
- 「ごうけい ○ かい」をライブ表示。集約は `collectSongs`（空名・0以下は除外）

### 記録の確定（両モード共通）

合計0回は記録不可（`isValidSession`）。スタンプモードで曲未選択ならヒント表示。確定後の動作：

1. コイン・XP・ストリーク・バッジを計算して反映（`applySession`）
2. ホームへ遷移し猫が喜ぶ。**目標にはじめて届いた記録は短尺動画クリップ**（→ 下記 #227）、節目（レベルアップ／新バッジ／連続日数の節目）は `playCelebrate`、通常はランダムな `playHappy`（or 確率で動画）。`celebrateRecord` が出し分ける（#81・#227）
3. 獲得コインのポップアップ（レベルアップ時はその旨も）
4. 効果音：記録完了 →（レベルアップ時）レベルアップ
5. お休み券で連続を守れば専用ポップアップ、新規バッジがあればバッジポップアップ（複数は順番に）

同日・過去日の扱い：

- **同日に既存記録があれば統合して全再計算**（`recomputeState`。目標達成ボーナスの二重取りを防ぐ）
- **過去日（最終練習日より前）の新規記録も全再計算経路**（#260）。`applySession`→`updateStreak` は日付が時系列順で届く前提の逐次更新で、過去日をそのまま流すとストリークが1に巻き戻り `lastPracticeDate` も過去へ戻る。挿入＋`recomputeState`（日付昇順の再生）で連続日数を保つ。後追い入力では「きょうのおまけ」を抽選しない（`bonusCoins: 0`）
- **未来日は選べない**（`max=今日`。手入力で入っても submit 時に今日へ丸める）

> **設計判断（#260）**: 新規汚染の防止のみで、旧バグで巻き戻った既存データの自動修復はしない（起動時 recompute は同日重複マージ時だけ）。クラウド初回 reconcile か次回の記録・編集・削除で自己修復される。

### 記録の動画クリップ演出（#227）

練習記録のあと、猫の上に**短尺動画**（720×720・1:1・muted・素材は約4秒）を重ねて再生する。「次は何が出るかな」というごほうび感を日常動作に少しずつ差し込むのが狙い。#296 で**2回ループ（視聴 約8秒）**にし、出現確率も引き上げた（下記）。実装は [cat-video.js](../js/cat-video.js)（再生ロジック）＋ [app.js](../js/app.js) `celebrateRecord`。

素材は**猫スタイル3色 × 3本 = 9本**（#300）。動作は3色で共通で、`record_v1` = ぴょんと跳ねて両前足でバンザイ＋水彩のハートが浮かぶ／`record_v2` = くるっと体をひねって回る／`record_v3` = おしりとしっぽを高く上げて大きくのびをする。どれも中立の座りポーズで始まって同じポーズで終わるので、クリップが畳まれた瞬間に元の静止画へ自然に戻る。

> **設計判断（#296・頻度↑・尺↑）**: 本番投入後に5歳の実利用者へ触らせたところ「かわいいのでもっと見たい」「短くて見逃す」との反応。#227 の方針（まれな節目演出ではなく日常にちょこちょこ差し込む）の範囲内の再チューニングとして、(1) `recordClipChance` のラダーを 12/20/30/40% → 25/40/55/70% へ、(2) 視聴尺を1周（約4秒）→2周（約8秒）へ広げた。節目でのクリップ非表示（`playCelebrate` 温存）は #227 の判断どおり維持。`video.loop` は使わず明示的に1回だけ巻き戻す——`loop=true` だと `ended` が発火せず、クリップの終了検知・世代管理（`_clipGen`）・張り替え時の `teardown` がすべて崩れるため。

> **設計判断（#300・1スタイル1本→3本）**: #296 で出現確率を 70% まで上げた結果、同じ映像を何度も見ることになりごほうび感が薄れた。追加する2本は色や小物ではなく**シルエットの動く軸**で選んでいる——v1=縦（跳ねる）／v2=回転（ひねる）／v3=前後（のびる）。5歳が小画面で一目で「ちがうのが出た」と分かるのはこの軸の違いで、「浮かぶ小物を変える」程度では同じ枠に見えてしまうため、水彩の音符を浮かべる案は採らなかった。**動作は3スタイル共通**にした（同じごほうびだと伝えるため。1動作＝3本セット）。
>
> **目標達成と通常記録は共通プールのまま**にした。別プールにすると「必ず再生」の枠に一番良い動作を割り当てられるが、専用素材が更に3本必要でリポジトリ重量も生成コストも倍になる。3本あれば「次は何が出るか」は満たせるので、分けるのは将来レア枠（例：蝶が飛んできて鼻先にとまる）を作るときとする。
>
> **prefetch を全部から1本へ**絞った。1スタイル1本の頃は全部取っても1本だったが、3本になると idle で 3本ぶんを取りに行ってしまう。`peekClip` でバッグの先頭だけ覗いて取る形にして、先読みと実再生が必ず同じ1本を指すようにした。この都合で `pickClip` は純関数でなくなり**バッグを消費する**——再生に失敗してもクリップは消費したままにする。巻き戻すと先読み済みの1本と次の再生がズレる方が害が大きい。

| 発火条件 | 挙動 |
|---|---|
| その記録で**今日の目標にはじめて届いた**（`crossedDailyGoal`） | 確率を飛ばして**必ず**再生。達成後の追加記録では確率へ戻る（同じ日に何度も出さない） |
| 節目（レベルアップ／新バッジ／連続日数） | 動画は出さず既存 `playCelebrate` を温存 |
| それ以外の通常記録 | `recordClipChance(なかよしLv)` の確率で再生（Lv1–3: 25% / Lv4–5: 40% / Lv6–7: 55% / Lv8: 70%・#296 で引き上げ）。なでなで（`bondCelebrateChance`）と違い Lv1 から出るのは、記録が1日数回しかなく始めたばかりの子が一度も見られないのを避けるため |

- **フォールバック**: 動画が未ロード／再生失敗（自動再生拒否・1000ms 以内に `playing` が来ない）／`prefers-reduced-motion` のときは既存のCSS演出（`playCelebrate` / `playHappy`）に落ちる。「必ず」を約束したのは目標達成の側で、出せなければ `playCelebrate`
- **2回ループ（#296）**: 1回目の終わりで頭へ巻き戻してもう一度再生し、2周目の終わりで畳む。通常は `ended` が駆動し、`ended` 不着の端末では尺経過タイマー（`duration + 0.4s`）が巻き戻す。最終保険は `duration * 2 + 1s` で `release`
- **タップでスキップ**: オーバーレイをタップで即フェード除去（ループ途中でも）。動画中に再度記録した場合は前のクリップを畳んで次を再生する（前のクリップのタイマーが次を殺さないよう `teardown` で片付ける）
- **ポップアップとの重なり**: 記録後のコイン／おまけ／お休み券／バッジのポップアップ（すべて `.coin-popup`・全画面暗幕・z-index 50）は、クリップ再生中は `body.cat-clip-playing` でクリップの後ろへ回す（暗幕も透明化）。クリップが主役で、コイン総額はホームのカードに即反映されるので情報は失われない。**既知の重なり**（#296 でクリップが約8秒に伸びた副作用）: 目標達成と同時に新バッジを獲得した記録では、バッジ告知（`showBadgePopup`・1件 2.2秒）がクリップの裏に入ることがある。`playSound('levelup')` は鳴り、バッジはホームで確認できるので取りこぼしではない。頻度が低いので現状は許容（直すなら告知をクリップ解放後へ繋ぐ）
- **クリップの選び方（#300）**: `pickClip` は **bag shuffle**。そのスタイルの3本を混ぜた「バッグ」から1本ずつ配り、空になったら詰め直す。バッグ内は全部がちょうど1回ずつ出るので連続重複は起きず、漏れるのはバッグの境目だけなので、詰め直した先頭が直前と同じなら末尾と入れ替えて潰す。`rng` は引数で注入できる（テスト用）
- **読み込みタイミング**: `cat-video.js` は**記録ビューに入ったとき** `requestIdleCallback` で動的 import＋**次に出る1本だけ**を prefetch（#284 の js-lazy 側）。外れても毎回モジュールを読まない／記録の瞬間に慌てて読まない、の両立。先読みを1本に絞るのは、9本すべてを idle 取得すると 1.4 MB を先に食うため。`peekClip` がバッグの先頭を消費せず覗くので、先読みした1本がそのまま次に再生される。1本再生されるとバッグが進み、次に記録ビューへ入ったときの `prime` が新しい先頭を取りに行く
- **音は常に muted**。効果音は既存 `sound.js` に任せる（ON/OFF の二重管理を避ける）

> **設計判断（DOM 配置）**: `<video>` オーバーレイ（`#catVideo`）は `#catStage` の**外**（`.cat-stage-wrap` 直下）に置く。`renderHome` は `#catStage` を `innerHTML` ごと差し替えるため（クラウド `onSnapshot` でも走る）、中に置くと再生中に他端末が保存すると動画が消える。`.cat` とサイズ指定（`width:80% / max-width:min(320px,90vw) / aspect-ratio:1/1`）を共有し、`.cat-stage` の `align-items:flex-end` + `bottom:0` で猫にピクセル一致させる。

> **設計判断（ダークモード）**: 動画は不透明（背景 `#FCF2EC`）で夜モードでは明るい四角が浮くが、**角丸＋影の「絵本のページ」**として意図的に見せる。透過動画（VP9 alpha / HEVC alpha）は Chrome と iOS Safari で形式が割れ2ファイル必要になるため不採用。実機で違和感が出たら再検討。

> **設計判断（配信方式）**: 動画は `apps/piano-pet/video/cat_<style>_record_v1.mp4` に**リポジトリ同梱**し Vercel の静的配信（rewrite `/piano-pet/(.*)`）で配る。当初案の Firebase Storage 外部配信は不採用——(1) 計測（perf-budget）とプリキャッシュ（gen-sw）の列挙は [piano-pet-assets.mjs](../../../scripts/piano-pet-assets.mjs) の明示リスト（`css/ js/ icons/ img/cat* sounds/`）だけで、新設の `video/` はどちらにも載らないので「同梱すると SW が太る」前提が事実と違った。(2) Storage は Blaze 課金＋セキュリティルールの版管理課題（#266）を1つ増やす。`img/` に既に 3.6 MiB のバイナリがある以上、同梱は方針と矛盾しない。**再検討条件**: クリップが十数本を超えて git が重くなったら Storage へ移す。差し替え時はファイル名を `_v2` に（同名上書きだと取得済み端末が古い動画を再生し続ける）。

> **今回入れないもの**: bag shuffle（1スタイル1本では無意味・2本以上で `pickClip` に足す）／クリップ図鑑（視聴済みフラグは `storage.js`／クラウド同期／`recomputeState` に波及するため別issue）／えさやりへの展開（#294）。

> 既存ユーザーのコインは `spentCoins` が支払額でなく**現行価格から毎回導出**されるため、次の `recomputeState` で `coins = 獲得総額 − 現行価格の購入総額 − foodSpent` に再導出され**差額が自動返金**される。「コインは sessions から導出される」という既存の不変条件そのままの帰結なので、購入価格を記録する新フィールドもマイグレーションも設けない。えさ（`foodSpent`）は消費済みなので返金しない＝**装備＝資産・えさ＝消費**の非対称は維持。
>
> **⚠️ 価格の変更は値下げ方向のみ**: 同じ仕組みが値上げでは逆に働き、**既存ユーザーのコインを黙って減らす**（極端には `Math.max(0, ...)` で 0）。娘が貯めたコインが理由もなく減るのは容認できないため `SHOP_ITEMS` / `FOODS` の `price` を**引き上げてはならない**。必要なら支払額を記録するフィールドとマイグレーション（→ [data-model.md](./data-model.md)）をセットで行う。
>
> **受容した過渡期リスク（複数端末×バージョン差でのコイン振動）**
> - デプロイ直後に旧価格JSと新価格JSの端末が混在すると `spentCoins` が端末ごとに異なり coins が振動する。realtime の `mergeCloud` は cloud-wins で受信値を採り、起動・復帰時の `reconcileInitialCloud`/`resyncFromCloud` は現行価格で再導出するため交互に push し合うため
> - ただし **sessions・inventory（唯一の正）は無傷でデータ消失なし**、**両端末が新JSになれば恒久収束**する
> - 購入価格を state に固定する対案（`spentCoinsTotal`）は不採用。旧価格を知らない新JS側で移行基準値を作れず、旧JS push での欠落も自己修復しない＝**自己修復する一過性の問題を、自己修復しない恒久リスクへ置き換える**ことになる
> - 運用上は各端末で一度アプリを開けば終わる（bridge-chat topic_1784289217445 で合意）

> **設計判断（#126・解放ゲート）**: 解放判定は購入時（`canBuy`）だけが参照する。装備・描画は現在Lvを見ず inventory/equippedItems の所属だけで判定するため、affinity 低下で再ロックされても**所持品は外れず・消えず・装備継続**（全再計算でも不変）。既存ユーザーは現在の affinity から相応に解放済みで始まるためマイグレーション不要。

> **設計判断（#229＋#234・高解像度化とWebP化を同時実施）**

> - PNG のままだとプリキャッシュ・初回DLが線形に増える（box×3 で ~5.2 MiB）ため、**同一ブランチで PNG→WebP 化**（href 拡張子と `gen-sw.mjs` の収集拡張子を `.webp` に、全61枚を quality85 で変換）
> - 結果 **4.82 MiB → 3.60 MiB**。解像度を上げつつ約25%削減
> - WebP は iOS Safari 14+（2020〜）対応で 2026 時点の旧版シェアが実質消滅のため `<picture>` フォールバックは設けない（#167 の PNG統一判断を反転）。全61枚のデコードを実測確認。演出・グラフSVGは対象外

> **設計判断（#210 拡充 / #213 装着感 / #241 環状アイテム）**
> - **#210**：手薄だった face / back を中心に4点追加（`beret`/head・`sunglasses`/face・`bell`/neck・`wings`/back）。新規スロット・置物系は導入せず既存パイプラインを流用＝最小構成。差別化として `sunglasses` はレンズ色付き（めがね＝透明と区別）、`bell` は鈴チャーム（星の首輪と区別）
> - **#213**：5点（`bowtie`/`ribbon`/`scarf`/`flowerCrown`/`glasses`）が「平置きの商品写真」調で猫に浮いて見えたため、アンカー原点基準の装着構図へ再作画。neck系は y0 に巻き帯→真下に蝶結び、`scarf` は上端の輪を y0・フリンジを y>0 に垂らすU字、`flowerCrown` は y0 を頭頂とする環状（box を 96×40→96×48 に拡張）、`glasses`（#212 を統合）はブリッジ(0,0)中心で左右対称・正面向き・レンズ透明。**テンプル（つる）は描かない**（丸まった耳掛けがフレーム欠けに見えた）。**アイテム画像は衣装単体で猫の顔・チャームを描き込まない**（重ねると二重に見える）
> - **#241**：`collar`/`bell`/`flowerCrown` は本来一周する輪だが、#211 で全アイテムを前面へ回した結果**背面の帯まで猫の手前に出て不自然**だった。背面帯を別レイヤーに描く案は本体画像が不透明で隠れる（#211 の断念理由）ため不採用。対応は**アート差し替えのみ**＝「前面から見える弧だけ」に再作画。`ITEM_BOX` 据え置きでコードは無改修

### きせかえ 自由配置（ドラッグ・#168／ピンチ拡縮・#205）

ホームの「👗 きせかえ」で編集モードに入ると、装備中の衣装を**1本指ドラッグで移動・2本指ピンチで拡縮**できる。実装は [dressup.js](../js/dressup.js)（pointer追跡）＋ [cat-image.js](../js/cat-image.js) `itemsSvg`/`itemAnchorPct`/`itemAnchorScale`。

- **配置データ**：`pet.itemLayout`（.catコンテナ基準の%・ビューポート非依存）。`pet` 内なので Firestore へ自動同期。`shop.js` の装備ロジックは無改修
- **フォールバック二段構え**：座標が無い衣装は既定アンカー・基準スケール（`a.s`）で描き、初操作で記録する
- **位置スナップは廃止（#214）**：ドロップ座標をそのまま記録。範囲外はステージ内に clamp、スロット跨ぎはしない。旧データはフォールバックで従来どおり描画（マイグレ不要）
- **ピンチ拡縮（#205）**：2本指の距離比で `scale` を更新し**絶対値**で `0.3〜3.0` に clamp。基準スケール `a.s` の ±5% 以内で `a.s` へ吸着。2指間距離が **10px** 動くまで拡縮を始めない（誤操作防止のデッドゾーン）。ピンチ中は位置固定
- **最小タッチ領域（#215）**：`<g scale>` で縮むとヒット領域も縮むため、各 `<g>` に透明ヒット矩形（`.cat__item-hit`）を**逆スケール**で内包（`width=max(box, MIN_HIT_UNITS(44)/scale)`）。scale 適用後の画面サイズが常に約66px以上になる。見た目は不変
- **なで競合の回避**：編集モード中は `petCat` を無効化し猫の周囲を点線で囲う。「✅ できた！」で抜ける
- **スクロール追従（#288）**：ドラッグ中の座標変換はステージ矩形を `pointermove` ごとに `getBoundingClientRect()` で取り直す。掴み時にキャッシュするとドラッグ中のページスクロールでドロップ位置がずれる（ホームは縦長）
- **ゴーストデータ掃除**：`commitState` の `cleanItemLayout` が装備していない衣装の座標を除く

> **設計判断（#168）**: 配置座標は `equippedItems`(id配列) に埋め込まず**別フィールド `pet.itemLayout`** に分離。`shop.js`/`equipItem` 系のロジックとテストを温存し状態遷移へのバグ混入を避けるため。
>
> **設計判断（#205・topic_1782030433684 で合意）**
> - `scale` は**乗数でなく絶対値**で保存。乗数（`a.s × k`）だと将来アセット更新で `a.s` を調整したときに配置済み衣装のサイズまで変わる。絶対値ならユーザーの意図が守られ `pos?.scale ?? a.s` で完全後方互換
> - 定位置に戻しても実座標は焼き込まず `{scale}` のみ保持し、位置は描画時にアンカーから引く
> - 5歳児UXの補助は**基準スケール吸着とピンチ開始デッドゾーンの2点のみ**。clamp で上下限は安全に頭打ちになるので、枠線の状態別色分けは最小構成のため見送り
>
> **設計判断（#214・topic_1782394334271 で合意）**: 位置スナップを**廃止**。「思った位置に置けず勝手に戻る」が操作ミスのように感じられ自由配置の意図に反するため。**サイズの基準スケール吸着（#205）は別物**（行き過ぎた拡縮を綺麗なサイズへ戻す補助）なので温存。
>
> **設計判断（#215・同 topic）**: ヒット領域確保は JS の最近傍探索でなく**マークアップ側の逆スケール透明矩形**で行う。①ブラウザ標準のポインタイベントとSVGの描画順（DOM順＝上層優先）にそのまま乗れて重なり時の挙動が素直、②位置・サイズを別途同期して距離計算するコードが不要で `cat-image.js` 内に閉じ込められる。`MIN_HIT_UNITS=44` は実機で調整可能な単一定数。
>
> **設計判断（#211・同 topic）**: cape を背面レイヤーから**前面へ移し** `cat__back` SVG 自体を撤去。背面だと不透明な本体画像に完全に隠れて「見えない・掴めない」ため。代替案（背面のまま端だけ覗かせ＋本体 `pointer-events:none`）は可視性を解決できず、なで反応にも影響するため不採用。cape の**アンカー種別（`back`）は不変**で変わるのは描画レイヤーのみ。

### まえ／うしろの切り替え（#270）

編集モード中だけ猫の下に**まえ／うしろパネル**（`#layerPanel`）が出る。装着中＋配置中のアイテムが2段に並び、チップをタップすると反対の段へ移り猫の描画も同時に入れ替わる。実装は [app.js](../js/app.js) `renderLayerPanel` ＋ [cat-image.js](../js/cat-image.js) `itemLayer`。

- **データ**：`pet.itemLayout[id].layer`（`'front'|'back'`）。**未設定・未知値は既定へ**（装着＝前面 #211 ／ 置物＝`SCENE_BOX[id].layer`）＝既存ユーザーの見た目は不変・マイグレ不要
- **描画**：`catMarkup` が実効レイヤーで振り分ける。うしろにしたものは装着・置物とも既存の背面SVG `cat__scene--back`(z1) へ（置物→装着の順＝背面同士では装着が猫寄り）、まえは装着 `cat__front`(z3) / 置物 `cat__scene--front`(z5)。**層は増やさない**
- **編集中は本体を半透明**（`opacity:.55`）にして、うしろへ送ったアイテムを透かして見せる。#240 の pointer 透過と合わせ、背面のままドラッグ・ピンチで調整できる
- **写真（#237）は無改修**で追随（DOM の z 順をそのまま読むため）
- **ドラッグとの両立**：dressup はドロップ時に `itemLayout[id]` を作り直すため `layer` だけ明示的に引き継ぐ
- **背面内の重なり順**：前面と同じ「cape が最下層 → neck/head/face」。1回のフィルタでまとめると `equippedItems` の並び（装備した順）に依存して見た目が変わるため2回に分けて描く
- **外すと既定に戻る**：`cleanItemLayout` がエントリごと落とすため `layer` も既定へ（座標・スケールと同じ扱い）

> **設計判断（#270）**
> - UIは**ジェスチャでなく一覧パネル**。ダブルタップ／長押しはドラッグ（#168）・ピンチ（#205）と競合し、幼児の誤操作が「アイテムが猫の裏に回って消えた・戻せない」に直結する。パネルは常に全アイテムを列挙するので**必ず戻せる**
> - タップ選択して反転ボタンを出す案は direct manipulation で自然だが、tap/drag の判別と再描画をまたぐ選択状態の復元が必要で dressup.js の改修が大きく、操作性の差に見合わない
> - 状態は新フィールドを作らず `itemLayout` の1キーに載せた（`cleanItemLayout` の掃除・同期・union マージ #242 をそのまま流用できる）
> - 背面の描画先も**新レイヤーを足さず** `cat__scene--back` を共用（層を増やすと catMarkup・CSS・写真合成の3箇所を再改修することになる）

### 写真モード（#237）

ホームの「📷 しゃしん」で飾った猫を**1枚の画像**にして共有／保存できる。きせかえ遊びに「見せたい・残したい」出口を作り、祖父母への共有動線にもなる。実装は [cat-snapshot.js](../js/cat-snapshot.js)（canvas 合成）と [app.js](../js/app.js) `shareCatPhoto`。

- **合成**：`renderCatCanvas(catEl, 600)` が 600×600 canvas に画面と同じ z 順（背面 z1 → 本体 z2 → 前面装備 z3 → 前面置物 z5）で描く。うしろへ回したアイテム（#270）もそのまま反映。**演出SVG（`cat__fx`）は初期スコープ外**
- **共有/保存**：`navigator.canShare({files})` が使えれば Web Share、非対応なら `a[download]` へフォールバック。**端末内完結・サーバ不要**
- **PII**：共有ペイロードに曲名・こども名を含めない。タイトルは固定「ピアノペット」、ファイル名も固定 `pianopet.png`、`text` は付けない。計測は操作フラグのみ（`cat_photo_shared` / `cat_photo_saved`）
- **背景**：透過のまま共有すると環境により黒背景になるため、クリーム色（`#fff6ee`）で塗ってから合成する

> **設計判断（#237）**
> - レイアウト数式（ANCHORS/ITEM_BOX/SCENE_BOX＋`itemLayout`）を**再実装せず**、描画済み DOM の `<g transform>` と `<image>` の box を読み取って canvas に落とす。数式を二重管理すると #168/#205 や box 変更のたびに画面と写真がズレるので「画面の DOM が唯一の真実」にする
> - 画像は同一オリジンなので canvas が汚染されず `toBlob` が使える
> - SVG を丸ごと data URL 化する案は不採用。`<image>` の外部参照が「画像として読み込んだ SVG」ではブロックされる

### 猫スタイル切り替え（#66）

編集モード中だけ**スタイルピッカー**（`#stylePicker`）が出る。ちゃとら／しろ／ぐれー（ロシアンブルー）の3種を `pet.catStyle` に保存して同期。未定義は 'tora' フォールバック。

- サムネイルは本番の `cat_{style}_low_idle` をそのまま使う。**ピッカーを開いた時点で各 idle が自動ロードされる**ため切替時のチラつきがない
- 切替は `commitState` → `renderHome` が本体画像・preload を引き直す
- スタイル別の衣装アンカー補正は `STYLE_ANCHOR_OFFSETS`（cat-image.js）

> **設計判断（#66・topic_1781184658026 で合意）**
> - 切替UIは**きせかえ編集モード内**（「見た目を変える」文脈で5歳児が自分で発見できる。ショップ解放は #126 と被るので将来拡張）
> - 命名は既存も含め **`cat_{style}_{tier}_{mood}` に全リネーム**（特例分岐を残さない。SW は gen-sw 再生成で旧キャッシュを自動破棄。茶トラ15枚は中身同一でも一度だけ再DLされるが許容）
> - **JSの preload は選択中スタイルのみ**。SW が `img/cat` 全45枚（~3.8MiB）をプリキャッシュするので、これはネットワークではなく**デコード/メモリの抑制**であり、オフライン中の切替も保証される
> - 立ち耳ロシアンブルーのアンカーずれは、生成側でポーズを揃える（体格バランスが崩れる）のではなく `STYLE_ANCHOR_OFFSETS` で吸収する。納品画像の実測では頭頂が tora/shiro=y31・russianblue=y35 と差4ユニット（ステージ2%）で軽微なため**オフセットは空のまま**

### 置物・小物系 アイテム（シーン配置型・#226）

装着型（猫アンカー基準・slot排他）とは別カテゴリの、**着せずに猫の前後シーンへ置く装飾**。実装は [shop.js](../js/shop.js)（`slot:'scene'`＋配置ロジック）と [cat-image.js](../js/cat-image.js)（`SCENE_BOX`／前後2層）。MVPは2点：🧶 けいとだま（前面）・🛋️ クッション（背面）。

- **データ**：配置中IDは `pet.placedItems`（`equippedItems` とは別配列・排他なし複数配置）。購入は装着と共通（`buyItem`・slot非依存）
- **描画（前後2層）**：`catMarkup` が `.cat` 正方枠に `cat__scene--back`(z1) と `cat__scene--front`(z5) を最初から持ち、`SCENE_BOX[id].layer` を**既定**として振り分ける（#270 でユーザーが上書き可）。画像は `img/cat/scene/{id}.webp`（透過・box×3・中心原点）
- **配置/ドラッグ**：置物も `.cat__item`＋`<g transform>` なので dressup（#168/#205）が**無改修で**扱える。装着アンカーを持たないため既定（`SCENE_DEFAULT_PCT`＝足元寄り 50%,64% / 基準スケール1）を返し、描画の初期位置と掴み開始位置を一致させて初回ドラッグのジャンプを防ぐ。座標は `itemLayout` を共用
- **背面置物の選択（#240）**：背面置物は不透明な本体img(z2)の下にあり、img が矩形全体で `pointerdown` を奪うため掴めなかった。**編集中だけ本体を pointer 透過**（`.cat-stage--editing .cat__body { pointer-events: none }`）にして下の `.cat__item` まで通す。なで（本体タップ）は非編集時のみなので無影響
- **同期**：`pet` 配下。初回マージ規則と復帰時の上書き対策（#242）は [data-model.md](./data-model.md)

> **設計判断（#226・topic_1782737748350 で合意）**
> - 装着の「slot排他1点」を流用すると `equipItem`/`spentCoins`/`cleanItemLayout` が汚染されるため **`placedItems` を新設**して装備と完全分離
> - 前面/背面の2層を**最初から**用意し `layer` で振り分ける（後から前面層を足すと catMarkup/DOM/dressup を再改修するコストが大きい）
> - 座標は新フィールドを作らず `itemLayout` を共用（IDが装着系と重複しない前提でマージ規則の追加が不要）
>
> **実装時の精緻化**: 合意時は「`.cat` の兄弟としてステージ全面に scene-SVG を張る」案だったが、`.cat-stage` が高さ指定の無い flex で**非正方（横長）**である一方、dressup の%基準と装着系の描画枠は正方 `.cat` だと判明。全面に張ると画像が歪むかドラッグ追従がズレるため、**scene-SVG を正方 `.cat` 内に置き**装着系と同一の viewBox に乗せた（前後はDOM順＋z-index）。

### きょうのおまけ（#148）

- **練習を記録した日だけ**、その日の**初回記録**（同日に既存記録がないとき）に低確率（`BONUS_CHANCE`＝20%）で `BONUS_COINS`＝3コインのプチ報酬。当選時は専用ポップアップ（🎁）

> **設計判断（#148）**: 「練習しなくても得するログインボーナス」は習慣化と矛盾するため**不採用**。練習行動に連動させる。

### 猫の見た目（なつき度 tier・#167）

|---|---|---|

| mid | Lv3〜7 | リラックス |

> **設計判断（#167）**

> - 衣装・演出は猫本体に焼き込まず別レイヤーで重ねる（#168 きせかえの土台）。ロードは現 tier の4mood先行＋次 tier 境界の2pt手前で `requestIdleCallback` 先読み

### ストリーク（連続練習）とお休み券

- 前日に練習していれば連続。同日の二重記録は増やさない
- **お休み券（`streak.freezes`）**：ちょうど3日、および7日ごと（7・14・21…）に +1枚（**上限2枚**＝`MAX_FREEZES`）
- 間が空いたとき、抜けた日数ぶんの券があれば消費して連続を維持（救済できなければ1にリセット）。**リセットされても券は没収されない**
- 券で連続を守ったときは専用ポップアップ

> **設計判断**: ストリーク報酬は非対称。コインのマイルストーン（+10/+30）は **3日・7日の到達時のみ**で14日以降は付かない（インフレ抑制／オンボーディングの前倒し）。一方お休み券は **7日ごと**に供給し続ける（長期の維持モチベーション）。コインは `calcRewards`、券は `isFreezeMilestone` と別ロジック。

## 猫の表示とインタラクション（[cat-image.js](../js/cat-image.js)）

- コンテナ `.cat` に `img.cat__body`＋衣装（`cat__front`・全種前面 #211）＋演出（`cat__fx`：ハート/きらきら/Zzz/エンブレム）を別レイヤーで重ねる（衣装は #196 でラスター、演出はSVG）

- **なでなで**（猫タップ）：記録に影響しない安全な操作
  - 反応の種類（約15%で「シャー」＝威嚇、残りは「ニャー」）は `rollCatVoice()` が**音設定に依存せず**抽選する。再生（`playCatVoice`）は別関数で、サウンドOFFなら無音
  - 威嚇でなければ喜ぶ／しっぽふり（ランダム）。**威嚇なら喜び演出を出さず `playHiss` が表情の一時差し替えだけ行う**（#187。抽選を再生から分離しているためミュート中でも出し分けが効く）
  - なかよしレベルが高いと、威嚇でないとき `bondCelebrateChance(level)` の確率で**特別演出**へ格上げ（#124）

## サウンド（[sound.js](../js/sound.js)）

- **効果音（シンセ）**：Web Audio API で生成。コイン獲得 / レベルアップ / 記録完了 / アイテム購入
- **スタンプ音階（#139, #154）**：`playStamp(index)` がド=C4 基準の Cメジャー音階で音程を上げ、目標マスは**主和音**で解決。周波数は平均律で計算（`stampSemitone`/`stampFrequency`・追加アセット0）、和音は `stampNotes(index)` が組み立てる（主音＝高いドに長三度・完全五度・1oct下ボディ）
- **鳴き声（録音サンプル）**：なでた時のみ。`meow1〜3.mp3`（通常）/ `hiss1.mp3`（威嚇）
- ヘッダーのトグルでON/OFF（`settings.soundOn`・端末ローカル）。AudioContext はユーザー操作後に解錠（自動再生ポリシー対策）
- **省電力・自動 suspend（#146）**：鳴り終わってアイドルが続いたら（`IDLE_SUSPEND_MS`）`suspend()`。タブ非アクティブ時も `suspendAudio()`、復帰時に `resumeAudio()`。次の再生で `getCtx()` が `resume()` するため状態は失わず体感遅延もない

> **設計判断（#139/#154）**
> - issue の実装例は半音上昇（`2^(index/12)`）だが、それでは「ドレミの音程感覚を養う」狙いが満たせないためダイアトニックを採用
> - 目標マスは当初 単音の高いドで解決させていたが、半音オフセット列が index8→9 で 14→12 と逆行し、最も興奮する最終タップでピッチが下がる違和感があった（topic_1780484001568 で指摘）。**主和音化**で「豪華なごほうび」へ昇華させ解消（#154）
> - pure 層（`stampSemitone`/`stampFrequency`）は主音=高いドのまま維持し、和音合成は再生側に閉じて責務分離を保つ

## Service Worker のキャッシュ戦略（[sw.js](../sw.js)）

`gen-sw` が生成する `APP_SHELL` を install 時にプリキャッシュし、fetch は2本立て。

| 対象 | 戦略 |
|---|---|
| 同一オリジン | **network-first**（`fetch(request, { cache: 'reload' })` で HTTP キャッシュもバイパス）。成功時にキャッシュを更新し、失敗時のみフォールバック。ナビゲーションのフォールバック先は `./index.html` |
| 外部オリジン | `caches.match` → 無ければ `fetch`。**プリキャッシュにも fetch 後の保存にも載せていない**ため実質は素通し |

> **設計判断**
> - ES モジュールの `import` には `?v=` を付けられず、HTTP キャッシュが効いていると古い版が残り続ける。`cache: 'reload'` で毎回サーバへ確認して**版ズレを構造的に断つ**方を選んだ
> - 代償はオンライン時のシェル取得が常にネットワーク待ちになること
> - #142 の「ローカルファースト」は **state 読み込み（localStorage を同期読みして即描画）** の話であってシェル配信ではない——**両者を混同しないこと**
> - 体感で問題になるなら `?v=` 付き JS を stale-while-revalidate にするなどシェル側で手当てする
>
> **外部オリジン**: `caches.match` を先に見る形だが、外部レスポンスをキャッシュへ入れる経路が無いので**必ず miss → fetch**。Google Fonts はオフラインで取得できずフォールバックフォントに劣化する（機能は落ちない）。外部依存をキャッシュで延命させないための意図的な素通し。

## テストの方針とカバレッジ（#277）

| 層 | 対象 | 置き場所 |
|---|---|---|
| 単体（Vitest） | 純粋ロジック（`game` / `storage` / `shop` / `feed` / `record-form` / `history` / `song-color` / `sound` / `cat-image` / `account` / `backup` / `badges` / `child-profile` / `onboarding`） | `tests/*.test.js` |
| E2E（Playwright・Pixel 5） | 画面をまたぐフローと DOM ↔ state の対応 | `e2e/*.spec.js` |
| E2E（iPhone 13・`@compat` のみ） | iOS 実機で壊れやすい経路 | 同上のうちタグ付き |

**`@compat` の基準**：iOS Safari 固有の懸念がある経路に限る（全件を各ブラウザで回すと重いため）。現在は5件——記録（#117）／ショップの購入・装備（#124）／きせかえのドラッグ（#168・Pointer Events）／バックアップの書き出し（#140・ダウンロード）／復帰時 resync（#242・iOS PWA のサスペンド）。

**クラウド同期のテスト（`e2e/cloud-sync.spec.js`）**：他の spec は Firestore を `route.abort` で遮断しているため、`initCloudSync` / `reconcileInitialCloud` / `applyRemoteState` / `resyncFromCloud` は長らく**一度も実行されていなかった**（データ損失系という最高リスク領域が退行検知できない状態）。

> **設計判断（#277）**
> - DI を作らず、**`./js/cloud.js` へのリクエストを `page.route` で差し替えて偽モジュールを配る**方式。`app.js` が `await import('./cloud.js')` で動的読み込みしている（#142）ため、本番コードを1行も変えずに実経路を通せる
> - Firestore エミュレータ案は不採用。CI の起動コストが高く、検証したいのは「マージ規則」であって Firestore の挙動ではない
> - 偽モジュールの doc は `window.__cloudDoc`、realtime のコールバックは `window.__onRemote` に生やしてテストから撃つ
> - 追加5件は**アプリ側の #142 / #242 を取り消すと3件が落ちる**ことを実測済み

**まだ埋まっていない空白**

- **オフライン / SW の実行検証**：全 project で `serviceWorkers: 'block'`（キャッシュ干渉を避けるため）なので install / activate / fetch が走らない。担保は `gen-sw:check`（列挙の一致）のみ
- **`prefers-reduced-motion`**：CSS のみの実装で E2E 検証なし

## アクセシビリティ・表示テーマ（#151）

- **prefers-reduced-motion**：OSの「視差効果を減らす」設定時、猫の呼吸/ジャンプ/ハート等（[cat.css](../css/cat.css)）に加え、スタンプの登場・オンボーディングのポップ・各種バーの伸び（[style.css](../css/style.css)）も停止。ご褒美フィードバックは静止表示で残す。CSSのみで完結
- **ダークモード**：構造色を `:root` のセマンティック変数（`--surface`/`--surface-soft`/`--surface-mute`/`--pink-soft`/`--cream`/`--ink`/`--shadow`/`--text-muted`）に集約し、ダーク時はこの変数群だけを上書き。ピンク/ゴールド等のアクセント色は両モード共通
  - **切替**：親ゲート内の「がめんの あかるさ」で じどう / あかるい / よる。`じどう` は `@media (prefers-color-scheme: dark)` でOS追従（`data-theme` なし）、他は `data-theme="light"/"dark"` で固定
  - **保存**：端末ごとの好みなので同期せず `localStorage['pp-theme']`（`settings.soundOn` と同じ方針）
  - **チラつき防止**：`index.html` の `<head>` インラインスクリプトで描画前に `data-theme` を適用。`auto` は属性を付けない

> **設計判断（#151）**: 既存CSSは `#fff` 等のリテラル色が散在していたため、ダーク化はセマンティック変数への置換で実現。ライトでは各変数を従来リテラルと同値に定義して見た目を完全維持（差分は無リスク）。`auto` で属性を外す方式により、JSでの `matchMedia` 監視なしにOSの切替へ即時追従できる。

## ポップアップ演出

獲得コイン / えさやり（もぐもぐ）/ きょうのおまけ / お休み券キープ / バッジ獲得。記録後はコイン → おまけ → お休み券 → 新規バッジの順で表示する。

> **設計判断（#261）**: 表示ロジックは共通ヘルパー `showPopup(popup, duration, onHidden)` に一本化。`transitionend` の once リスナーを素朴に張る旧実装は、連続表示（えさやり連打等）で前回のリスナーが残り、新しいポップアップを表示アニメの transitionend で途中非表示にする競合があった。要素ごとにタイマー・リスナーを張り替えて解消（バッジの連続表示は `onHidden` チェーン）。
