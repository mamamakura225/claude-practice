## 画面とナビゲーション

ハッシュベースのSPA（[router.js](../js/router.js) / [app.js](../js/app.js) `render`）。

- ボトムナビ4タブ：**ホーム / きろく / ショップ / バッジ**
- 練習記録入力（record）はナビに出さず、ホームの「れんしゅうを きろくする」ボタンから開く（ナビ上はホームを選択状態に保つ）
- UI文言はひらがな主体（5歳でも読める表記）

### こどものアバター（#121）

ヘッダ左隅にこども本人のアイコン（絵文字）と名前を常設表示する。home / きろく の両画面ヘッダに同じ内容を出す（`renderChildAvatar` が `.child-avatar` を一括更新）。

- **アイコンはタップで選択**：アバターをタップすると選択オーバーレイ（`#avatarOverlay`）が開く。こども本人が選ぶ操作なので**親ゲートは挟まない**。絵文字10種（🐥🐰🐻🐼🦊🐸⭐🌸🦄👑・[child-profile.js](../js/child-profile.js) `CHILD_AVATARS`）から選び、なまえ（最大12文字）も入力できる。
- **顔写真は不採用**：認証なしの共有 Firestore に保存するため、子の顔写真を載せるのはプライバシー上不可。絵文字なら軽量・クラウド同期可・PII を増やさない。
- **保存とフォールバック**：`pet.childName` / `pet.childAvatar`（絵文字ID）に保存し、pet ごと cloud-wins で別端末にも同期。未設定・未知IDは既定の 🐥（chick）にフォールバック、名前が空ならラベルは非表示。analytics には名前・アイコンを送らない（PII規約）。
- 名前は入力中もヘッダに即反映し、オーバーレイを閉じるときに前後空白を落として確定保存する（`normalizeChildName`）。

**猫のmood**（プリレンダ画像の表情。恒常表示は idle/sleep、happy/love/hiss は演出中の一時差し替え）

| mood | 条件 | 表現 |
|---|---|---|
| `idle` | 通常 | ゆっくり呼吸（画像を scaleY でふくらませる） |
| `happy` | 練習記録直後 | うれしい表情に差替＋ぴょんと跳ねる・ハートが飛ぶ |
| `sleep` | 最後の練習から2日以上経過 | 目を閉じた表情＋Zzz |
| `love` | なでた時の反応 | だいすき（ハート目）表情に差替＋しっぽふり／喜ぶ |
| `hiss` | なで反応で威嚇（シャー）を抽選した時（#187） | 威嚇表情に差替のみ。喜び演出（ハート・しっぽふり）は出さない |

## 初回オンボーディング（猫の吹き出し紙芝居・#141）

初回起動時、猫（きーちゃん）の**吹き出し3画面の紙芝居**で「①れんしゅうを きろく → ②ごほうび（コイン／猫が育つ）→ ③きせかえ・ごはん」を案内し、最初の成功体験で初期離脱を防ぐ。実装は [onboarding.js](../js/onboarding.js)（紙芝居データ＋フラグ）と [app.js](../js/app.js)（DOM 制御）。

- **新規アセットは持たない**。既存の猫SVG（`catMarkup`・若猫）をカードに流用し、上向きしっぽの吹き出しで説明する
- ひらがな主体・大ボタン（「スキップ」「つぎへ／はじめる！」）。進捗ドット3つで現在地を示す
- 「つぎへ」で次の画面、最後の画面ではボタンが「はじめる！」に変わる
- **スキップ可**。「スキップ」または最後の「はじめる！」で `piano-pet-onboarded='1'` を立てて閉じ、以後は出さない
- 表示制御は localStorage の単独フラグ `piano-pet-onboarded` のみ（端末ローカル・クラウド非同期。[data-model.md](./data-model.md) 参照）。`renderHome()` の後に重ねて表示する
- localStorage が読めない環境（プライベートモード等）では「見た」扱いにして案内を抑止する（うるさく出すより無害側に倒す）

## 練習記録入力（2モード：スタンプ / まとめて）

日付の下に「**🐾 スタンプ / 📝 まとめて**」のモード切替（タブ）がある。既定はスタンプモード。実装は [record-form.js](../js/record-form.js)（純粋ロジック）と [app.js](../js/app.js)。

- **日付**：両モード共通。デフォルト今日
- モード切替時は入力途中の内容を「曲×回数」として相互変換して引き継ぐ（`stampsToSongs` / `collectSongs` / `songsToStamps`）。取りこぼしなし

### スタンプモード（親=曲えらび／子=スタンプ・#117）

タイル状の「ハンコ」を押して回数を数える、子供にも押せるUI（役割ガイドの文言は #189 で削除し、チップとハンコだけのシンプルな画面にした）：

- **きょくを えらぶ**：曲名チップ（過去の曲を「よく弾く順→新しさ」で最大8件サジェスト＝`pastSongNames`）。新規曲入力欄は過去の全曲名を `datalist` で補完。「＋」で候補に追加。曲の選定は親の操作。各チップには曲の色スウォッチ（左の丸）が付き、選択中はチップ全体がその色になる（#122）
- **ハンコを おす！**：タップで選択中の曲のハンコ（🐾）が1つ増える。最低10マス、超過時も常に1マス余分に出して押し続けられる。10マス目（目標）を強調。「○こ / もくひょう 10こ」表示、「↩ ひとつ もどす」で直前を取り消し。回数記録（スタンプ）は子に渡せる操作。**押したマスは押下時に選ばれていた曲の色で塗られる**（曲ごとに色が変わる・#122）
- **当日中はスタンプカードを引き継ぐ（#164/#186）**：押したスタンプは localStorage の下書きキー `piano-pet:stamp-draft` に一時キャッシュされ、ホームに戻って記録画面を開き直しても0からリスタートしない。打鍵ごとの Firestore 同期はしない。**記録を確定した後でも当日なら引き継ぐ（#186）**：当日セッションが既にあれば下書きではなくそのセッションからスタンプを復元（`songsToStamps(combineSongs(...))`）し、続きを押せる。日付（`todayStr`）が変われば下書きは破棄して0スタート（[data-model.md](./data-model.md) 参照）
  - **当日の記録画面は「その日ぜんぶ」を表す（#186）**：記録画面は当日セッションの全内容を復元しているため、submit 時は追記ではなく**置き換え**る（`isToday` 分岐）。これにより当日中の押し増しが二重計上されず、データ上も同日同曲が1レコードに収まる。日付欄を過去日に変えた場合のみ従来どおり合算する
  - **同日同曲の合算表示（#186）**：きろくタブの表示は `combineSongs` で同名の曲を1行に合算（既存の分割済みデータも表示時に合算される）。`mergeSameDaySessions` も統合時に `combineSongs` する

#### 曲の色（決定的ハッシュ＋衝突回避・#122/#165）

曲名→色は [song-color.js](../js/song-color.js) が担う。曲名を FNV-1a ハッシュして色相（0〜359）を取り、彩度・明度は固定（`songColor` が `fill`/`tint`/`ink` の3色を返す）。**保存しない**ので sessions さえ同じならどの端末でも同じ曲は同じ色になる。空名は無彩色グレーにフォールバック。前後空白は無視して同一視する。
- **色かぶり回避（#165）**：ハッシュだけだと別の曲の色相が近接し同じ色に見えることがある。`assignSongColors(names)` は曲名リストを先頭から走査し、すでに割り当てた色相に近すぎる（最小ギャップ 25°未満）曲は隣の色へずらして識別性を確保する。並びは累計回数順（`songTotals`）で決定的なので #122 の「sessions さえあれば端末間で一致」は維持される。スタンプ／チップ／コレクションは同一マップ（app.js `buildSongColors`）を基準にする
- スタンプを押すたびに音程が**ドレミ…と上がる**（1マス目＝ド）。目標マス（最後の1マス）は**Cメジャー主和音（ド・ミ・ソ）**で「シャラーン」と解決し、同時にレベルアップ音が鳴る（#139, #154）

### まとめモード（親の後追い入力・#123）

その場でスタンプを押さなかった日を、**親が後からまとめて記録**するための入力。

- **きょく＋かいすう を まとめて**：1行＝曲名（`datalist` で過去曲を補完）＋回数ステッパー（− / 数値 / ＋）。「＋ ぎょうを ふやす」で行を追加、各行の「✕」で削除
- 「ごうけい ○ かい」をライブ表示。集約は `collectSongs`（空名・0以下の行は除外）

### 記録の確定（両モード共通）

- **きろくする**：合計0回（有効な入力なし）は記録不可（`isValidSession`）。スタンプモードで曲未選択ならヒント表示

**記録後の動作**
1. コイン・XP・ストリーク・バッジを計算して反映（`applySession`）
2. ホームへ遷移、猫が喜ぶアニメ。節目（レベルアップ／新バッジ／連続日数の節目）は特別演出 `playCelebrate`、それ以外はランダムな日常のお祝い `playHappy`（`celebrateRecord` が出し分け / #81）
3. 獲得コインのポップアップ（レベルアップ時はその旨も表示）
4. 効果音：記録完了音 →（レベルアップ時）レベルアップ音
5. お休み券で連続を守った場合 → お休み券ポップアップ、新規バッジ獲得 → バッジポップアップ（複数は順番に）
6. **同じ日付に既存記録がある場合は統合して全再計算**（`recomputeState`、目標達成ボーナスの二重取りを防ぐ）

## 記録履歴（きろく）

- 連続記録カード：いまの れんぞく / さいこう きろく
- **今週の ふりかえりカード**（#144）：今週（月曜起点）の「かいすう／きょく数／れんしゅうした日数」を集計表示（[history.js](../js/history.js) `weeklySummary`）。**「📤 せんせいに おくる」共有ボタンは現在閉塞（#192・先生は利用者として登場しない方針 #152）＝UI 非表示。ハンドラ `shareReview`・計測 `review_shared` は温存。** 共有時は Web Share API（`navigator.share`）にワンタップ送信。本文は `reviewShareText`（曲名は載せない＝送信は最小限）。Web Share 非対応はクリップボードコピー→スクショ案内にフォールバック。送信用ストレージ・外部ライブラリ・サーバー不要（端末内完結）。計測は操作フラグ `review_shared` のみ（内容は送らない）
- 週ごとの合計回数の棒グラフ（直近8週、SVG・外部ライブラリなし＝[history.js](../js/history.js) `weeklyChartModel`）
- **きょくべつ コレクション**（#122）：曲ごとの累計回数を「多い順→新しさ」で一覧表示（[record-form.js](../js/record-form.js) `songTotals`）。各曲は決定的ハッシュ色のスウォッチ＋「○かい」。回数0や空名の曲は出さない
- **曲マスター👑**（#149）：曲の累計回数が `SONG_MASTER_COUNT`（=50）回に達した曲はコレクションに👑を表示（[record-form.js](../js/record-form.js) `isSongMaster`）。`songTotals` から決定的に導出し専用フラグは持たない（再計算で矛盾しない）
- 記録一覧（新しい順）：日付「M月D日（曜）」・曲名・回数・合計。各記録に「✏️ なおす」「🗑️ けす」
- **はなまるスタンプ**（#145）：各記録にワンタップで評価スタンプ（💮はなまる／🌟じょうず／👍がんばった）を付与・表示。同じスタンプの再タップで解除。固定絵文字のみで自由記述は持たない（[record-form.js](../js/record-form.js) `PRAISE_STAMPS` / `normalizePraise`）。`session.praise` は曲数から導出されない単一値だが全再計算・同期で保持される

**編集・削除**
- 「なおす」：record 画面に切り替え、スタンプカードへ内容を復元して編集モード（`songsToStamps`）
- 「けす」：確認ダイアログのうえ削除
- 編集・削除後は **sessions を唯一の正として XP・レベル・コイン・ストリーク・バッジをゼロから全再計算**（`recomputeState`）。報酬演出は出さない

## ショップ

### ごはんを あげる（えさやり・消費型）

実装は [feed.js](../js/feed.js)。

| アイテム | 価格 | なかよし |
|---|---|---|
| 🐟 おさかな | 10コイン | +1 |
| 🥛 ミルク | 15コイン | +1 |
| 🍰 ケーキ | 30コイン | +3 |

- 「あげる」でコインを消費し「なかよし度（`pet.affinity`）」が上がる → もぐもぐポップアップ
  - えさは別タブ（ショップ）であげるためホームの猫が見えない。「あげた」感が伝わるよう、ポップアップ内でえさアイコンが もぐもぐ揺れて → 食べられて消え、なかよし💖が弾む演出を付ける（CSS `coin-popup--feed`・#217）
- 消費したコインは `pet.foodSpent` に累積し、記録の編集・削除時の全再計算でも所持コインが復活しないようにする
- えさやりの見出しに現在の「なかよしレベル」名を表示し、下に**なかよし ごほうび解放リスト**（Lv1〜8・🔒/💝）を並べる（#124）

#### なかよしレベルとご褒美（#124・#216）

`affinity` のしきい値で「なかよしレベル」が上がり、ご褒美が解放される（[feed.js](../js/feed.js) `affinityLevel` / `affinityRewards` / `bondCelebrateChance`）。

**#216 で 5→8段階に細分化**し、刻みも詰めた（えさやり等の成果が「すぐ見える」ように）。番号で報酬を判定する消費側（`unlockLevel` / `bondCelebrateChance` / `tierFromBond` / エンブレム）は、旧しきい値と**等価な affinity 値の新レベルへ再マップ**してあり、既存ユーザーの解放状態は退行しない。

| Lv | 名前 | 必要 affinity | ご褒美 |
|---|---|---|---|
| 1 | ともだち | 0 | いっしょに あそぼう |
| 2 | なかよし | 3 | ホームの猫に**ハートのエンブレム**が常時付く |
| 3 | だいすき | 7 | 猫の見た目が **mid tier**（表情が豊かに） |
| 4 | だいだいすき | 12 | なでると**ときどき特別演出**（`playCelebrate`） |
| 5 | ベストフレンド | 18 | エンブレムに**きらきら**が加わる＋特別演出の確率アップ |
| 6 | きずな | 25 | 特別演出がさらに出やすく |
| 7 | さいこうのなかま | 33 | 特別演出がもっと出やすく |
| 8 | えいえんのきずな | 42 | 猫の見た目が **high tier**＋さいこうの なかよし演出（確率最大） |

- **エンブレム**：[cat-image.js](../js/cat-image.js) `bondEmblemGroup` が `catMarkup({ bond })` で猫の隅（fxオーバーレイSVG）にハートを描く（Lv2〜、Lv5+ できらきら）。ホームは `affinityLevel(affinity).level` を `bond` に渡す。`bond` は画像の tier 導出にも使う（Lv1-2→low / Lv3-7→mid / Lv8→high・#167）
- **専用演出**：なでなで時、`bondCelebrateChance(level)` の確率で通常反応の代わりに特別演出が出る（Lv4:20% / Lv5:30% / Lv6:40% / Lv7:50% / Lv8:55%）
- **ホーム表示**：「💖 なかよしレベル N（名前）」＋次レベルまでの進捗バー（最大レベルは「さいこうの なかよし！」）
- 解放状態は **`affinity` から決定的に導出**し専用フラグを持たない（`recomputeState` が `affinity` を保持するため全再計算でも矛盾しない）

- 所持済み：「みにつける」/「はずす」トグル（装備中バッジは「みにつけてる ✓」）。**同一スロットは1つだけ装備可**（別アイテムを装備すると同スロットの既存装備は自動で外れる）
- 装備するとホームの猫画像の上に、アンカー位置（neck/head/face/back）で重ねて即時表示。**全種を前面 `cat__front` に重ねる**（#211：cape も含む。前面内では cape を最下層に描き、その上に neck/head/face のアクセサリが乗る）。描画方式は基準0＝水彩ラスター（#196 で SVG から移行）
- 購入に使ったコインは `spentCoins`（インベントリの価格合計）として全再計算に反映

> **設計判断（#126・解放ゲート）**: 解放判定は `isUnlocked`＝`affinityLevel(pet.affinity).level >= unlockLevel` で、**購入時（`canBuy`）のみ**参照する。装備・描画（`equipItem`/`toggleEquip`/`catMarkup`）は現在Lvを一切見ず inventory/equippedItems の所属だけで判定するため、affinity 低下で再ロックされても**所持品は外れず・消えず・装備継続**（`recomputeState` の全再計算でも不変）。解放済みフラグは持たず affinity から決定的に導出（なかよしご褒美 #124 と同設計）。既存ユーザーは現在の affinity から相応に解放済みで始まるためマイグレーション不要。

### きせかえ アイテム 品質基準（#191・#126へ引き継ぎ）

既存・新規を問わず衣装が満たすべき基準。子供＝「一目で何かわかる・買った絵文字と一致」、親＝「コイン（練習の努力）の対価として段階的に豪華」を両立させる。新規アイテム（#126）はこの基準を満たしてから追加する。

0. **描画方式＝本体と同じ水彩ラスター**: 衣装は猫本体（プリレンダ水彩PNG）と画風を統一するため、透過ラスター画像（PNG/WebP・retina 2x）で用意する。手書きインラインSVGからの移行。**A（SVG）とB（ラスター）の混在は禁止**（猫の上で水彩とベクターが同居すると画風が割れ、本基準の目的に反する）。色違い展開は行わず、必要な色は個別の画像として作成する。装備時は dressup の `<g transform>` 内の中身を `<image href>` に差し替えて重ねる（ドラッグ・アンカー・スナップは無改修）。画像は `img/` 配下でSWプリキャッシュ対象だが perf-budget（html/css/js のみ判定）の対象外。
1. **絵文字一致（第一条件）**: ショップアイコン（絵文字）と装備後のシルエット・主色が同系統に見える。買った🎀が猫の上で🎀と認識できること。
2. **小サイズ可読**: 猫装着サイズ（scale≈0.8）で、塗りの面＋2〜3色で「何か」が判別できる。細い線画だけに依存しない（例: 星はひし形でなく星型シルエットで示す）。
3. **顔・表情を残す（バランス）**: neck/face は猫の目・口にかからない配置・サイズを既定とする。王冠・はなかんむり等の head 上位アイテムは、目を残す範囲なら頭頂〜額の装飾が多少かかってもよい（豪華さとのバランスを許容）。
4. **スロット内の差別化**: 同一スロットのアイテムは形か主色で明確に別物とわかる（現状 neck4・head4 が過密で被りやすい点に留意）。
5. **価格＝豪華さの段階性**: 高価格ほど面積・装飾・きらめきを増やし、価格順に視覚的グレードが上がるようにする。

> **設計判断（#191）**: 着せ替えは「拡充（#126）の前に既存品質を上げる」順序とする。絵文字を事実上の完成イメージとして基準1に据えるのは、5歳児にとってショップ選択時の期待（絵文字）と装着結果の不一致が最も混乱・がっかりにつながるため。個別アイテムの描き直しは本基準に沿って別Issue/PRで進める。
>
> **設計判断（#191・描画方式）**: 衣装を手書きインラインSVGから水彩ラスターへ移行する（基準0）。理由は猫本体が「SVGでは水彩品質に届かない」としてラスター化済みであり、衣装だけSVGだと本体と画風が割れること（#191の見栄えの悪さの一因）。ラスターの弱点である色違いの量産（PNGは任意色に再着色できない）は、当面**色違いを行わない**方針で割り切り、必要な色は個別画像として作成する。衣装は mood/tier に依存せず重ねるだけのため必要枚数は本体（45枚）と異なり1アイテム1枚（×retina）で済み、perf-budget 対象外なので肥大化リスクは本体同様に小さい。

##### 画像の作画枠（`cat-image.js` `ITEM_BOX` ＝アンチグラビティ納品仕様・#196）

各画像は下表の **box（描画座標系・原点(0,0)＝装着アンカー）** の縦横比で、透過・**box×3**（#229・box の3倍px。旧 retina 2x から引き上げ）の **WebP**（#234）で作成する。`<image>` は `preserveAspectRatio="xMidYMid meet"` で box にフィットさせるため、**画像の縦横比を box と一致**させ、原点位置（猫に対してどこに乗るか）を box の (x,y)〜(x+w,y+h) 範囲に合わせること。box を据え置くことで dressup／アンカー／スナップ（#168）は無改修・ドラッグ移動継続。

> **設計判断（#229＋#234・高解像度化とWebP化を同時実施）**: ピンチ拡縮（#205・絶対スケール最大3.0倍）で 2x ソースが引き伸ばされアラが出るため、装着14点＋置物2点＋本体45枚の作画枠を **retina 2x → box×3** に引き上げた。PNG のまま倍率を上げると SWプリキャッシュ・初回DLが線形に増える（box×3 で ~5.2 MiB）ため、**同一ブランチで PNG→WebP 化**（`cat-image.js` の href 拡張子・`gen-sw.mjs` の収集拡張子を `.webp` に、全61枚を quality85 で変換）。結果 **4.82 MiB（従来PNG）→ 3.60 MiB（box×3 WebP）** と、解像度を上げつつ総量を約25%削減。WebP は iOS Safari 14+（2020〜）でネイティブ対応し 2026 時点で旧版シェアが実質消滅のため `<picture>` フォールバックは設けない（#167 の PNG統一判断を反転）。全61枚のブラウザデコード（naturalSize>0・404無し）を実測確認。演出・グラフSVGは対象外。

### きせかえ 自由配置（ドラッグ・#168／ピンチ拡縮・#205）
ホームの「👗 きせかえ」トグルで編集モードに入ると、装備中の衣装を**1本指ドラッグで移動・2本指ピンチで拡縮**できる。実装は [dressup.js](../js/dressup.js)（pointer追跡）＋ [cat-image.js](../js/cat-image.js) `itemsSvg`/`itemAnchorPct`/`itemAnchorScale`。

- **配置データ**: `pet.itemLayout = { itemId: {x_pct, y_pct, scale?} }`（ステージ=.catコンテナ基準の%・ビューポート非依存）。`pet` 内なので Firestore へ自動同期（ズレは LWW）。`shop.js` の装備ロジックは無改修
- **フォールバック二段構え**: `itemLayout` に座標が無い衣装は既定アンカー位置・基準スケール（`a.s`）で描画し、初操作で `itemLayout` に記録
- **位置スナップは廃止（#214）**: ドロップ時は常にその座標を `itemLayout` に記録する。以前あった既定アンカーへの位置吸着は、配置の自由を奪い操作ミスのように感じられたため撤去。範囲外はステージ内に clamp。スロット跨ぎはしない。座標を持たない旧データ（`{scale}` のみ等）はフォールバックで従来どおり描画（後方互換・マイグレ不要）
- **ピンチ拡縮（#205）**: 2本指の距離比で `scale` を更新。**絶対値**で `0.3〜3.0` に clamp。基準スケール `a.s` の ±5% 以内に入ると `a.s` へ吸着し「元のサイズ」へ戻しやすくする。2指間距離が 10px 動くまでは拡縮を始めない（誤操作・ガタつき防止のデッドゾーン）。ピンチ中は位置を固定し拡縮のみ反映
- **最小タッチ領域（#215）**: アイテムは `<g scale>` で縮むと `<image>` のヒット領域も縮み掴みにくいため、各 `<g>` に透明ヒット矩形（`.cat__item-hit`・`fill=none`/`pointer-events=all`）を**逆スケール**で内包する（`width=max(box, MIN_HIT_UNITS(44)/scale)`）。scale 適用後の画面サイズが常に約66px以上になり、小さく縮めても掴める。見た目（画像）は不変
- **なで競合の回避**: 編集モード中は `petCat`（なで演出）を無効化。猫の周囲を点線で囲う視覚フィードバック。「✅ できた！」で抜ける
- **ゴーストデータ掃除**: `commitState` の `cleanItemLayout` が、装備していない衣装の座標を `itemLayout` から除く（同期ペイロード健全化）。`scale` は同 id のオブジェクト丸ごと保持/掃除されるため無改修

### 猫スタイル切り替え（#66）
きせかえ編集モード中だけ、猫の下に**スタイルピッカー**（`#stylePicker`）が出る。ちゃとら／しろ／ぐれー（ロシアンブルー）の3種から選べ、選択は `pet.catStyle`（'tora' | 'shiro' | 'russianblue'）に保存して Firestore 同期。未定義は 'tora' フォールバック＝既存ユーザー後方互換。

- サムネイルは本番の `cat_{style}_low_idle.png` をそのまま使う。**ピッカーを開いた時点で各スタイルの idle が自動ロードされる**ため、切り替え時のチラつきがない
- 切り替えは `commitState` → `renderHome` が本体画像・preload を新スタイルで引き直す
- スタイル別の衣装アンカー補正は `STYLE_ANCHOR_OFFSETS`（cat-image.js）。納品画像の実測で値を決め、ズレが小さければ空のまま（手動ドラッグ #168 でも調整可能）

> **設計判断（#168）**: 配置座標は `equippedItems`(id配列) に埋め込まず**別フィールド `pet.itemLayout`** に分離した。`shop.js`/`equipItem` 系の装備ロジックとテストを温存し、状態遷移へのバグ混入を避けるため。完全自由配置だと5歳児には絵が崩れやすいので、アイテム固有アンカー1点への吸着で「自由さ」と「見栄え」を両立する。

> **設計判断（#205・Antigravity対称レビュー topic_1782030433684 で合意）**: ①`scale` は**乗数でなく絶対値**で保存。乗数（`a.s × k`）だと将来アセット更新で基準スケール `a.s` を調整した際、すでに自由配置済みの衣装サイズまで勝手に変わり配置と齟齬が出る。絶対値ならユーザーの意図したサイズが守られ、`pos?.scale ?? a.s` で完全後方互換。②**スナップで定位置に戻してもアンカー実座標は焼き込まない**——`{scale}` のみ保持し位置は描画時にアンカーから引く（※位置スナップは #214 で廃止。`{scale}` のみのデータは旧データのフォールバックとして読み続ける）。③5歳児UXの補助は**「基準スケール吸着」と「ピンチ開始デッドゾーン(10px)」の2点のみ採用**。clampで上限下限は安全に頭打ちになるので、(a)枠線の状態別色分けと(b)clamp到達時の色シグナルは**最小構成のため見送り**（必要になったら別Issue化）。

> **設計判断（#214・Antigravity対称レビュー topic_1782394334271 で合意）**: 位置スナップ（既定アンカーへの吸着）を**廃止**し、ドロップ座標を常に自由配置として記録する。アンカー吸着は「思った位置に置けず勝手に戻る」操作ミスのように感じられ、自由配置の意図に反するため。**サイズの基準スケール吸着（#205）は位置スナップとは別物（行き過ぎた拡縮を綺麗なサイズへ戻す補助）なので温存**する。座標を持たない旧 `itemLayout`（`{scale}` のみ等）は `itemsSvg` のアンカーフォールバックでそのまま描画され、マイグレーション不要。

> **設計判断（#215・Antigravity対称レビュー topic_1782394334271 で合意）**: ピンチ縮小時のヒット領域確保は、JS側の最近傍アイテム探索ではなく**マークアップ側の逆スケール透明矩形**で行う。理由は①ブラウザ標準のポインタイベントとSVGの描画順（DOM順＝上層優先）にそのまま乗れて重なり時の挙動が素直、②位置・サイズを別途同期して距離計算するコードが不要で `cat-image.js` 内にロジックを閉じ込められ保守性が高い。`MIN_HIT_UNITS=44`（viewBox200系・`.cat`最大320pxで約66px）は実機で微調整可能な単一定数。ライブのピンチ中はヒット矩形を再描画せず確定時の再レンダで更新（掴み判定は開始時点で足り、簡潔さを優先）。

> **設計判断（#211・Antigravity対称レビュー topic_1782394334271 で合意）**: cape を背面レイヤー（`cat__back`）から**前面（`cat__front`）へ移し**、`cat__back` SVG 自体を撤去した。背面だと不透明な本体PNGに完全に隠れて「見えない・掴めない」ため。代替案（背面のまま端だけ覗かせ＋本体 `pointer-events:none`）は可視性を解決できず、なで反応にも影響するため不採用。前面内では cape を最下層に描画し neck/head/face のアクセサリがその上に重なる順序を保つ。cape の**アンカー種別（`back`＝位置・基準スケール）は不変**で、変わるのは描画レイヤーのみ。前面化で旧アート（背面前提）が前掛けに見える点は別途アート修正（#213）へ申し送り。

### 置物・小物系 アイテム（シーン配置型・#226）

装着型（猫アンカー基準・slot排他）とは別カテゴリの、**ペットに着せず猫の前後シーンに置く装飾アイテム**。実装は [shop.js](../js/shop.js)（`slot:'scene'`＋配置ロジック）と [cat-image.js](../js/cat-image.js)（`SCENE_BOX`／前後2層の描画）。MVPは2点：🧶 けいとだま（前面）・🛋️ クッション（背面）。

- **データ**: 配置中IDは `pet.placedItems`（装備 `equippedItems` とは**別配列・排他なし複数配置**）。`togglePlace`/`placeItem`/`unplaceItem` が管理し、`equipItem`/`spentCoins`/`canBuy` 等の装着ロジックは無改修。購入は装着と共通（`buyItem`・slot非依存）。
- **描画（前後2層）**: `catMarkup` が `.cat` 正方枠に `cat__scene--back`(z1・本体PNGの背後) と `cat__scene--front`(z5・演出の手前) の2つのSVGを最初から持ち、`SCENE_BOX[id].layer`（`'back'|'front'`）で振り分ける。画像は `img/cat/scene/{id}.webp`（透過・box×3・center原点／#229高解像度・#234 WebP）。`SCENE_BOX` の box は中心原点（配置点へ translate して中央描画）。
- **配置/ドラッグ**: 置物も `.cat__item`＋`<g transform>` なので、きせかえ編集モードの dressup（#168/#205）が**無改修で**ドラッグ移動・ピンチ拡縮できる。装着アンカーを持たないため `itemAnchorPct`/`itemAnchorScale` は置物の既定（`SCENE_DEFAULT_PCT`＝足元寄り50%,64% / 基準スケール1）を返し、描画の初期位置と掴み開始位置を一致させて初回ドラッグのジャンプを防ぐ。座標は `pet.itemLayout` を装着系と**共用**（置物IDは装着IDと重複しない）。配置外しは `cleanItemLayout` が座標を掃除。
- **背面置物の選択（#240）**: 背面置物（cushion=`cat__scene--back` z1）は不透明な本体img(`cat__body` z2)の下にあり、img が矩形全体で `pointerdown` を奪うため `onDown` の `e.target.closest('.cat__item')` が null になり掴めなかった。**編集中だけ本体を pointer 透過**（`.cat-stage--editing .cat__body { pointer-events: none }`）にして下の背面 `.cat__item` まで pointer を通す。なで（本体タップ）は非編集時のみなので無影響、前面置物(z5)・装着(z3)は本体より上で無影響。
- **同期**: `pet.placedItems` は CLOUD_FIELDS の `pet` 配下で同期。初回マージは equippedItems と同じ「union ∩ inventory」（未所持の配置は残さない）。`itemLayout` も union（cloud土台にローカル上書き）で他端末の配置座標を取り込む（#242）。

> **設計判断（#242・復帰時の丸ごと上書き対策）**: `pushCloud` は `setDoc`（merge無し＝doc丸ごと置換）、realtime の `mergeCloud` は `pet` をフィールドごと cloud-wins で差し替える。iOS PWA 等はサスペンド中 `onSnapshot` が届かないため、**復帰直後の古い in-memory state のまま操作すると、その古い `pet` が `placedItems`/`itemLayout` ごとクラウドを上書きし、他端末で配置した置物が消える**。対策として `visibilitychange`→visible で `fetchCloud`→**非破壊 union マージ**（`reconcileInitialCloud`＝`mergeCloudInitial` 経路）を挟み、最新の配置を取り込んでから操作・push を受ける（差分なしなら getDoc 1回で no-op）。併せて `mergeCloudInitial` の `itemLayout` をローカル固定→union に修正（placedItems だけ union して座標をローカル固定だと置物が既定位置に戻るため）。**本筋の field 別タイムスタンプ/世代管理は #233（匿名認証＋ルール）と合わせて別途**。union の副作用（一方で外した装備の復活）は初回同期と同じ既知トレードオフ。

> **設計判断（#226・Antigravity対称レビュー topic_1782737748350 で合意）**: ①装着の「slot排他1点」を置物に流用すると `equipItem`/`spentCoins`/`cleanItemLayout` が汚染されるため、**`placedItems` を新設**して装備と完全分離（排他なし複数配置）。②前面/背面の2層を**最初から**用意し `layer` で振り分ける——後から前面層を足すと catMarkup/DOM/dressup を再改修するコストが大きく、🛋️背面+🧶前面の2点で z5 までMVPで実証できるため。③座標は新フィールドを作らず `itemLayout` を共用（IDが装着系と重複しない前提でマージ規則の追加が不要）。

> **設計判断（#226・実装時の精緻化）**: 合意時は「`.cat` の兄弟として*ステージ全面*にscene-SVGを張る」案だったが、実装で `.cat-stage` が高さ指定の無い flex で**ステージが非正方（横長）**である一方、dressup の%基準（`#catStage` rect）と装着系の描画枠は正方 `.cat` であることが判明。ステージ全面に張ると非正方ゆえに `preserveAspectRatio` で画像が歪むかドラッグ追従がズレるため、**scene-SVGを正方 `.cat` 内（`cat__front` の兄弟）に置き**、装着系と同一の viewBox/座標系・dressupのドラッグ数学にそのまま乗せた。前後はDOM順＋z-index（back z1<本体z2、front z5>演出z4）で表現し、合意の意図（猫の前後・ドラッグ可・座標整合）をより素直に満たす。

### 猫の見た目（なつき度 tier・#167）

猫本体は **スタイル3種(style) × なつき度3段階(tier) × mood5種 = 45枚のプリレンダ透過PNG**（`img/cat/cat_{style}_{tier}_{mood}.png`・hiss は #187、style は #66 で追加）。style は tora（茶トラ・既定）/ shiro（白猫）/ russianblue（立ち耳グレー）。tier は既存の「なかよしレベル」(#124)から導出し、上がるほど表情・ポーズが親密になる。

| tier | なかよしレベル | 見た目 |
|---|---|---|
| low | Lv1〜2（ともだち／なかよし） | 控えめな表情 |
| mid | Lv3〜7（だいすき〜さいこうのなかま） | リラックス |
| high | Lv8（えいえんのきずな） | デレデレ |

> **設計判断（#167）**: ①旧 SVG 数式描画（kitten/young/adult のレベル連動ステージ）を**廃止**し、見た目の軸を **level → なつき度(affinity tier)** に一本化した（Issue要件「なつき度3段階で表情・ポーズが変化」に忠実。level はレベルバー・XP表示で存続）。②画像形式は当初 **透過PNG統一**（WebP はやめた。5歳児が使う旧 iOS Safari の互換リスクを避け `<picture>` フォールバック不要にするため）→ **#234 で WebP へ移行**（下記 #229/#234 の設計判断参照。iOS Safari 14+（2020〜）で WebP がネイティブ対応し 2026 時点で旧版シェアが実質消滅、フォールバック不要のまま容量削減できるため反転）。③閾値は**新設せず**既存5レベルを3 tier に集約して #124 を温存。④衣装・演出は猫本体に焼き込まず別レイヤーSVGで重ねる（#168きせかえの土台）。ロードは現 tier の4mood先行＋次 tier 境界の2pt手前で `requestIdleCallback` 先読み。

> **設計判断（#66・Antigravity対称レビュー topic_1781184658026 で合意）**: ①スタイル切り替えUIは**きせかえ編集モード内**（「見た目を変える」文脈で5歳児が自分で発見できる。ショップ解放は #126 と被るので将来拡張）。②命名は既存も含め **`cat_{style}_{tier}_{mood}.png` に全リネーム**（特例分岐を残さない。SWは gen-sw 再生成で旧キャッシュを自動破棄。茶トラ15枚は中身同一でもURL変更により一度だけ再DLされるが許容）。③**JSの preload は選択中スタイルのみ**。SW は `img/cat` 全45枚（~3.8MiB）をプリキャッシュするため、これはネットワークではなく**デコード/メモリの抑制**であり、オフライン中のスタイル切替も保証される。④立ち耳ロシアンブルーの衣装アンカーずれは生成側でポーズを無理に揃えず（体格バランスが崩れる）、`STYLE_ANCHOR_OFFSETS` で吸収する。納品画像の実測では頭頂（中央列）が tora/shiro=viewBox y31・russianblue=y35 と差4ユニット（ステージ2%）で軽微だったため**オフセットは空のまま**（手動ドラッグ #168 でも調整可。ズレが問題になったら値を入れる）。

### ストリーク（連続練習）とお休み券

- 前日に練習していれば連続。同日の二重記録はストリークを増やさない
- **お休み券（`streak.freezes`）**：ストリークがちょうど3日、および7日ごと（7・14・21…）に到達したとき +1枚付与（**上限2枚**＝`MAX_FREEZES`）
- 練習に間が空いたとき、抜けた日数ぶんのお休み券があれば消費して連続を維持（救済できなければ1からリセット）。**リセットされてもお休み券は没収されず維持される**
- お休み券で連続を守ったときは専用ポップアップで通知

> **設計判断**: ストリーク報酬は非対称。コインのマイルストーンボーナス（+10/+30）は **3日・7日に到達した瞬間のみ**で14日以降は付かない（インフレ抑制／オンボーディングの前倒し）。一方お休み券は **7日ごと**に供給し続ける（長期の維持モチベーション）。コインは `calcRewards`、お休み券は `isFreezeMilestone` と別ロジック。

## 猫の表示とインタラクション（[cat-image.js](../js/cat-image.js)）

- 猫本体は水彩タッチのプリレンダ透過WebP（style 3種 × tier×mood 15枚 = 45枚・#66／#234 で PNG→WebP）。コンテナ `.cat` に `img.cat__body`＋衣装(`cat__front`・全種前面 #211)＋演出(`cat__fx`：ハート/きらきら/Zzz/なかよしエンブレム)を別レイヤーで重ねる（衣装は #196 で SVG→水彩ラスター、演出は引き続きSVG）

  - 反応の種類（約15%で「シャー」＝威嚇、残りは「ニャー」）は `rollCatVoice()` が**音設定に依存せず**抽選する。鳴き声の再生（`playCatVoice`）は別関数で、サウンドOFFなら無音
  - 威嚇でなければ喜ぶ／しっぽふりの反応アニメ（ランダム）。**威嚇のときは喜び演出を出さず、`playHiss` が威嚇表情（hiss画像）への一時差し替えだけ行う**（#187。抽選を再生から分離しているため、ミュート中でも出し分けは同じく効く）
  - なかよしレベルが高いと、威嚇でないとき `bondCelebrateChance(level)` の確率で**特別演出**に格上げされる（#124）

## サウンド（[sound.js](../js/sound.js)）

- **効果音（シンセ）**：Web Audio API で生成。コイン獲得 / レベルアップ / 記録完了 / アイテム購入
- **スタンプ音階（#139, #154）**：ハンコは固定SEではなく `playStamp(index)` で鳴らす。ド=C4 を基準に Cメジャー音階（ド レ ミ ファ ソ ラ シ）で音程が上がり、目標マス（最後の1マス）は **Cメジャー主和音（ド・ミ・ソ）** で「シャラーン」と解決する。周波数の主音は平均律で計算（`stampSemitone`/`stampFrequency`、追加アセット0）、和音は `stampNotes(index)` が組み立てる（主音＝高いドに長三度・完全五度・1oct下ボディを重ねる）。再生は `playStamp`。
  > **設計判断**: issue #139 の実装例は半音上昇（`2^(index/12)`）だが、それでは「ドレミの音程感覚を養う」狙いが満たせないため、ダイアトニック（メジャー音階）を採用。目標マスは当初 単音の高いドで解決させていたが、半音オフセット列が index8→9 で 14→12 と逆行し、最も興奮する最終タップでピッチが下がる違和感があった（Antigravity との対称レビュー topic_1780484001568 で指摘）。これを **主和音化** で「豪華なごほうび演出」へ昇華させ、違和感を解消（#154）。pure 層（`stampSemitone`/`stampFrequency`）は主音=高いドのまま維持し、和音合成は再生側（`stampNotes`/`playStamp`）に閉じて責務分離を保つ。
- **鳴き声（録音サンプル）**：なでた時のみ。`meow1〜3.mp3`（通常）/ `hiss1.mp3`（威嚇）
- ヘッダーのトグルでON/OFF（設定は端末ローカル `settings.soundOn`、クラウド非同期）
- AudioContext はユーザー操作後に解錠（ブラウザの自動再生ポリシー対策）
- **省電力・自動 suspend（#146）**：効果音が鳴り終わってアイドルが続いたら（`IDLE_SUSPEND_MS`）AudioContext を `suspend()` し、音声ハードウェアを起こしっぱなしにしない。タブ非アクティブ時（`visibilitychange`→hidden）も `suspendAudio()`、復帰時に `resumeAudio()`。次の効果音再生で `getCtx()` が `resume()` するため状態は失わず体感遅延もない（モバイルのバッテリ節約）。

## アクセシビリティ・表示テーマ（#151）

- **prefers-reduced-motion 対応**：OSの「視差効果を減らす」設定時、猫の呼吸/ジャンプ/ハート等の演出（[cat.css](../css/cat.css)）に加え、スタンプの登場・オンボーディングのポップ・各種バーの伸び（[style.css](../css/style.css)）も停止する。ご褒美フィードバック（ハート/きらきら）は静止表示で残す。CSSのみで完結、JS不要・むしろ軽量。
- **ダークモード（夜の練習配慮）**：構造色を `:root` のセマンティック変数（`--surface`/`--surface-soft`/`--surface-mute`/`--pink-soft`/`--cream`/`--ink`/`--shadow`/`--text-muted`）に集約し、ダーク時はこの変数群だけを上書きする。ピンク/ゴールド等のアクセント色は両モード共通。
  - **切替**：せってい（親ゲート内）の「がめんの あかるさ」で **じどう / あかるい / よる** の3択。`じどう` は `@media (prefers-color-scheme: dark)` でOS設定に追従（`data-theme` 属性なし）、`あかるい`/`よる` は `data-theme="light"/"dark"` で明示固定。
  - **保存**：テーマは端末ごとの好み（夜配慮）なのでクラウド同期する state ではなく `localStorage['pp-theme']` に保存（`settings.soundOn` と同じ端末ローカル方針）。
  - **チラつき防止**：`index.html` の `<head>` インラインスクリプトで保存値（dark/light のみ）を描画前に `data-theme` へ適用。`auto` は属性を付けずCSSのメディアクエリに委ねる。
  > **設計判断**: 既存CSSは `#fff` 等のリテラル色が散在していたため、ダーク化はセマンティック変数への置換で実現。ライトでは各変数を従来リテラルと同値に定義し、見た目を完全維持（差分は無リスク）。`auto` で属性を外す方式により、JSでの `matchMedia` 監視なしにOSのライト/ダーク切替へ即時追従できる。

## せってい：データのバックアップ/復元（[backup.js](../js/backup.js)・#140）

ホーム ⚙️ →「おうちのひとへ」オーバーレイ。子の誤操作を防ぐため、まず簡単な掛け算（1桁×1桁の九九・`makeGateProblem`）の**ペアレンタルゲート**を出し、正解時のみメニューを開く。足し算だと子に突破されやすいため九九に変更（#166）。メニューは「アカウント」「きょうの きょく（宿題）設定」「がめんの あかるさ（テーマ・#151）」「データのバックアップ/復元」「データ初期化」のセクション（専用ナビ画面は増やさない）。

**アカウント切替（マルチアカウント・#182）**

検証用と実運用でデータを分けるため、有効アカウント（既定：娘／テスト用）を切り替える。純粋ロジックは [account.js](../js/account.js)。

| 操作 | 挙動 |
|---|---|
| ゲート通過時 | 有効アカウントと一覧を `renderAccountList` で描画（有効は「いま これ ✓」、他は「きりかえる」ボタン） |
| きりかえる | `setActiveAccount(id)` で有効アカウントを書き換え → `window.location.reload()`。storage の参照キーと cloud の購読 doc が新アカウントで貼り直される |

- データの分離は**保存先の名前空間化**で実現（localStorage キー＝`storageKeyFor`、Firestore doc＝`cloudDocIdFor`）。娘（`data`）は既存の `piano-pet`／`pianopet/data` を温存し既存データは移動しない。
- 認証は導入しない（家庭内ツール前提）。詳細・設計判断・Firestore ルール前提は [data-model.md](./data-model.md)「マルチアカウント」を参照。

**きょうの きょく（宿題）設定・#143**

> **閉塞中（#192）**: 先生はアプリの利用者として登場しない方針（#152）に伴い、しゅくだい登録UI（せってい内セクション・ホームのカード・達成演出）と「せんせいに おくる」共有ボタンは現在 UI 非表示。ロジック（`assignment.js`）・保存データ・クラウド同期（LWW）は温存し、`app.js` の `HW_ENABLED=false` と HTML の `hidden` で閉塞している。再開は容易。

先生の宿題を親が代理登録する。実装は純粋ロジック [assignment.js](../js/assignment.js)＋[app.js](../js/app.js)。

| 操作 | 挙動 |
|---|---|
| ゲート通過時 | 現在の宿題を `hwName`/`hwTarget`/期間トグルへ反映（`loadHwInputs`） |
| きめる | 曲名・目標回数・期間（きょう／こんしゅう）から `makeAssignment` で保存（`setAt` 付き）。曲名が空なら保存しない。ホームにカードが即反映 |
| けす | `items: []` のトゥームストーンで保存（他端末へも LWW 伝播）。ホームのカードは非表示に |

- MVPは**単一曲**の手入力（スキーマは配列だが入力・表示は先頭1件）。
- 期間 `こんしゅう` は月曜始まり（`weekStart`）で週次グラフと一致。
- 達成判定は `sessions` から導出（専用フラグ無し）。詳細・設計判断は [data-model.md](./data-model.md)「Assignment」を参照。

**データのバックアップ/復元（[backup.js](../js/backup.js)・#140）**

認証なし・匿名同期のため端末故障やブラウザデータ削除でデータが消えるリスクに備える安全弁。

| 操作 | 挙動 |
|---|---|
| データを ほぞん | 現行 state を `exportState()` でラップ JSON 化し `piano-pet-backup-YYYY-MM-DD.json` をダウンロード。無害なので確認なし |
| データを よみこむ | ファイル選択 → `parseBackup()` で検証 → 上書き確認 → 復元。検証 NG はひらがなで理由表示（壊れ/別アプリ/必須キー欠落/未来バージョン） |
| データを ぜんぶ けす | 確認 → 新品の `normalizeState({})` で上書き（猫の状態・アイテム・練習記録・宿題をすべて初期化）。#183 |

**復元フロー（クラウド競合対策）**: ①直前データを `piano-pet-backup-before-restore` へ自動退避 → ②cloud 購読を一時解除 → ③ローカル保存 → ④`pushCloud` 完了を await → ⑤`reload`。古いスナップショットによる巻き戻しを断つ。詳細・設計判断は [data-model.md](./data-model.md) の「バックアップ/復元」を参照。

**データ初期化（`resetData`・#183）**: 機種変更・配布前のテストデータ汚染をリセットする手段。復元フローと同一の安全手順をたどり、取り込み先が「新品の `DEFAULTS`」になるだけ。退避（`piano-pet-backup-before-restore`）も同じく行うため、誤操作してもこの localStorage キーから最後の手段で復旧できる。`settings`（音 ON/OFF 等の端末ローカル値）も既定へ戻る。
