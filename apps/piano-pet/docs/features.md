## 画面とナビゲーション

> 実装: [router.js](../js/router.js)・[app.js](../js/app.js) `render` ｜ テスト: e2e/navigation.spec.js

**仕様**

- ハッシュベースの SPA
- ボトムナビ5タブ：**ホーム / きろく / ショップ / バッジ / スタンプ**（スタンプは #409 で追加）
- 記録入力（record）はナビに出さず、ホームの「れんしゅうを きろくする」から開く。ナビはホームを選択状態に保つ（「なおす」からの編集中は きろく・#401）
- UI文言はひらがな主体（→ [requirements.md](./requirements.md) 4.3）
- **アプリアイコンのショートカット（#235）**：`manifest.json` の `shortcuts` に1件。`./index.html#/record` へ直行。アイコンは `icons/icon-96.png`

**設計判断（#235）**

- router は改修不要。起動時の `router.syncFromHash()` → `viewFromHash('#/record')` が `record` を返すので、ディープリンクは既存実装で成り立つ
- 足したのは manifest と 96px アイコン（`icon.svg` から生成）だけ
- **iOS/iPadOS は `shortcuts` 非対応**。短縮は Android/デスクトップ限定（iOS は1タップ多いだけで機能は欠けない）

## ホーム

> Issue: #121 #167 #187 #396 #399 ｜ 実装: [app.js](../js/app.js)・[cat-image.js](../js/cat-image.js)・[child-profile.js](../js/child-profile.js) ｜ テスト: tests/child-profile.test.js・e2e/child-avatar.spec.js・e2e/navigation.spec.js

**仕様**

| 要素 | 内容 |
|---|---|
| 猫イラスト | なつき度(tier)×mood のプリレンダ画像（`aria-live="polite"`）。装備・演出は別レイヤー（#167） |
| 猫の名前 | 初期値「きーちゃん」 |
| きょうの もくひょう | `○ / N かい`（N＝親が決めた目標・既定10・#238）＋進捗バー＋メッセージ |
| スタンプの進捗 | 押せるスタンプがあれば強調（→ [ねこスタンプちょう](#ねこスタンプちょう409)） |
| レベル / XPバー | 「あと○かい で レベルアップ」 |
| なかよしレベル | 「💖 なかよしレベル N（名前）」＋次のレベルへの進捗バー（#124） |
| ステータスカード | 🪙コイン / 🔥れんぞく / 🎫おやすみけん / 💖なかよし |
| しゃしん | 猫の下の「📷 しゃしん」（→ [写真モード](#写真モード237)） |
| サウンドトグル | ヘッダー右（🔊 / 🔇） |
| せってい | ヘッダー右の ⚙️ →「おうちのひとへ」（親ゲート） |
| こどものアバター | ヘッダー左に常設。絵文字アイコン＋なまえ（#121） |
| 記録ボタン | 「れんしゅうを きろくする」を下ナビの上に `position: sticky` で固定（#399） |

- 記録ボタンを固定しない場合：高さ 600px 未満（320x568・横向き）／きせかえ中（`toggleDressup` が `.is-dressup` を付け外し）
- 幅 〜420px では名前とタイトル「ピアノペット」の側を省略記号で縮め、右端の 🔊/⚙️ を押し出さない（#396）

**設計判断**

- **記録ボタンを固定した（#399）**：猫とステータスの下、約2画面スクロールしないと見えず、子どもが記録の入口に気づかなかった
  - 低い画面では きせかえ／しゃしん に重なり、きせかえ中は まえ／うしろ パネルを隠すので外す
  - `:has` は古い Safari/Firefox で効かないので使わずクラスで切り替える
- **記録画面の送信ボタンは固定しない（#399）**：固定すると開いた直後にスタンプカードの下段（6〜10マス目）を覆い、マスのつもりのタップで途中の回数のまま記録された（レビューで再現）。空送信のエラー文も画面外になる。代わりに目標回数に届いたら送信ボタンを画面中央へスクロールする
- **狭い幅で ⚙️ を守る（#396）**：320px＋長い名前で ⚙️ が切れ、親が設定に入れなかった

### こどものアバター（#121）

**仕様**

- home / きろく の両ヘッダの `.child-avatar` を `renderChildAvatar` が更新する
- **タップで選ぶ**：`#avatarOverlay` が開く。本人の操作なので**親ゲートなし**
- 絵文字10種（🐥🐰🐻🐼🦊🐸⭐🌸🦄👑・`CHILD_AVATARS`）。各選択肢に読み上げ名（ひよこ・うさぎ…・#397）
- なまえは最大12文字。入力中もヘッダへ即反映し、閉じるときに前後空白を落として確定する
- 保存先は [data-model.md](./data-model.md#pet) の `pet.childName` / `pet.childAvatar`。analytics には送らない

**設計判断**

- 「自分が主役」の自己効力感を出しつつ、本番アカウントとテスト用の見分けも兼ねる
- **顔写真は使わない**：認証なしの共有 Firestore に置くのでプライバシー上不可。絵文字なら軽く・同期でき・PII を増やさない

### 猫の mood

恒常表示は idle/sleep。happy/love/hiss は演出中だけの一時差し替え。

| mood | 条件 | 表現 |
|---|---|---|
| `idle` | 通常 | ゆっくり呼吸（scaleY） |
| `happy` | 記録直後 | うれしい表情＋ぴょんと跳ねる・ハート |
| `sleep` | 最後の練習から2日以上 | 目を閉じた表情＋Zzz |
| `love` | なでた時 | ハート目＋しっぽふり／喜ぶ |
| `hiss` | なで反応で威嚇を引いた（#187） | 威嚇の表情だけ。喜びの演出は出さない |

## 初回オンボーディング（#141）

> 実装: [onboarding.js](../js/onboarding.js)（見たかの印）・[onboarding-ui.js](../js/onboarding-ui.js)（文面・ステップ・DOM） ｜ テスト: tests/onboarding.test.js・e2e/onboarding.spec.js

**仕様**

- 初回起動時、猫の**吹き出し3画面**で「①きろく → ②ごほうび → ③きせかえ・ごはん」を案内する
- **新規アセットなし**（既存の `catMarkup` をカードに流用）
- 大きいボタン（スキップ／つぎへ・はじめる！）＋進捗ドット3つ
- **スキップ可**。どちらで閉じても `piano-pet-onboarded='1'` を立て、以後は出さない
- localStorage が読めない環境（プライベートモード等）は「見た」扱い
- 横向き（高さ 520px 以下）ではオーバーレイをスクロール可能にし、猫を縮める（#396）

**設計判断**

- **読めない環境は出さない側へ倒す**：うるさく出し続けるより無害
- **横向きの対応（#396）**：カードが画面より高くなって「つぎへ」が切れ、固定配置のためスクロールもできなかった
- **画面は遅延読込（#365）**：紙芝居は初回の1回しか使わないのに文面と DOM が js-entry に載っていた。印だけを entry に残し、**まだ見ていないときだけ**動的 import する
  - idle で毎回読む形（cloud.js と同じ）にしなかったのは、起動をブロックしないだけで帯域は毎回かかり、「idle 読みを増やしても total は動かない」（#284）の抜け道になるため
  - 実測：js-entry 76.1→75.1・total 96.0→95.0 KiB（js-lazy 16.7→18.2）

## 練習記録

> Issue: #117 #123 #164 #186 #252 #260 #273 #398 #399 ｜ 実装: [record-form.js](../js/record-form.js)（純粋ロジック）・[app.js](../js/app.js) ｜ テスト: tests/record-form.test.js・tests/game.test.js・e2e/record.spec.js・e2e/record-date.spec.js

### モードの切り替え

- 日付の下に「🐾 スタンプ / 📝 まとめて」の切替（`aria-pressed` のトグルボタン2つ・#397）。既定はスタンプ
- 日付は両モード共通で、既定は今日
- 切り替えると入力途中の内容を「曲×回数」に変換して引き継ぐ（`stampsToSongs` / `collectSongs` / `songsToStamps`）

**設計判断（#397）**：`role=tab` を名乗ると矢印キーでの切替を約束することになるのに、実装していなかった。トグルにした。

### スタンプモード（曲は親・スタンプは子・#117）

タイル状の「ハンコ」を押して回数を数える。子どもでも押せる。

| 操作 | 仕様 |
|---|---|
| きょくを えらぶ | 曲名チップを「最近ひいた順（最終練習日）→累計回数」で最大8件（`pastSongNames`・#252）。漏れた曲は新規入力欄の `datalist`（過去の全曲名）から選ぶ。各チップに曲の色、選択中はその色（#122） |
| いまの曲の表示 | スタンプカードの上に「🎵 いまは「曲名」」（#399） |
| ハンコを おす！ | タップで選択中の曲の🐾が1つ増え、押したマスは**その時の曲の色**で塗る。マス数は目標ぶん（既定10・5〜20・#238）＋常に1マス余分 |
| ↩ ひとつ もどす | 直前の1つを取り消す |
| 曲が1つも無いとき | 押すと「おうちの ひとと、うえの らんに きょくの なまえを いれてね」（#399） |
| 当日中の引き継ぎ（#164 #186） | ホーム往復でも0に戻らない（下書きキー・打鍵ごとの Firestore 同期はしない）。**記録したあとも当日なら**、当日の記録からスタンプを復元（`songsToStamps(combineSongs(...))`）して続きを押せる。日付が変われば下書きは捨てる（→ [data-model.md](./data-model.md#スタンプ下書きstamp-draft)） |

- 役割ガイドの文言は #189 で削除

**設計判断**

- **曲チップは直近順（#252）**：練習する曲は移り変わるので、累計順だといま練習中の曲が載らない
- **曲名の表示と空のときの案内（#399）**：前回の曲が選ばれたまま別の曲に押してしまっていた。曲が無いのに「えらんでね」と言われても選ぶものが無かった

### まとめモード（親の後追い入力・#123）

その場でスタンプを押さなかった日を、親が後からまとめて記録する。

- 1行＝曲名（`datalist` で過去の曲を補完）＋回数ステッパー（− / 数値 / ＋）
- 「＋ ぎょうを ふやす」で行を足し、各行の「✕」で消す
- 「ごうけい ○ かい」をその場で表示する。集約は `collectSongs`（空名・0以下は除く）

### 記録の確定（両モード共通）

- 合計0回は記録できない（`isValidSession`）。スタンプモードで曲が未選択ならヒントを出す
- 確定後の流れ

  1. コイン・XP・連続日数・バッジを計算して反映する（`applySession`）
  2. ホームへ移り猫が喜ぶ（→ [記録後のごほうび演出](#記録後のごほうび演出)）
  3. 獲得コインのポップアップ。レベルアップしたらその旨も出し、レベルアップ音も一緒に鳴る
  4. 効果音：記録完了 →（レベルアップ時）レベルアップ
  5. お休み券で連続を守ればその案内、新しいバッジがあればバッジの案内

- **何も増えていない**（同じ内容の再送信・回数を減らした修正）ときは祝わず、ポップアップは「✏️ きろくを なおしたよ」（#396）

### 日付と、同日・過去日の扱い

| ケース | 扱い |
|---|---|
| 今日 | 記録画面は「その日ぜんぶ」を表す。submit は追記ではなく**置き換え**（`isToday` 分岐・#186） |
| 同日に既存の記録がある | 統合して全再計算（`recomputeState`）。目標達成ボーナスの二重取りを防ぐ |
| 過去日（最終練習日より前） | 挿入＋`recomputeState`（日付昇順の再生）で連続日数を保つ（#260）。「きょうのおまけ」は抽選しない（`bonusCoins: 0`） |
| 記録済みの過去日を選んだ | 日付の下に「この ひは もう Nかい きろく してあるよ。いれた ぶんは たしざん されるよ。」（#398） |
| 未来日 | 選べない（`max=今日`）。手入力で入っても submit で今日へ丸める |
| ひづけ欄を変えた（#273） | その日付が本来始まるべき内容へ入れ直す（`onRecordDateChange`）。今日＝当日の記録／下書きから復元、今日以外＝空のカード。過去日の間は当日の下書きを書き換えない |

- 同日同曲の合算（#186）：きろくタブは `combineSongs` で同名の曲を1行にまとめる（既存の分割データも表示時にまとめる）。`mergeSameDaySessions` も統合時に `combineSongs` する

**設計判断**

- **当日は置き換え（#186）**：全内容を復元しているので、追記にすると当日の押し増しが二重に数えられる。置き換えなら同日同曲が1件に収まる
- **過去日は全再計算（#260）**：`applySession`→`updateStreak` は日付が時系列順に届く前提の逐次更新で、過去日をそのまま流すと連続が1に戻り `lastPracticeDate` も過去へ戻る
  - 新しい汚染を防ぐだけで、旧バグで戻った既存データの自動修復はしない（起動時の recompute は同日重複の統合時だけ）。クラウドの初回 reconcile か、次の記録・編集・削除で自己修復される
- **日付の変化を起点に作り直す（#273）**：#186 の復元と「過去日は合算」は、日付欄が変わらない前提で噛み合っていた。復元した当日ぶんを持ったまま過去日にすると**もう一度数えられる**（実測：今日5かい → おとといへ → セッション 5+5 の2件・コイン/XP とも 10）
  - 後追い入力の本来の導線はまとめモード（常に空）だが、スタンプモードのままでも操作できてしまうので、モードではなく日付の変化を起点にした
- **記録済みの過去日の案内（#398）**：気づかず二重に記録してコインが水増しされるのを防ぐ

### 曲の色（#122 #165）

> 実装: [song-color.js](../js/song-color.js) ｜ テスト: tests/song-color.test.js

**仕様**

- 曲名を FNV-1a でハッシュして色相（0〜359）を出す。彩度・明度は固定（`songColor` が `fill`/`tint`/`ink` を返す）
- **保存しない**。`sessions` が同じならどの端末でも同じ色。空名はグレー、前後の空白は無視
- **色かぶりの回避（#165）**：`assignSongColors(names)` が先頭から見て、既出の色相に近すぎる（**25°未満**）曲を隣へずらす
- スタンプ／チップ／コレクションは同じマップ（`buildSongColors`）を使う。並びは `songTotals` の順
- `songTotals` の同数の並び（#326）：最終練習日が新しい順 → 曲名のコードポイント昇順

**設計判断**

- **同数の並びを `sessions` 内の値で決める（#326）**：配列位置で決めると、`sessions` の並び（元の順／日付降順／先頭へ追加）が経路で変わり、同期のたびに色が入れ替わる。日付と曲名はどちらも `sessions` の中の値なので、「`sessions` が同じなら端末間で色が一致」が実際に成り立つ。この修正で既存ユーザーの色が一度だけ変わった（保存していないので移行は不要）
- **端末間で一致しない例外**：記録画面の `formSongColors()` だけは、端末ローカルの `chipNames`（まだ保存していない新しい曲名）を末尾に足す。未保存の曲が混ざっている間はずらし方が端末ごとに変わりうるが、記録して `sessions` に載れば一致する。保存フィールドを持たない方針（#122）を守るための許容範囲

### スタンプ音（#139 #154 #238）

- 押すたびに**ドレミ…と上がる**（1マス目＝ド）
- 目標マスは **Cメジャー主和音（ド・ミ・ソ）**で解決し、レベルアップ音を鳴らす
- 途中のマスは目標数に合わせて1オクターブ内へ割り振る
- **目標を超えても主和音のまま**（`stampSemitone` は `index >= goal-1` を解決音にする）＝「目標より先はぜんぶごほうび」
- 音の作り方は [サウンド](#サウンド)

**設計判断（#238・目標回数を可変にした `pet.dailyGoal`）**

- **保存先は同期される `pet`**：進捗・達成演出・マス数・音程は全端末でそろうべき。`settings`（端末ローカル）ではなく `pet` に置いた（`childName`/`catStyle` と同じでマージ規則の追加不要）
- **達成ボーナスは10回で固定**（`GOAL_BONUS_THRESHOLD`）：`recomputeState` は全履歴に `calcRewards` をかけ直すので、報酬を可変の目標に連動させると**過去の記録のコインまで増減する**（下げれば水増し・上げれば娘のコインが減る）。表示上の目標だけを可変にした
- **音程をマス数に合わせる**：旧実装は `12*floor(i/7)` でオクターブを無制限に積み、goal=20 では +31 半音まで高くなった。分母 `(goal-1)` で 0..6 の音度へ正規化し1オクターブに収める。goal=8 のとき途中がちょうど ド〜シ になる

| その記録で起きたこと | 猫の演出 |

| 今日の目標に**はじめて**届いた（`crossedDailyGoal`） | **必ず**動画クリップ。出せなければ CSS 演出（節目でもあれば `playCelebrate`、それ以外は `playHappy`） |
| 節目（レベルアップ／新バッジ／連続日数の節目） | `playCelebrate`（動画は出さない） |

### 記録の動画クリップ演出（#227）

> Issue: #227 #296 #300 #303 #305 #400 ｜ 実装: [cat-video.js](../js/cat-video.js)・[app.js](../js/app.js) `celebrateRecord` ｜ テスト: tests/cat-video.test.js・e2e/clip.spec.js・e2e/streak-milestone.spec.js・e2e/reward-sequence.spec.js・e2e/sw-clip-cache.spec.js

猫の上に**短い動画**を重ねて「次は何が出るかな」というごほうび感を日常に少しずつ差し込む。

**素材**

| 項目 | 内容 |
|---|---|
| 形式 | 720×720・1:1・muted・素材は約4秒。**2回ループで約8秒**見せる（#296） |
| 本数 | 猫スタイル3色 × 3本 = 9本（#300）。`video/cat_<style>_record_v<n>.mp4` |
| 動き（3色共通） | `record_v1`＝ぴょんと跳ねて両前足でバンザイ＋水彩のハート／`record_v2`＝くるっと体をひねって回る／`record_v3`＝おしりとしっぽを高く上げて大きくのびをする |
| 始まりと終わり | どれも同じ座りポーズで始まって終わる。畳んだ瞬間に静止画へ自然に戻る |

**出す条件**

| 条件 | 挙動 |
|---|---|
| 今日の目標にはじめて届いた | 確率を飛ばして**必ず**再生。達成後の追加記録は確率へ戻る |
| 節目（レベルアップ／新バッジ／連続日数） | 動画は出さず `playCelebrate`。3つとも「**その記録で**起きたこと」で判定する。連続日数は `streakAdvanced`（この記録で日数が伸びたか）も見るので、節目の日でも2回目以降の記録は通常の確率に戻る（#305） |
| それ以外 | `recordClipChance(なかよしLv)` の確率（[feed.js](../js/feed.js)） |

| なかよしLv | 1–3 | 4–5 | 6–7 | 8 |
|---|---:|---:|---:|---:|
| 確率（#296） | 25% | 40% | 55% | 70% |

**再生の仕様**

- **選び方（#300）**：`pickClip` は bag shuffle。そのスタイルの3本を混ぜた「バッグ」から1本ずつ配り、空になったら詰め直す。詰め直した先頭が直前と同じなら末尾と入れ替える。`rng` は引数で渡せる（テスト用）
- **2回ループ（#296）**：1回目の終わりで頭へ戻してもう一度再生し、2周目の終わりで畳む。通常は `ended` が駆動し、`ended` が来ない端末では尺経過タイマー（`duration + 0.4s`）が巻き戻す。最終保険は `duration * 2 + 1s` で `release`
- **タップでスキップ**：オーバーレイのタップで即フェード（ループ途中でも）
- **再記録**：動画中にもう一度記録したら前のクリップを畳んで次を再生する（前のタイマーが次を消さないよう `teardown` で片付ける）
- **ホームを離れたら畳む**（#400）
- **フォールバック**：未ロード／再生失敗（自動再生拒否・1000ms 以内に `playing` が来ない）／`prefers-reduced-motion` のときは CSS 演出（`playCelebrate` / `playHappy`）
- **読み込み**：**記録ビューかショップ（#294）に先に入ったとき** `requestIdleCallback` で `cat-video.js` を動的 import し、**次に出る1本だけ**を先読みする（`peekClip` がバッグの先頭を消費せずに覗く）
- **キャッシュ**：SW がクリップを cache-first で返す（#303）。先読みが間に合わなくても、`tryPlay` 自身の取得がキャッシュに入り次から即再生になる
- **音は常に muted**。効果音は `sound.js` に任せる（ON/OFF の二重管理を避ける）

**DOM とスタイル**

- `<video>` オーバーレイ（`#catVideo`）は `#catStage` の**外**（`.cat-stage-wrap` 直下）に置く
- `.cat` とサイズ指定（`width:80% / max-width:min(320px,90vw) / aspect-ratio:1/1`）を共有し、`.cat-stage` の `align-items:flex-end` + `bottom:0` で猫にピクセル一致させる
- 夜モードでは不透明な動画（背景 `#FCF2EC`）を**角丸＋影の「絵本のページ」**として見せる

**設計判断**

- **頻度と尺を上げた（#296）**：本番で5歳の利用者に触らせたところ「かわいいのでもっと見たい」「短くて見逃す」。#227 の方針（まれな節目ではなく日常にちょこちょこ）の範囲で、確率を 12/20/30/40% → 25/40/55/70%、視聴を1周（約4秒）→2周（約8秒）にした
  - 節目でクリップを出さない（`playCelebrate` を残す）判断は #227 のまま
  - `video.loop` は使わず明示的に1回だけ巻き戻す。`loop=true` だと `ended` が来ず、終了検知・世代管理（`_clipGen`）・張り替え時の `teardown` が崩れる
  - Lv1 から出すのは、記録が1日数回しかなく、始めたばかりの子が一度も見られないのを避けるため（なでなでの `bondCelebrateChance` は Lv4 から）
- **1スタイル3本にした（#300）**：確率を70%まで上げた結果、同じ映像ばかりでごほうび感が薄れた
  - 追加の2本は色や小物ではなく**シルエットの動く軸**で選んだ（v1=縦に跳ねる／v2=回転／v3=前後にのびる）。小画面で5歳が一目で「ちがうのが出た」と分かるのはこの違いで、浮かぶ小物を変える程度では同じに見える（水彩の音符を浮かべる案は不採用）
  - **動作は3スタイル共通**（同じごほうびだと伝えるため。1動作＝3本セット）
  - **目標達成と通常記録は同じプール**。分けると「必ず再生」の枠に一番良い動きを当てられるが、専用素材がさらに3本要り、重量も生成コストも倍になる。分けるのは将来レア枠（例：蝶が飛んできて鼻先にとまる）を作るとき
  - **先読みは1本だけ**。3本を idle で全部取りに行かない（現在のスタイルの3本で約 390 KB）。この都合で `pickClip` は純関数でなく**バッグを消費する**。再生に失敗しても消費したままにする（巻き戻すと先読みした1本と次の再生がずれる方が害が大きい）
- **節目は状態でなくイベントで見る（#305）**：`STREAK_CELEBRATIONS.has(streakCurrent)` は「連続日数がその値のあいだ」ずっと真になる**状態**で、`leveled`（前後のレベル差）や `badgeCount`（`newlyEarned` の件数）のような**イベント**と意味が揃っていなかった
  - そのため節目の日（3/7/14/30/50/100日目）は**その日の全記録**が節目扱いになり、目標到達の1本を除いてクリップが一本も出なかった（6日に1回、#296 で上げた確率が丸ごと無効になる日があった）
  - `commitState` の前に取った `prevStreak` と比べて「この記録で伸びたか」を渡す（`prevCoins`/`prevLevel`/`prevBadges` と同じ取り方）。特別演出が一日中出っぱなしで薄まる問題も消えた
- **`#catVideo` を `#catStage` の外に置く**：`renderHome` は `#catStage` を `innerHTML` ごと差し替える（クラウドの `onSnapshot` でも走る）ので、中に置くと再生中に他端末が保存すると動画が消える
- **透過動画は使わない**：VP9 alpha / HEVC alpha は Chrome と iOS Safari で形式が割れ、2ファイル要る。実機で違和感が出たら再検討
- **動画はリポジトリ同梱＋静的配信**：`apps/piano-pet/video/` に置き、Vercel の rewrite（`/piano-pet/(.*)`）で配る（えさやりクリップ #294 も同じ）
  - 当初案の Firebase Storage 外部配信は不採用。(1) プリキャッシュ（gen-sw の `APP_SHELL`）と予算の判定は [piano-pet-assets.mjs](../../../scripts/piano-pet-assets.mjs) の `listAssets()`（`css/ js/ icons/ img/cat* sounds/`）だけを見ており、`video/` はどちらにも載らない。「同梱すると SW が太る」という前提が事実と違った (2) Storage は Blaze 課金と、セキュリティルールの版管理の課題（#266）を1つ増やす
  - `img/` に 3.6 MiB のバイナリがある以上、同梱は方針と矛盾しない
  - **再検討の条件**：クリップが十数本を超えて git が重くなったら Storage へ移す。#294 で18本・約 3.8 MiB になり本数では条件に届いたが、総量は `img/` と同程度で clone も重くないので据え置いた（次に足すときに改めて判断）
  - `_v1`〜`_v3` の別名（`_v2b` 等）は「差し替え履歴ではなく動作のバリエーション」（#300）を区別する命名で、キャッシュを更新する手段ではない（→ [Service Worker](#service-worker-のキャッシュ戦略)・#318）
- **#227 で入れなかったもの**：bag shuffle（当時は1スタイル1本。#300 で実装済み）／クリップ図鑑（視聴済みフラグが `storage.js`・同期・`recomputeState` に波及するので別issue）／えさやりへの展開（#294 で実装済み）

### ポップアップ演出

> Issue: #261 #294 #309 #320 #323 #396 #400 ｜ 実装: [app.js](../js/app.js) `showPopup` ｜ テスト: e2e/reward-popup.spec.js・e2e/reward-sequence.spec.js・e2e/uiux-bugs.spec.js・e2e/shop.spec.js

**種類**：獲得コイン ／ えさやり（もぐもぐ・クリップ #294）／ きょうのおまけ ／ お休み券キープ ／ バッジ獲得

**仕様**

| 項目 | 内容 |
|---|---|
| 記録後の順番 | コイン → おまけ → お休み券 → 新しいバッジ。2.2秒おきに順に出す |
| クリップとの順番（#400） | クリップを出すときは**見終わる（タップでスキップ）まで出さない**。`celebrateRecord` が「出してよい」合図の Promise を返し、`tryPlay(style, onDone)` の `onDone` で解決する（クリップが出せなければすぐ解決） |
| バッジが複数（#400） | 2つまでは順に、3つ以上は2つ目以降を1枚にまとめる |
| 記録以外のバッジ | 購入直後（300ms後）・えさやりポップアップが閉じた後（クリップ再生時はその終わり・#294）・はなまる／テンポを付けた直後（300ms後）にも `showBadgePopup` を出す（`checkBadges` の即時再判定・#309 #320） |
| タップで送る（#400） | 表示中（`.coin-popup--show`）だけ `pointer-events: auto`。タップで閉じて次へ（`showPopup` が `popup.onclick = hide`）。表示中は下の画面のボタンに届かない |
| 前のポップアップ | 別のポップアップを出すとき、残っている前のものは即座に畳む（`dismissOtherPopups`・#396）。クリップ再生中のえさやりカード（`.coin-popup--clip`）は畳まない |
| 早く閉じる | `showPopup` は `duration` を待たずに閉じる関数を返す（えさやりクリップの終了・スキップで使う・#294） |
| 確定 | `duration` 経過後、`transitionend` と `setTimeout(finish, 300)` の早い方で `hidden` にする |
| 記録クリップ中の重ね順 | `body.cat-clip-playing` の間は `#feedPopup` 以外の暗幕を透明にして猫を前に出す |
| 再記録したとき | 前の記録の「見終わった」通知は捨てずに流す（`startClip` が前の `_clipDone` を呼ぶ）。前の記録のポップアップが次のクリップ中に出ると、クリップの裏に回る |

**設計判断**

- **クリップを見終わってから出す（#400）**：以前はクリップの裏へ回していた（`body.cat-clip-playing` で暗幕を透明化）ので、ホームのカードは画面外で、もらったコイン数・バッジ名が子どもに見えなかった
  - 「動画とポップアップを並べて出す」案は、動画が猫ごと覆う約8秒のあいだに 2.2秒のポップアップが流れ去るので不採用。待つぶん最大約8秒遅れるが、記録直後に猫の動画が主役になる体験は変えない
  - ホームを離れたらクリップを畳むのは、見えないまま保険タイマー（約9秒）まで待ち、移った先の画面にポップアップがまとめて出ていたため
- **表示は `showPopup(popup, duration, onHidden)` に一本化（#261）**：`transitionend` の once リスナーを素朴に張る旧実装は、連続表示（えさやり連打等）で前回のリスナーが残り、新しいポップアップを表示アニメの transitionend で途中で消していた。要素ごとにタイマー・リスナーを張り替え、バッジの連続表示は `onHidden` の連鎖にした
- **畳んだ側の後続を回す（#396）**：購入で出たバッジが、続けて押したえさやりのカードに半透明で重なり、どちらも読めなかった
  - 畳むだけだと、畳まれた側の `onHidden`（バッジの連鎖 `showNext`・えさやり後のバッジ告知 `flushFeedBadges`）が失われ、取ったバッジの告知が二度と出ない（レビューで指摘）
  - そこで畳んだ側の `onHidden` と、その側が預かっていた分を新しいポップアップの cycle（`deferred`）へ移し、新しいものが閉じたあとに実行する。新しいものの `onHidden` が同じ要素で続きを出した（バッジ連鎖）ときは、預かり分をその次の cycle の後ろへ送る
  - 不採用：全ポップアップをキューで直列化する（記録後の並びは setTimeout で組んでおり作り直しが大きい）／重なりを許す（読めないまま）
  - 退行テストは e2e/uiux-bugs.spec.js（後続を回さない実装で落ちることを確認済み）
- **`[hidden]` を CSS で明示する**：`.coin-popup`（[css/style.css](../css/style.css)）は `position:fixed; inset:0; display:flex` を持ち、author の `display:flex` が UA 既定の `[hidden]{display:none}` を上書きしていた。`hidden` でも画面全体を覆う要素が残り続けた（`opacity:0`・`pointer-events:none` なので見た目と操作には出ず、長く気づかれなかった）
  - 実害はアクセシビリティ：5要素（`#coinPopup`/`#feedPopup`/`#bonusPopup`/`#freezePopup`/`#badgePopup`）とも `role="status" aria-live="polite"` なので、常にアクセシブルツリーに出ていた（`getByRole('status')` の実測：是正前は idle 時も常時5件 → 是正後は表示中の1件だけ）
  - `.coin-popup[hidden] { display: none; }` を足した（属性セレクタぶん詳細度が高く確実に勝つ）。Playwright の `toBeVisible`/`toBeHidden` も正しく効くようになった
- **reduced-motion の保険タイマー**：`hidden` の確定を `transitionend` だけに頼っていたので、`prefers-reduced-motion: reduce`（`transition: none`）では `transitionend` が来ず、`hidden` が立たないうえ、`showBadgePopup` の `showNext` 連鎖が1件目で止まり2件目のバッジが出なかった
  - 再現は `page.emulateMedia({ reducedMotion: 'reduce' })`。`test.use({ reducedMotion })` はこの Playwright/ブラウザの組み合わせでは `matchMedia` に反映されず使えない
- **未検証の懸念（スクリーンリーダーの読み上げ）**：各 `show*Popup`（例 `showCoinPopup`）はテキストを入れてから `showPopup`（`hidden=false`）を呼ぶ。是正後は「`display:none` の間に書き換えてから出す」順になり、live region として実際に読み上げられるかは未検証（`getByRole('status')` は露出を見ているだけ）。実機で確かめるか、テキスト設定を `hidden=false` の**後**に動かすかは別issue

**れんしゅうカレンダー（#236）**

- 日ごとの練習量を色の濃さで見せる。日曜起点の CSS グリッド
- 濃さは4段階：0 ／ 目標の半分未満 ／ 半分以上〜目標未満 ／ 目標達成（**目標に追従**・`heatLevel(count, goal)`）
- 前月・翌月へ移る（`shiftMonth`）。今日は枠で強調、レッスン日（#393）は🎹
- 練習しなかった日は白抜き、先の日は枠なしで日付だけ
- 記録のある日は `<button>`。押すとその日の記録カードへ移る（一覧の表示件数の外なら広げる・#401）

**編集と削除**

| 操作 | 仕様 |
|---|---|
| なおす | record 画面に移り、スタンプカードへ内容を復元して編集する（`songsToStamps`）。編集中のナビは「きろく」 |
| なおす → もどる／保存 | きろく の元のスクロール位置へ戻る（#401）。日付を変えて保存したら、直した記録へ移る |
| なおす中に他端末で消された | 案内を出して編集状態のまま（再送信で新規記録にしない）。もどるは きろく へ |
| なおす で日付を変えた | **元の日付も墓標に残す**（#358） |
| けす | 確認（コイン・レベル・れんぞく日数も減ると書く）のうえ削除。日付は `deletedDates`（墓標・#319）に残る |
| けした直後 | 5秒間「もとに もどす」のトースト（#398）。その間は一覧から隠すだけで削除は確定しない |
| 削除の確定 | 期限切れ／別の操作で保存（`commitState`）が走った／画面を移った／せっていを開いた／アプリが裏に回った（`pagehide`/`visibilitychange`）。当日分を消して確定したらスタンプの下書きも消す |

- どちらも **sessions を唯一の正として XP・レベル・コイン・連続・バッジを全再計算**する（`recomputeState`）。報酬の演出は出さない
- 端末の戻るボタンと、編集中のナビ「きろく」は通常の遷移なので先頭へ戻る

**設計判断**

- **専用データを持たない（#236）**：カレンダーは `sessions` から毎回導出するので、同期・移行が要らずズレない。描画は SVG ではなく CSS grid（セルが多く、グリッドの方が軽くレスポンシブ）
- **カレンダーの色（#407）**：白抜きは少ない日の淡いピンクと見分けるため。先の日を `opacity` で薄くすると 1.75:1 で読めなかった
- **はなまると質メモは同じ作り（#239）**：praise をテンプレートに Session へ1フィールド足し、CSS も共通にした。実装は `setSessionMark`/`markRowMarkup` に統合（#261）。付ける／外す → 保存 → クラウドへ即送信 → `renderHistory`。報酬に関係しないので再計算は要らない。自由記述は持たず、analytics にも絵文字の種類以外を送らない（#145 と同じ）
- **付与値は統合・マージで残す（#315）**：→ [data-model.md の Session](./data-model.md#session)
- **一覧は14件ずつ（#360）**：全件だと1件約 290px・14日で 4,500px（実測）、1年で365枚になる。一覧の下端と最後の記録の操作がたどれず、はなまる1つで全件の innerHTML を組み直していた。14件＝直近2週間
  - `data-index` は元配列の index のままなので、足した行の操作も正しい記録に当たる（e2e/history-list.spec.js）
  - ボタンは親メニューの `settings-btn` を流用し、CSS を増やしていない（css 予算の余白が無い）
- **編集対象は日付で持つ（#314）**：配列 index で持つと、フォームを開いたまま画面を離れて戻る間に同期で `state.sessions` の並びが変わり（`mergeCloudInitial` は日付降順／realtime はクラウドの順／過去日は先頭へ追加）、**別の日の記録を上書きして消す**
  - 記録は「同日1件」なので日付が主キーになる（`editingDate`）
  - `applyRemoteState` 側で index を補正する案は、並び替え経路が3つあり増えるたびに補正を足し忘れるので不採用
  - 編集開始時の日付（`editingDate`）と入力欄の日付（変更後）は別物として扱う
  - 編集対象がリモートで消えていたら（`findIndex < 0`）別の記録を壊さず `#recordError` に案内を出す
- **元の場所へ戻す（#401）**：もどるがホームへ行き、長い一覧を入り直していた。続けて別の日を直せるようにした
- **削除の確定を遅らせる（#398）**：すぐ確定して取り消しで元に戻す方式は不採用。クラウド送信の待ち（2秒）が猶予（5秒）より短く、墓標が先に他端末へ届くと、戻した記録が他端末からの union で消し直される
  - 猶予のあいだカレンダー・集計は元のまま（除くのは一覧だけ）
  - 画面を移ったら確定するのは、保留のまま記録画面を開くと消した当日分がフォームに戻ったり、同じ日の再記録がその日ごと消えたりするため
  - せっていを開いたら確定するのは、アカウント切替・読み込み・初期化の reload で `pagehide` が別アカウントの保存先へ確定してしまうため（レビューで指摘）

**設計判断**

- **買う前に確認する（#421・ユーザー決定）**：#398 では「2段階の確認はテンポを落とす」として、買った直後に5秒間「やっぱり やめる」を出す取り消し方式だった。子どもは買えた時点で満足してトーストを読まず、5秒で消えて戻せなかった。何日も練習して貯めたコインの買い間違いは、確認1回の手間より重い
  - 「はい／いいえ」だけにせず、**のこりコインを見せて判断材料にする**（反射で押すだけの念押しにしない）
  - 値段で確認の有無を分ける案は、子どもには「ときどき聞かれる」方が分かりにくいので不採用。全アイテムで確認する
  - えさの「あげる」は安く何度も使うので確認しない
  - 購入の取り消しトーストと、そのためのクラウド送信の猶予（`holdCloudPush`）は購入では使わなくなった（レッスン日の解除・記録の削除の取り消しはそのまま）
- **連打で着替えまで進んでいた（#396）**：無言で無視すると分かりにくいので、見た目でも押せないと示す
- **ロック品を後ろへ（#399）**：序盤は45品中7品しか買えず、ロック品の間に埋もれていた。カード内の「🔒 なかよしLv○」はボタンと重複するのでやめた。ごほうび一覧は読み物で、きせかえ アイテムを約1.5画面下へ押し出していた
- **「あと ○ コイン」（#360）**：一律の「コインが たりない」は5歳には「だめ」の表示で、なかよしロックと違って次の目標にならなかった。1かい＝1コインなので、不足額がそのまま「あと何回れんしゅうすれば買えるか」の目安になる（達成ボーナス等で実際はもう少し早い）
- **価格は一律半額にした（#250）**：1日10回で15コイン前後の獲得ペースに対し、旧価格では最初のリボンに3日超・王冠に20日かかり、幼児の集中と噛み合わなかった。半額でも全価格が5の倍数に収まり、価格の段階（レア度）は変わらない
  - 既存ユーザーのコインは、`spentCoins` が支払額でなく**現行価格から毎回導出**されるので、次の `recomputeState` で `coins = 獲得総額 − 現行価格の購入総額 − foodSpent` になり**差額が自動で返る**。「コインは sessions から導出」という不変条件の帰結なので、購入価格の記録も移行も作らない
  - えさ（`foodSpent`）は消費済みなので返さない＝**装備は資産・えさは消費**
- ⚠️ **価格は下げる方向にしか変えない**：同じ仕組みが値上げでは逆に働き、**既存ユーザーのコインを黙って減らす**（極端には `Math.max(0, ...)` で0）。`SHOP_ITEMS` / `FOODS` の `price` を上げてはならない。必要なら支払額を記録するフィールドと移行（→ [data-model.md](./data-model.md#5-マイグレーション)）をセットで行う
- **受容した過渡期のリスク（#250）**：デプロイ直後に旧価格と新価格の JS の端末が混ざると、`spentCoins` が端末ごとに違ってコインが行き来する（realtime の `mergeCloud` は受信値を採り、起動・復帰時の `reconcileInitialCloud`/`resyncFromCloud` は現行価格で出し直して push し合う）
  - sessions・inventory（唯一の正）は無傷で消えず、両端末が新しい JS になれば収束する。各端末で一度アプリを開けば終わる（bridge-chat topic_1784289217445 で合意）
  - 購入価格を state に固定する案（`spentCoinsTotal`）は不採用。旧価格を知らない新 JS 側で基準値を作れず、旧 JS の push での欠落も自己修復しない＝自己修復する一過性の問題を、自己修復しない恒久リスクへ置き換えることになる
- **アイテムを廃止するとき（#326・方針だけ）**：`spentCoins` は所持品を現行の `SHOP_ITEMS` から引くので、定義から消すと `spent` が下がり、次の `recomputeState` で**コインが勝手に増える**（価格改定と同じクラス）
  - 方針：定義から消さず `retired: true` を立てて `price` を残す（一覧には出さないが `itemById`/`spentCoins` は引ける）
  - `checkBadges` の `first_outfit` も `itemById(id)` が引けるものだけを見る（#326 で未知IDを弾く修正済み）
  - いま廃止予定は無いので未実装

**設計判断（#294）**

- **ショップの中で食べる猫を見せる**：#347 の「ホームへ戻った瞬間に、えさが猫の口元へ飛んでもぐもぐ」（`playFeed`）は廃止。「ポップアップのもぐもぐが何か分からない」「戻ったときの再生が一瞬で分からない」と言われた
- **毎回出す**：原案（記録クリップと同じく確率）は不採用。えさやりはこのクリップが主役で、外れると分かりにくい演出に戻る
- **えさ別に作る**：選んだえさを食べることで「これをあげた」が伝わる（共通1本だとケーキでもお皿の中身が同じ）
- **1周で足りる**：素材が8秒あり、記録クリップの2周（#296）と同じ視聴尺になる
- **静止カードのまま閉じる場合**：モジュールの読み込みが遅く静止カードが閉じきってから再生が始まったとき、開き直すとバッジ告知が2回走る
- **再生開始の上限を記録クリップ（1秒）より長くする**：待つ間も静止カードが出ていて間延びしない

- **告知をキューに積む**：連打で前回のポップアップが張り替えられると前回の `onHidden` は呼ばれないので、えさやり1回ごとに告知を結び付けると取りこぼす
- **先読みは3本**：どのえさが押されるか分からず、3本で約0.6〜1.1 MB（実測 shiro 0.63／tora 0.80／russianblue 1.08 MB）に収まる
- **再生中に「あげる」を押させない**：連打で見ないうちに次へ進まないため
- **`startClip` は src を関数で受ける**：記録クリップのバッグを、mp4 非対応の端末で無駄に消費しない
- **`#feedPopup` を暗幕の透明化から除く**：記録クリップの直後にえさをあげると、えさやりの暗幕まで消えていた
- **生成**：Google Flow。開始フレームは Nano Banana 2.1 で `mid_idle` にえさのお皿を描き足した静止画、動画は Veo 3.1 Lite（9:16 の中央 720×720 を切り出し）。耳の形は**スタイルごとに開始フレームのまま保つ**よう指示する（tora／shiro は折れ耳、russianblue は立ち耳。全色に「折れ耳」と書くと russianblue が折れ耳になったり、途中で変わったりした）

### 品質基準（#191・#126 へ引き継ぎ）

子ども＝「一目で何かわかる・買った絵文字と一致」、親＝「練習の対価として段階的に豪華」を両立する。新しいアイテムはこれを満たしてから足す。

**設計判断**

- **SVG からラスターへの移行（#196）**：`cat-image.js` の `ITEMS[id]()` を `<image>` を返す形に置き換え、`sw.js` のプリキャッシュへ足した（`gen-sw`）。box は移行前の手描き SVG の描画範囲を引き継いで見た目を保った

  - WebP は iOS Safari 14+（2020〜）対応で、2026年時点で旧版は実質いないため `<picture>` のフォールバックは置かない（#167 の PNG 統一を反転）。全61枚のデコードを実測確認。演出・グラフの SVG は対象外

- **環状アイテム（#241）**：`collar`/`bell`/`flowerCrown` は本来一周する輪だが、#211 で全アイテムを前面へ回した結果、**背面の帯まで猫の手前に出て**不自然だった。背面の帯を別レイヤーに描く案は、不透明な本体に隠れる（#211 で断念した理由と同じ）ので不採用。「前から見える弧だけ」に描き直した（`ITEM_BOX` 据え置き・コード無改修）

  - コードは `SHOP_ITEMS`・`ITEM_BOX`/`ITEM_ANCHOR_TYPE`/`SCENE_BOX` への追記だけで、購入・装備・配置・同期は無改修。**新規追加なので既存ユーザーのコインに影響しない**（#250 の⚠️の対象外）
  - 画像は Google Flow（Nano Banana 2.1・1:1）で水彩の単体画像を作り、白背景を端から塗りつぶして透過 → **box×3** の WebP（quality85）

| 位置スナップ | **廃止**（#214）。落とした座標をそのまま記録。範囲外はステージ内へ clamp。スロットはまたがない |
| ピンチ（#205） | 2本指の距離の比で `scale` を変える。**絶対値**で `0.3〜3.0` に clamp。基準スケールの ±5% 以内なら基準へ吸着。2本指の距離が **10px** 動くまで拡縮しない。ピンチ中は位置を固定 |
| 押せる大きさ（#215） | 各 `<g>` に透明なヒット矩形（`.cat__item-hit`）を**逆スケール**で入れる（`width=max(box, MIN_HIT_UNITS(44)/scale)`）。拡縮後も画面上で約66px以上。見た目は変わらない |
| なでとの競合 | 編集中は `petCat` を止め、猫の周りを点線で囲う |
| スクロール中のドラッグ（#288） | 座標変換のたびに `pointermove` ごとに `getBoundingClientRect()` を取り直す |
| 掃除 | `commitState` の `cleanItemLayout` が、付けていない衣装の座標を消す |
| 編集モードの開始 | `cat-stage--editing` は `dressup.js` を読み込んでから付ける（#284） |

**設計判断**

- **座標は別フィールド（#168）**：`equippedItems`（id 配列）に埋め込まず `pet.itemLayout` に分けた。`shop.js`/`equipItem` 系のロジックとテストを残し、状態遷移にバグを入れないため
- **scale は絶対値（#205・topic_1782030433684 で合意）**：乗数（`a.s × k`）だと、将来アセットを直して `a.s` を変えたとき配置済みの衣装のサイズまで変わる。絶対値ならユーザーの意図が守られ、`pos?.scale ?? a.s` で後方互換
  - 定位置に戻しても座標は焼き込まず `{scale}` だけ持ち、位置は描画時にアンカーから引く
  - 5歳向けの補助は**基準スケールへの吸着とピンチ開始のデッドゾーンの2つだけ**。clamp で上下限は安全に止まるので、枠線の色分けは入れない
- **位置スナップを廃止（#214・topic_1782394334271 で合意）**：「思った位置に置けず勝手に戻る」が操作ミスのように感じられ、自由配置の意図に反した。**サイズの吸着（#205）は別物**（行き過ぎた拡縮をきれいなサイズへ戻す補助）なので残した
- **ヒット領域はマークアップで確保（#215・同 topic）**：JS の最近傍探索ではなく逆スケールの透明矩形にした。①ブラウザ標準のポインタイベントと SVG の描画順（DOM順＝上が優先）にそのまま乗り、重なったときの挙動が素直 ②位置・サイズを別に同期して距離を計算するコードが要らず `cat-image.js` に閉じる。`MIN_HIT_UNITS=44` は実機で調整できる1つの定数
- **cape を前面へ（#211・同 topic）**：背面だと不透明な本体に完全に隠れて「見えない・掴めない」。背面のまま端だけ覗かせ本体を `pointer-events:none` にする案は、見えないことを解決できず、なで反応にも響くので不採用。`cat__back` SVG は撤去した。cape の**アンカー種別（`back`）は変えず**、描くレイヤーだけ変えた
- **掴んだ時点の矩形を使わない（#288）**：キャッシュするとドラッグ中のページスクロール（ホームは縦長）で落とす位置がずれる
- **クラスを読み込み後に付ける（#284）**：クラスが付いた時点でドラッグが必ず効く＝「編集モードが使える」合図になる

### まえ／うしろの切り替え（#270）

> 実装: [app.js](../js/app.js) `renderLayerPanel`・[cat-image.js](../js/cat-image.js) `itemLayer` ｜ テスト: tests/cat.test.js・e2e/dressup.spec.js

**仕様**

- 編集モード中だけ、猫の下に**まえ／うしろパネル**（`#layerPanel`）を出す
- 付けている装着＋置いている置物が2段に並ぶ。チップをタップすると反対の段へ移り、猫の描画も同時に入れ替わる
- 何も無いときは「まだ なにも つけていないよ。ショップで かってね」と「🛍️ ショップへ」（押すと編集モードを終えてから移る）。あるときは「タップすると まえ／うしろ が かわるよ」（#399）

| 項目 | 仕様 |
|---|---|
| データ | `pet.itemLayout[id].layer`（`'front'`/`'back'`）。未設定・未知値は既定（装着＝前面 #211／置物＝`SCENE_BOX[id].layer`）＝既存ユーザーの見た目は変わらず移行不要 |
| 未知IDは出さない（#312） | `equippedItems`/`placedItems` はクラウド由来で任意の文字列が入りうる。パネルは `itemById(id) \|\| isSceneItem(id)` を通ったものだけ並べ、`data-item`・`aria-label`・アイコン・名前はすべて `escapeHtml` する |
| 描画 | `catMarkup` が実際のレイヤーで振り分ける。うしろは装着・置物とも背面 SVG `cat__scene--back`(z1)（置物→装着の順＝背面同士では装着が猫寄り）。まえは装着 `cat__front`(z3)／置物 `cat__scene--front`(z5)。**層は増やさない** |
| 背面の中の重なり | 前面と同じ「cape が最下層 → neck/head/face」。`equippedItems` の並び（付けた順）に左右されないよう2回に分けて描く |
| 編集中の本体 | 半透明（`opacity:.55`）にして、うしろへ送ったものを透かす。#240 の pointer 透過と合わせ、背面のままドラッグ・ピンチできる |
| ドラッグとの両立 | dressup は落としたときに `itemLayout[id]` を作り直すので、`layer` だけ明示的に引き継ぐ |
| 外したとき | `cleanItemLayout` がエントリごと消すので `layer` も既定へ戻る |
| 写真（#237） | 無改修で追随する（DOM の z 順をそのまま読む） |

**設計判断（#270）**

- UI は**ジェスチャでなく一覧パネル**。ダブルタップ／長押しはドラッグ（#168）・ピンチ（#205）とぶつかり、幼児の誤操作が「アイテムが猫の裏に回って消えた・戻せない」に直結する。パネルは常に全アイテムを並べるので**必ず戻せる**
- タップで選んで反転ボタンを出す案は直接操作として自然だが、タップとドラッグの判別と、再描画をまたぐ選択状態の復元が要り、dressup.js の改修が操作性の差に見合わない
- 状態は新しいフィールドを作らず `itemLayout` の1キーにした（`cleanItemLayout` の掃除・同期・union マージ #242 をそのまま使える）
- 背面の描画先も**新しいレイヤーを足さず** `cat__scene--back` を共用（層を増やすと catMarkup・CSS・写真合成の3か所を直すことになる）
- 「🛍️ ショップへ」で編集モードを終えるのは、残すと戻ったとき猫をなでられないため（#399）

### 猫スタイルの切り替え（#66）

> 実装: [app.js](../js/app.js)・[cat-image.js](../js/cat-image.js) ｜ テスト: tests/cat.test.js・e2e/cat-interaction.spec.js

**仕様**

- 編集モード中だけ**スタイルピッカー**（`#stylePicker`）を出す。ちゃとら／しろ／ぐれー（ロシアンブルー）の3種を `pet.catStyle` に保存して同期する。未定義は `'tora'`
- サムネイルは本番の `cat_{style}_low_idle` をそのまま使う。ピッカーを開いた時点で各 idle が読み込まれるので切り替えでチラつかない
- 切り替えると `commitState` → `renderHome` が本体画像と先読みを引き直す
- スタイル別の衣装アンカー補正は `STYLE_ANCHOR_OFFSETS`（cat-image.js）

**設計判断（#66・topic_1781184658026 で合意）**

- 切り替えは**きせかえ編集モードの中**（「見た目を変える」文脈で5歳が自分で見つけられる。ショップでの解放は #126 と被るので将来）
- 画像名は既存も含め **`cat_{style}_{tier}_{mood}` に全部リネーム**（特例分岐を残さない。SW は gen-sw の再生成で古いキャッシュを捨てる。茶トラ15枚は中身が同じでも一度だけ再DLされるが許容）
- **JS の先読みは選択中のスタイルだけ**。SW が `img/cat` 全45枚（~3.8MiB）をプリキャッシュするので、これは通信ではなく**デコード/メモリの節約**。オフラインでの切り替えも保証される
- 立ち耳のロシアンブルーのアンカーずれは、生成側でポーズを揃える（体のバランスが崩れる）のではなく `STYLE_ANCHOR_OFFSETS` で吸収する。実測では頭頂が tora/shiro=y31・russianblue=y35 と差4ユニット（ステージの2%）で軽微なので、**オフセットは空のまま**

### 写真モード（#237）

> 実装: [cat-snapshot.js](../js/cat-snapshot.js)（canvas 合成）・[app.js](../js/app.js) `shareCatPhoto` ｜ テスト: e2e/photo.spec.js

ホームの「📷 しゃしん」で、飾った猫を**1枚の画像**にして共有／保存する。きせかえに「見せたい・残したい」出口を作り、祖父母への共有にも使える。

| 項目 | 仕様 |
|---|---|
| 合成 | `renderCatCanvas(catEl, 600)` が 600×600 の canvas に、画面と同じ z 順（背面 z1 → 本体 z2 → 前面装備 z3 → 前面置物 z5）で描く。うしろへ回したもの（#270）もそのまま。**演出 SVG（`cat__fx`）は対象外** |
| 共有/保存 | `navigator.canShare({files})` が使えれば Web Share、無ければ `a[download]`。**端末内で完結**（サーバ不要） |
| PII | 共有に曲名・こども名を含めない。タイトルは固定「ピアノペット」、ファイル名も固定 `pianopet.png`、`text` は付けない。計測は操作フラグだけ（`cat_photo_shared` / `cat_photo_saved`） |
| 背景 | クリーム色（`#fff6ee`）で塗ってから合成する（透過のまま共有すると環境によって黒くなる） |

**設計判断（#237）**

- レイアウトの計算（ANCHORS/ITEM_BOX/SCENE_BOX＋`itemLayout`）を**作り直さず**、描画済み DOM の `<g transform>` と `<image>` の box を読んで canvas に落とす。計算を二重に持つと #168/#205 や box の変更のたびに画面と写真がずれるので、「画面の DOM が唯一の正」にした
- 画像は同一オリジンなので canvas が汚染されず `toBlob` が使える
- SVG を丸ごと data URL にする案は不採用（画像として読み込んだ SVG では `<image>` の外部参照がブロックされる）

- `sessions` / `streak` / `pet`（`inventory` 込み）から判定し直すので、編集・削除で条件を満たさなくなれば外れる
- **判定のタイミング**

  | バッジ | いつ判定するか |

  | `affinity_max` | えさやりの直後（#309） |
  | `praise_all3` / `tempo_all3` | はなまる／テンポを付けた直後（#320・`setSessionMark`） |

- `affinity_max` を取った瞬間は `playCelebrate` も出す（`feedList` のクリックハンドラで、`gainedBadges` に `affinity_max` が含まれるときだけ）。再生はホームへ戻ったとき（→ [猫の表示とインタラクション](#猫の表示とインタラクション)）。バッジのポップアップはえさやりポップアップが閉じた後（#294）

**設計判断**

- **何を足したか（#298）**：5種だと練習が進んだ時点で全部埋まり「次の目標」が無くなる。連続（14/30）・累計（500/1000）・記録日数（100）で上を伸ばしつつ、**回数以外の軸**として曲の種類（`songs_*`）と1日の集中（`big_day`）を足した。全部が「長く続ける」軸だと一本道になり、体調などで連続が切れた日に手がかりが残らない
- **曲名の数え方（#298）**：`trim` だけで、全角/半角・ひらがな/カタカナの揺れは畳まない。[song-color.js](../js/song-color.js) の `songHue` も `trim` だけで色を決めるので、**「ちがう色の曲＝ちがう曲」**が画面上で一致する
- **`freeze_earned` は作らない（#298）**：`updateStreak` は救済も含めて `current` を必ず +1 ずつしか進めないので、`best >= 3` ⟺ どこかで `current === 3` を通った ⟺ お休み券を1枚はもらっている。`streak_3` と同じ条件になる
- **13→24種（#309・複数人格ブレストで選定）**：親の追加要望を受け、保育士／ゲームデザイナー／データ実現性／懐疑派レビューの4視点で考え、既存に無い軸（`tempo`・`praise`・`pet.affinity`・所持品・1日の曲数・カムバック）を中心に11種を選んだ
  - 見送った案：曜日のレッスンなどカレンダー依存（家庭のレッスン頻度で不公平・日付境界のバグ）／`challenge_2000` 等の単純なインフレ（最難関の2倍は難しすぎる）／`praise` 回数の累積（親の操作への依存が高すぎる。多様性は `praise_all3` で確保）／複数曲マスターや所持品・置物の収集（練習でなくコイン消費のバッジになる。`song_master_first`・`first_outfit` の1個ずつに絞った）
- **`goal_hit_5` は固定 `GOAL_BONUS_THRESHOLD`（=10）**：#238 と同じく、目標の変更が過去の資格を動かすのを防ぐ
- **`comeback` は日付の素の間隔だけを見る**：`streak.current`/`best` はお休み券で救済した連続も含むので、それとは別に「本当に途切れたあとの立て直し」を評価する。3日以上（`missed>=3`）空いたあと3日連続で記録したかを `sessions` の日付から毎回判定する。レッスン日（#393）で空白が埋まっても変わらない
- **`first_outfit` は所持で判定（レビューで修正）**：`equippedItems`（付けている）は自由に外せるので、「服を脱がせた」だけでバッジが外れてしまう。購入は取り消せず増える一方の `inventory` を使い、置物（`slot:'scene'`）は除く。説明文も「きせた」→「かった」にした
- **`affinity_max` で `playCelebrate` も出す**：娘がなかよしMAXに届いたときの追加要望。練習記録の「節目は特別演出」（`celebrateRecord`）と揃える
- **操作の直後に判定し直す（#309 #320）**：これらは `pet`/`inventory` やスタンプのタップで条件が決まるので、購入・えさやり・スタンプの各ハンドラ（[app.js](../js/app.js)）でも `checkBadges` を呼ぶ。呼ばないと「条件を満たしているのに次の記録までバッジ画面が🔒」になり、しかもその記録が `badgeCount>0` 扱いで動画クリップの抽選から外れる
- **スタンプを外しても剥がれない**：`checkBadges` は `state.badges` を Set の初期値に引き継ぐので追加だけ。剥がすには `recomputeState` を通す必要がある（編集・削除と同じ）が、「スタンプを1つ外したら褒めバッジが消える」は過剰なのでそのまま
- **判定の入力は `sessions` / `streak` / `pet` だけ**：どれも全再計算で決まるので、バッジも決定的に導ける

## ねこスタンプちょう（#409）

> Issue: #409 #410 #413 #415 #417 #419 ｜ 実装: [stamp-book.js](../js/stamp-book.js)（ロジック）・[stamp-view.js](../js/stamp-view.js)（画面）・[stamp-settings.js](../js/stamp-settings.js)（せってい）。3つとも遅延読込 ｜ テスト: tests/stamp-book.test.js・e2e/stamp-book.spec.js

1日10回以上ひいた日に猫スタンプが1こもらえ、親が決めた個数がたまったら**現実のごほうび**（好きなものを買う・出かける等）をもらう。紙のスタンプ帳に毎日1こずつ押すイメージで、コインより長い目標を作る。保存先は [data-model.md](./data-model.md#stampbook409) の `pet.stampBook`。

**仕様**

| 項目 | 仕様 |
|---|---|
| もらえる日 | その日の合計が **10回以上**（固定 `STAMP_THRESHOLD`）。何回ひいても**1日1こ**。同じ日が複数件でも合計で見る |
| 数える範囲 | カードの開始日〜今日。古い順に、カードの個数で打ち止め。まとめモードで後から入れた過去日も、開始日以降なら入る |
| レッスン日 | **数えない**（`sessions` に記録がない日は対象外）。レッスン日でも自宅で10回ひけば通常どおり |
| 記録の修正・削除 | 10回を下回ればそのスタンプも消える（押した日の記録は残るが、もらえる日でなくなるので表示されない） |
| 押す | もらえる日は「🐾 おしてね」が光り、**子がタップして押す**。画面が暗くなり、**画面いっぱいの大きさで**肉球が降りてきて「ぺたっ」とスタンプが出る（効果音 `peta`）。そのあと縮みながら押したマスへ飛んで収まる（計 約1.6秒・肉球の着地は約0.4秒で、効果音もその瞬間に鳴る）。押し忘れた日は後からでも押せる |
| ごほうび | 個数ぶん押し終えると、最後のスタンプが収まったあと**全画面のお祝い**（#419）：画面を暗くし、大きな「ごほうび ゲット！」が ぽんっと跳ねて出て、ごほうびの なかみ・「おうちの ひとに みせてね」を大きく出し、5色の紙吹雪を降らせ続ける。音は専用のファンファーレ `fanfare`（ソドミソと駆け上がって高いドの和音・[sound.js](../js/sound.js)）。「やったね！」かどこかをタップ（Esc・戻るでも）で閉じる。閉じたあとのカードには「🎉 ごほうび ゲット！ おうちの ひとに みせてね」が残る |
| 絵柄 | 猫の姿10種（`STAMP_DESIGNS`）。色は姿ごとに固定で5色×2種。日付だけから決まる（`designForDate`）。[一覧](#ねこスタンプの絵柄410413) |
| ホーム | きょうの もくひょう の下に進捗行（`#stampHomeLink`）。押せるスタンプがあれば「🐾 スタンプを おしてね！（n/N）」で強調し、タップでスタンプタブへ。カードが無ければ出さない |
| おわった カード | スタンプタブの下に一覧（ごほうび・こすう・もらった日） |

**せってい（親ゲートの内側）**

- ごほうびの なかみ（20文字）・えもじ（8種・`REWARD_EMOJIS`）・なんこで ごほうび（**5〜60**）を決めて「カードを つくる」
- 進行中のカードは同じ欄で「なおす」（開始日は変わらない）
- うまったら「ごほうびを あげた」で おわった カードへ移し、次のカードを作れる。同時に進めるカードは1枚

**設計判断**

- **しきい値は10回で固定し、`pet.dailyGoal` に連動させない**：もらえる日は記録から毎回導出するので、目標を変えると過去のスタンプが付いたり消えたりする（#238 と同じ理由）。ユーザー合意済み。ごほうびの重さは「なんこで ごほうび」で調整する
- **もらえる日は導出、押した日だけ保存**：記録の修正・削除・マージのたびに整合を取る処理が要らない（バッジと同じ）。押すという子の操作だけは記録から導けないので `pressed` に持つ
- **カードは開始日から数える**：作る前の記録で一気に埋まると「毎日1こずつ」にならない。次のカードの開始日は**前のカードの最後のスタンプの翌日**にして、うまってから次を作るまでの日を持ち越す（親が作り忘れても子のがんばりが消えない）
- **おわったカードは日付ごと固定**：ごほうびを渡した後に過去の記録を直しても、思い出のカードが崩れない
- **絵柄は日付から決める**：曲の色（#122）と同じく保存不要で端末間で一致する。単純なハッシュだと同じ絵が続くことがあるので、種類数（10）日ごとのブロックの中で全種を種付きシャッフルした順に配る（ブロック内で重複なし・ブロックごとに並びが変わる）
- **押したら先に保存し、演出は後**：演出の途中でタブを移っても押した事実が消えない。押している間はクラウドからの再描画を止め、演出中のマスを作り直さない
- **「おしてね」は影の明滅**：拡大縮小だとボタンが動き続け、Playwright が「静止しない」としてクリックできなかった（子どもにも押しにくい）。`prefers-reduced-motion` では点滅だけ止め、ぺたっの演出は遊びの手応えなので残す（kabutetsu #75〜#77 と同じ方針）
- **押す演出は画面いっぱい（#415）**：マスの中（約60px）だけの「ぺたっ」では手応えが弱かった
  - 暗幕（`z-index:80`・`pointer-events:none`）の中央に幅 `min(80vw,60vh)` の大きい版を出し、1.25秒後にマスの位置・大きさへ0.35秒で移して消す
  - **押す動きは等倍の0.6倍速**（#417）：等倍の0.7秒だと「押した！」感が出にくいとユーザー判断。キーフレームは増やさず `getAnimations({subtree:true})` の `playbackRate` で遅くする（css は増えない）
  - 肉球の着地が約0.41秒に遅れる。効果音 `peta` は頭に0.25秒の間がもともと入っている（等倍の着地に合わせてあった）ので、タップ時に `unlockAudio()` で解錠だけして 160ms 後に鳴らし、0.41秒の着地に合わせる
  - マスは最初からスタンプ入りで描き、着地まで `visibility:hidden`（飛んできた絵とマスの絵が重ならない）
  - **CSS は1行も足していない**：css 予算の余白が 0.1 KiB しかない。大きい版は既存の `.sb-cell--peta`／`.sb-paw` のキーフレームを使い回し、マスへ飛ぶ動きと暗幕のフェードは stamp-view.js の Web Animations API（`element.animate`）にした（js-lazy 31.4→32.0/32 KiB・2026-11-18 実測）
  - 絵柄は 192px のまま。375px 幅だと約1.6倍に拡大されるが、水彩のにじみの絵なので粗さは目立たない（作り直しは不採用）
  - 暗幕は毎回作り、自分の要素だけを消す（使い回すと遅延 cleanup が次の演出を壊す）
- **ごほうび ゲットは全画面で、閉じるまで出す（#419）**：以前はカードの文字が少し跳ねてレベルアップ音が鳴るだけで、何十日もかけた達成の重みに見合わなかった
  - 子が「おうちの ひと」を呼びに行って見せられるよう、時間で消さずタップで閉じる（紙吹雪も閉じるまで降り続ける）
  - モーダルは `dialog.js` で開き、フォーカスを「やったね！」へ移し、Esc・戻るでも閉じる
  - CSS は足さず、インラインスタイルと Web Animations API で書いた。使わなくなった `.sb-goal--new` の CSS は消した
  - **ごほうびの絵文字は出さない**（#423・ユーザー判断）：親が8種から選ぶ飾りで、ごほうびの なかみとの結びつきが弱く、大きく出しても意味が伝わらない。跳ねる動きは見出しの文字に移した
  - 音は既存の `levelup`（記録のレベルアップと同じ）を使い回さず、達成専用にした
  - js-lazy は 32.0→32.8 KiB 増えたが、スタンプのタブを開いたときだけ読むので起動に影響しない（枠の変更は [perf-budget.mjs](../../../scripts/perf-budget.mjs) のコメント）
  - `prefers-reduced-motion` でも止めない（遊びの手応え）
- **古い せってい画面からは確定しない**：せっていは開いたときに描くだけなので、別の端末で「ごほうびを あげた」→次のカード作成のあと、もう1台の古い画面のボタンを押すと、新しいカードを終わらせたり上書きしたりした（レビューで発覚）。ボタンにカードの `id` を持たせ、押した時点のカードと違えば描き直すだけにする。`redeemCard` も、うまっていないカードは終わらせない
- **実在しない日付は数えない**：`normalizeState` は書式しか見ないので、`2026-11-00` のような値が認証なしの Firestore やバックアップから入りうる。数えると絵柄の計算が NaN になり、押した瞬間の例外でタブが固まる（押した日は保存済みなのでリロードしても直らない）。判定と次の開始日の計算で実在しない日を捨て、押す処理は `finally` で必ず解除する
- **個数を減らしたとき**：子は好きな順に押せるので、後ろの日を押したあとで親が個数を減らすと、その押印は今のカードの枠から外れて見えなくなる。データは残り、ごほうびを あげた あとの次のカードで数える（`pressed` は最後のスタンプより後の日を残す）
- **同期**：realtime は `pet` ごと cloud-wins。初回マージは [data-model.md](./data-model.md#63-初回取り込みのマージmergecloudinitialローカル優先)
- **遅延読込**：タブ・ホームの進捗行・せっていでしか使わないので3モジュールとも動的 import。起動時に増えるのは `normalizeState` の矯正（信頼できない入力の関門なので entry）と配線だけ

### ねこスタンプの絵柄（#410・#413）

- `img/stamp/{id}.webp`（192×192・透過・色を焼き込み済み）
- 描画は `stampFace`（stamp-view.js）の `<img>` 1つ。タブのマスと「ぺたっ」の両方で使う
- 肉球 `paw.webp`（`#e0577a`）は「ぺたっ」で降りてくる `.sb-paw`

| 色（`STAMP_INKS`） | 値 | 姿（id） |
|---|---|---|
| あか | `#e0574f` | ねこパンチ（`punch`）・ジャンプ（`jump`） |
| あお | `#3d86d4` | なべねこ（`nabe`）・おさかな（`sakana`） |
| みどり | `#3a9e68` | のび〜（`nobi`）・ふみふみ（`fumifumi`） |
| むらさき | `#9563cc` | おじぎ（`ojigi`）・しっぽハート（`heart`） |
| ちゃいろ | `#b5793f` | けいとだま（`keito`）・はこ（`hako`） |

- 割り振りは意味で寄せた（元気＝あか、水・ねむり＝あお、のびのび＝みどり、やさしい仕草＝むらさき、もの＝ちゃいろ）

**設計判断（#410）**

- **黒インクで描き、輝度からアルファを抜いて色を焼き込む**：色インクで直接描くと、生成ごとに同じ「あか」でも色相・濃さがぶれて5色に揃わず、色付きのにじみを紙から抜くと白フチや色ずれが残る。黒なら輝度＝インク量なので、にじみの濃淡がそのままアルファになり、色は指定値どおりに揃う
- **CSS で塗らない**（`mask-image`＋`background-color` 案は不採用）：css の余白が 1 KiB 未満で、`-webkit-mask` の併記とライト/ダーク×2の色トークンを足す余地が無い
  - 押したマスは背景なし（`.sb-cell--done`）でカードの `--surface` に乗る。5色はライト（#fff）・ダーク（#2a2327）の両方に非テキスト 3:1 以上（最小 3.35＝みどり/ライト、3.61＝むらさき/ダーク。肉球 3.61/4.25）なので、テーマで色を変える必要も無い
  - `<img>` にしたことで仮絵柄の span と CSS が消え、css は 15.0→14.9 KiB に減った（js-lazy も増えていない・2026-11-17 実測）
- **色の記録は `STAMP_INKS`／`ink` に残す**：描画には使わないが、「姿ごとに1色・5色」という要件をユニットテストで固定し、画像を作り直すときの色の正をソースに置く
- **画風**：最初は「濃いベタ塗り」を指定したら版画調になり、水彩のにじみが消えた（猫本体・衣装と画風が割れる）。「水っぽいインク・灰色のにじみ」で全姿を描き直し、小さなマスで淡い部分が消えないようアルファに γ0.6 をかけた
- **192px**：マスは5列で、375px 幅のとき約 60 CSS px。3x 端末で足りる最小の 192px にした（16種のとき 256px だと合計 615 KiB、192px で 340 KiB。#413 の10種＋肉球で 215 KiB）。マスを大きくするときは作り直す
- **作り方**：Google Flow（Nano Banana 2.1・1:1）で各姿2候補から1枚 → 紙の明るさ（輝度90パーセンタイル）とインク（1パーセンタイル）で正規化してアルファ化（0.10 未満は紙のザラつきとして捨てる・γ0.6）→ 外接矩形から余白10%（肉球22%）の正方形に切り出し → 192px・WebP q80（alpha_quality 90）。全枚をライト/ダーク・60px 縮小で目視検品

**設計判断（#413・10種への見直し）**

- **削った6種**：ねんね・ばんざい・かおあらい・おんぷとダンス・ピアノをひく・おすわり（ユーザー判断）。残りを**5色×2種**に配り直した。16種のときは あか4・他3 で、あかだけ多かった。「どの色も同じ数」をユニットテストで固定する
- **描き直した3種**
  - ねこパンチ：右端から差し出された猫じゃらしに前足を出す構図（パンチの先に的があると、何を叩いているか小さなマスでも伝わる）。茎は輪の外まで描かれるので、輪の外周で切ってから切り出す（そのままだと外接矩形が広がり、この1枚だけ輪が小さく左に寄る）
  - ジャンプ：「飛び猫」写真のジャンル（空中で体を伸ばしきり、前足を前へ・後ろ足を後ろへ）に寄せた。最初の候補は水平に飛ぶ姿が小さく点のように見えたので、猫を大きく・右上へ斜めに飛ぶ構図にした
  - まるくなる → 「なべねこ」（土鍋で丸くなって寝る）に替え、id も `marui`→`nabe`
- **過去の日の絵柄が変わる**：絵柄は日付から決める（#409）ので、種類数が変わると押した日も含めて振り直される。押した事実（`pressed`）は日付なので消えない。公開直後で見た目が変わるだけなので、旧16種を残す互換は作らない
- **色のコントラスト**：5色は変えていないので #410 の測定がそのまま成り立つ

## 育成・報酬ロジック

> Issue: #148 #167 #238 #393 ｜ 実装: [game.js](../js/game.js)（純粋関数） ｜ テスト: tests/game.test.js・e2e/record.spec.js・e2e/reward-popup.spec.js・e2e/lesson.spec.js

### コインと XP

| 条件 | コイン | XP |
|---|---:|---:|
| 1回練習（1曲1回） | +1 | +1 |
| 目標達成（その記録の合計10回以上・固定 #238） | +5 | +3 |
| 連続がちょうど3日に届いた | +10 | — |
| 連続がちょうど7日に届いた | +30 | — |
| レッスン日（#393・1日につき） | +10 | +5 |
| きょうのおまけ（当たったとき） | +3 | — |

- 必要累計 XP：Lv2=20 / Lv3=50 / Lv4=90 / Lv5=140 / Lv6 以降は前のレベル +60 ずつ

### きょうのおまけ（#148）

- **練習を記録した日だけ**、その日の**最初の記録**で `BONUS_CHANCE`（20%）の確率で `BONUS_COINS`（3コイン）。当たったら専用のポップアップ（🎁）
- 抽選は app.js（`rollDailyBonus`）。額は記録の `bonusCoins` に保存し、`recomputeState` で戻す（→ [data-model.md](./data-model.md#session)）。同じ日の2件目以降は抽選しない

**設計判断（#148）**：「練習しなくても得するログインボーナス」は習慣化と矛盾するので不採用。練習に連動させた。

### ストリーク（連続練習）とお休み券

- 前日に練習していれば連続。同じ日の二重記録では増えない
- **お休み券（`streak.freezes`）**：ちょうど3日、および7日ごと（7・14・21…）に +1枚（**上限2枚**＝`MAX_FREEZES`）
- 間が空いたとき、抜けた日数ぶんの券があれば使って連続を保つ。足りなければ1に戻る。**戻っても券は没収しない**
- 券で連続を守ったら専用のポップアップ

**設計判断**：連続の報酬は非対称。コインの節目（+10/+30）は **3日・7日に届いたときだけ**（インフレを抑え、始めのうちに前倒し）。お休み券は **7日ごと**に出し続ける（長く続ける動機）。コインは `calcRewards`、券は `isFreezeMilestone` と別のロジック。

### レッスン日（#393）

親が登録した日（`pet.lessonDates`）は、記録の有無によらず**練習した日として連続に数える**。レッスンの日は自宅練習を記録できず、おやすみけんで凌ぐしかなかった。

| 項目 | 仕様 |
|---|---|
| 登録 | せってい →「ピアノの レッスンび」で日付を選んで「いれる」。一覧の「×」で取り消し（5秒間は「もとに もどす」で戻せる・#398）。当日・過去日（入れ忘れ）・先の日付（予定。一覧では「よてい」）を入れられる |
| 一覧の表示 | 先の予定はすべて、過去日は新しい順に3件。「もっと みる」で12件まで（#401） |
| 反映 | 今日以前の登録日だけが対象。先の日付はその日が来たら加算される。起動時に登録日があれば毎回再計算し、数値が動いたときだけ確定してコインポップアップで知らせる。登録・解除はどちらも全再計算 |
| 報酬 | 1日につき `LESSON_COINS`(=10)・`LESSON_XP`(=5)。自宅練習も記録した日は通常報酬に上乗せ（連続は二重に数えない）。連続の節目コイン（3日+10／7日+30）は練習を記録した日だけ。おやすみけんの付与（3日・7日ごと）はレッスン日でも付く |
| おやすみけんの二重付与 | レッスンを反映済みの当日に練習を記録すると、逐次更新では節目判定が再び立つ。`submitRecord` は `date === lastPracticeDate` のときも全再計算で確定する |
| 表示 | ホームに「🎹 きょうは レッスンび！」、カレンダーの該当日に🎹 |
| 実装 | 一覧のせってい画面は遅延読込（`lesson-settings.js`） |

**設計判断（#393）**

- **`sessions` には入れない**：レッスン日は曲も回数も無い。偽の記録にすると曲別集計・カレンダー・バッジ・「同日1件」の統合・墓標（`deletedDates`）と干渉し、マージでも衝突する。`pet.lessonDates` に日付だけ持ち、`recomputeState` が記録と日付順に並べて再生する
- **報酬は記録でなく再計算で出す**：登録の追加・解除で増減しても、`sessions` と登録日から常に同じ結果になる。`coinsEarned` には含めない（記録カードの表示は通常報酬のまま）
- **経路は全再計算に一本化**：まだ反映していないレッスン日が記録日までにあるとき、`submitRecord` は `applySession` の逐次更新ではなく `commitRecordedSessions`（全再計算）で確定する（`hasUncreditedLesson`）。日付をまたいで開いたままの記録で、レッスン日を挟まずに連続を数えるのを防ぐ
- **曜日の固定登録にしない**：想定は月3回のレッスンで、補講・休講で曜日が崩れる。日付を直接入れる方が実態に合い、いつから有効かの版管理も要らない
- **おやすみけんの自動付与は不採用**：上限2枚・節目の付与だけでは毎週のレッスンを賄えない
- **解除は墓標（`pet.lessonRemoved`）で伝える**：初回マージ（復帰時の再同期を含む）は登録の union なので、墓標が無いと、解除のとき前面にいなかったもう1台の古い登録が毎回戻る。再登録すると墓標を外す。realtime は `pet` ごと cloud-wins
- **取り消しの猶予（#398）**：スクロール中の誤タップで連続が切れないように
- **一覧の件数（#401）**：予定が多くても誤登録した過去日を解除できるようにした。常に12件だと設定画面を占めていた

## Service Worker のキャッシュ戦略

> Issue: #303 #317 #318 ｜ 実装: [sw.js](../sw.js)（`gen-sw` が生成）・[scripts/gen-sw.mjs](../../../scripts/gen-sw.mjs) ｜ テスト: e2e/sw-clip-cache.spec.js・`gen-sw:check`（CI）

`gen-sw` が作る `APP_SHELL` を install 時にプリキャッシュし、fetch は次の3通り。

| 対象 | 戦略 |
|---|---|
| 同一オリジン（下記以外） | **network-first**（`fetch(request, { cache: 'reload' })` で HTTP キャッシュも通さない）。**`response.ok` のときだけ**キャッシュを更新（#317）。取れないときだけキャッシュを返す。ナビゲーションの代わりは `./index.html` |
| 記録・えさやりクリップ（`video/*.mp4`・`isClip`） | **cache-first**（#303）。初回再生後は SW キャッシュに常駐する |
| 外部オリジン | `caches.match` → 無ければ `fetch`。キャッシュに入れる経路が無いので実質は素通し |

**キャッシュの版**

- `video/*.mp4` はプリキャッシュと予算の列挙（`listAssets()`）には入れず、`listHashOnlyAssets()`（#318）で**ハッシュにだけ**載せる
- 動画を1バイトでも書き換えると `sw.js` の `CACHE` 名が必ず変わり、古いキャッシュは `activate` で捨てられる

**設計判断**

- **network-first＋`cache: 'reload'`**：ES モジュールの `import` には `?v=` を付けられず、HTTP キャッシュが効くと古い版が残り続ける。毎回サーバへ確かめて**版のずれを構造的に断つ**
  - 代償はオンライン時のシェル取得が毎回ネットワーク待ちになること。体感で問題になれば `?v=` 付き JS を stale-while-revalidate にする等、シェル側で手当てする
  - #142 の「ローカルファースト」は **state の読み込み（localStorage を同期で読んで即描画）**の話で、シェル配信の話ではない。**混同しないこと**
- **失敗レスポンスを焼かない（#317）**：5xx/404 をキャッシュすると、オフライン時だけ白画面になる
- **外部オリジンは素通し**：Google Fonts はオフラインで取れずフォールバックのフォントになる（機能は落ちない）。外部依存をキャッシュで延命しない
- **クリップだけ cache-first（#303）**：`prime` の先読みは、network-first のままでは**オンラインで一度も効いていなかった**（先読みでキャッシュに入れても、`tryPlay` は別の `<video>` で改めてネットワークへ出る）。1秒の再生タイムアウトに間に合わず演出が出ないことがあった
  - `PLAY_TIMEOUT_MS`（1秒）を延ばす案は、フォールバックを遅らせて間延びさせるだけで根本が直らない
  - `prime` の `<video>` を `tryPlay` で使い回す案は、#296 の世代管理（`_clipGen`）・`teardown` に手を入れることになりリスクが高い
  - SW を数行変えるのがいちばん小さい
- **動画もハッシュに載せる（#318）**：cache-first でも古い版が返らないのは、URL が同じなら中身も同じという約束に頼っているからではなく、内容が変われば `CACHE` 名が変わるから
  - 不採用：クリップの URL に `?v=` を個別に付けて1本だけ更新する案。`CLIPS`（[cat-video.js](../js/cat-video.js)）に版管理が戻り、#303 の cache-first のキー（URL そのまま）に手を入れることになる。`gen-sw.mjs` も index.html 以外に版を撒く必要が出る
  - 代償：クリップ1本の差し替えで `APP_SHELL` 全量（img 含む）が再プリキャッシュされる。これは元々どの css/js 変更でも起きる既存の挙動

**設計判断**

- **DI を作らず偽モジュールを配る（#277）**：`app.js` が `await import('./cloud.js')` で動的に読む（#142）ので、本番コードを1行も変えずに実経路を通せる

  - 追加5件は、アプリ側の #142 / #242 を取り消すと3件が落ちることを実測済み
- **報酬ポップアップのテストが効いていること（#323）**：`showPopup` 冒頭の前サイクル解除（`clearTimeout`/`removeEventListener`）を削ると4本目が、`nextDelay += 2200` の直列化を外す・`rewards.frozeDays > 0` の分岐を消す・`showBadgePopup` の `showNext` を1件目で切ると1本目が落ちることを実測済み
- **#261 の退行ガードはページ内で観測する**：1回目の表示直後に2回目を押しても再現しない（1回目の `transitionend` リスナーがまだ無い）。再現には、1回目の `duration` 経過でフェードアウトが始まった直後（旧リスナーがある窓・実測で約250ms）に2回目を重ねる必要がある。固定の `waitForTimeout` で窓を狙うと CI の遅れで静かに空振りする（実測）ので、ページ内の `MutationObserver` で「`--show` が外れた瞬間」を見て2回目を撃つ
  - `.coin-popup` の `[hidden]` の是正後、`reward-popup.spec.js` はクラスベースの回避策をやめ素直な `toBeVisible`/`toBeHidden` に戻した。`shop.spec.js` の #261 ガードは、250ms の窓を捉える精度が Playwright のポーリングでは足りないので `MutationObserver` のまま
- **`Math.random` のモックは値域の中で**：`Math.random = () => 1` は `[0,1)` の外で、`cat-video.js` の Fisher-Yates が範囲外スワップでバッグを壊す（穴が入る）。`0.999` のように値域に収める

**まだ埋まっていない空白**

- **オフライン / SW の実行**：ほとんどの project は `serviceWorkers: 'block'`（キャッシュの干渉を避けるため）なので install / activate / fetch が走らない。担保は `gen-sw:check`（列挙の一致）と、`sw-clip-cache.spec.js`（`serviceWorkers: 'allow'`）の限定的な fetch 経路の検証（クリップの cache-first #303／失敗レスポンスを焼かない #317）だけ。install/activate と全面的なオフライン起動は未検証（#289）
- **`prefers-reduced-motion`**：報酬ポップアップの確定（保険タイマー）は `e2e/reward-popup.spec.js` の `@ prefers-reduced-motion` で検証済み。猫の呼吸/ジャンプ/ハート等・スタンプの登場・バーの伸びの停止は CSS だけで E2E なし。えさやりクリップを出さない（先読みもしない）ことは `e2e/shop.spec.js` で検証済み（#294）
- **えさやりクリップの WebKit 実再生**：`@compat` のえさやりフォールバックはクリップを abort した経路だけ。「読めるが `playing` が来ず上限で諦める」WebKit の経路と、実機 iOS での再生は未検証（#294。記録クリップは実機 iOS で再生できている）
- **サウンド**：音程などの計算は単体テスト、サウンドOFFでも威嚇を出し分けることは `e2e/cat-interaction.spec.js`。鳴った音そのものは未検証
- **曲の色**：単体テストのみ
- **ダークモード**：切り替えと保存値（`data-theme`・`pp-theme`）は `e2e/settings.spec.js`。テーマごとの見た目は未検証
