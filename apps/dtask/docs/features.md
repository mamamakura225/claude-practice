# 機能一覧

実装済み機能のリファレンス。コード参照は [app.js](../app.js) を基準とし、関数名で指す（行番号はドリフトするため極力使わない）。

## ビュー

### リストビュー
- 1列でタスクカードを縦並び表示
- スワイプ操作（モバイル）：左で削除背景表示、右で完了背景表示
- カード上に期限・優先度・プロジェクト・タグ・サブタスク進捗・ステータスを表示。ステータスは優先度バッジと見分けがつくよう、未着手＝枠線のみ／進行中＝青／完了＝緑（`.badge-status-*` #353）

### Kanban ビュー
- `todo` / `inprogress` / `done` の3列
- ステータスはセレクトで変更
- サブタスクのインライン展開も Kanban カードで対応
- スマホ幅（〜767px）は横スクロール。列幅は画面の85%（最大320px）固定で、次の列の端を覗かせてスクロールできることを示し、列単位でスナップする（#353）

> **設計判断 (#353)**: 以前は列が `min-width:260px`＋中身の幅で伸び、長いカードで列が画面外まで広がって件数バッジが切れていた。幅を画面基準で固定し中身を折り返す形にした。85% は「次の列が少し見える＝横に続きがある」手がかりを残すため。不採用案：長いタイトルを省略表示（内容が読めなくなる）、縦積み（3列の関係が一覧できなくなる）。

ビュー切替は画面上部のトグルで行い、選択状態は `state.currentView` に保持。**ビュー形式（list/kanban）は localStorage `dtask_view` に永続化し、次回起動時に復元する**（`switchView` で保存、`init` で復元）。

### 今日やること（ホームビュー）(#33)
- **起動時は常に「今日」プリセットON**で開く（`state.filters.preset` 既定 `'today'`）。preset はビュー形式と違い**復元せず毎回 today に固定**（「起動したらまず今日やることが見える」ため）。手動で「すべて」chip を押せば全件表示に戻せる。
- **達成（ご褒美）空状態**：preset が today で、今日対象タスクが**あるが全て完了**のとき、List/Kanban を隠してビュー非依存の `#todayDoneState` を中央表示する（「今日のタスクは完了！＋次の締切は◯日後」）。`renderTodayDone` / `nextDeadlineInfo` 参照。
  - 次の締切＝`status!=='done'` かつ `deadline > today` の最小日。該当なしは「次の締切はありません ☕」。
- 今日対象が**元々0件**（新規ユーザー等）の場合はご褒美ではなく各ビュー既存の汎用空状態にフォールバック。
- **今日ビューからの追加 (#352)**：「今日」ビューでは、クイック追加は期限チップ未指定でも**期限=今日**で追加する（入力欄のプレースホルダーと読み上げ名でも「期限は今日」と示す）。そのため今日ビューのクイック追加では期限なしのタスクは作れない（期限なしは他のビューか詳細モーダルで期限を消して追加）。詳細モーダルを新規で開くと期限に今日が入る。
- **見えない追加の通知 (#352)**：どの絞り込みでも、追加したタスクが今の絞り込みで表示されない場合はトースト「◯◯を追加しました（今の絞り込みでは表示されません）」と **[すべて表示]**（プロジェクト・優先度・ステータス・検索・プリセットを解除。並べ替えと「完了タスクを隠す」は維持）を出す。

> **設計判断 (#352)**: 起動既定が今日ビュー(#33)になったことで、期限なしのクイック追加が即座にフィルタで消え「追加できなかった」ように見えていた。今日ビュー＝「今日やることを足す場所」と捉え期限を今日にした（Todoist 等の Today ビューと同じ）。黙って期限を付けるのを避けるためプレースホルダーで明示する。今日以外の絞り込みでは期限を推測できないので、通知と戻り道で対処する。0件時の説明的空状態は #114 で扱う。

> **設計判断 (#33)**: `today` プリセットに当日完了済みタスクも含めるのは、統計バー（X/Y 完了）を正しく機能させ完了カードの可視性（完了確認の安心感）を保つため。ご褒美画面の0件判定だけは「残り未完了＝0」（`getFilteredTasks().filter(t => t.status!=='done').length===0`）で行い、フィルタ定義と判定を分離している。

## タスク CRUD

| 操作 | 入口 |
|---|---|
| 追加 | クイック追加バー（タイトルのみ即追加） / 詳細モーダル |
| 編集 | カードの ✏️ / ⋮ メニュー |
| 削除 | ⋮ メニュー / スワイプ（モバイル）/ ホバー時の 🗑️ |
| 完了切替 | カード上のチェック / スワイプ / ⋮ メニューのステータス移動 |
| 並べ替え | ⋮ メニューの「上へ／下へ」/ D&D（デスクトップ） |
| ステータス移動 | ⋮ メニュー（未着手/進行中/完了）/ Kanban のセレクト / D&D |

詳細モーダルでは title / description / category / priority / deadline / tags / subtasks / recurrence を編集可能。

### カード操作メニュー（⋮）(#111)
ドラッグ/スワイプに依存しない**明示的アクションの正規ルート**。カード右端の常時表示「⋮」ボタンから、タップ・キーボードのいずれでも操作できる。

- 項目：**編集 / 上へ / 下へ / 未着手へ / 進行中へ / 完了にする / 削除**（先頭・末尾では上/下を `disabled`、現在のステータスは項目から除外）
- キーボード：`⋮` にフォーカスして Enter で開く → `↑`/`↓` で項目移動、Enter で実行、`Esc` で閉じてトリガーへフォーカス復帰。メニュー外クリック・スクロール・再描画でも閉じる
- ビュー非依存：`#cardMenu` は body 直下の単一ポップアップ（`openCardMenu` が `position:fixed` で配置）。List/Kanban 共通
- 「上へ／下へ」は表示順で隣と入れ替え、`order` を再採番して**手動ソートに切替**（D&D と同じ挙動）。完了化時は `toggleDone` と同様に繰り返しタスクを自動生成
- スワイプ（モバイル）/ D&D（デスクトップ）は**上級者向けショートカットとして維持**。初回のみ ⋮ メニューの存在を軽いトースト（`dtask_hint_actions`）で1回だけ案内

> **設計判断 (#111)**: スマホはホバーが無く、従来のカードアクション（✏️🗑️）は `:hover/:focus-within` でしか出ないためタッチで到達できなかった。⋮ メニューを常時表示の正規ルートにすることで、マウス無し／タッチのみ／キーボードのみのいずれでも移動・完了・削除が完結する。

## サブタスク

- カードのメタ行に進捗バー（n/m、％）
- インライン展開ボタンで一覧表示
- インライン追加・タイトル編集・チェック切替が可能
- サブタスク0件の場合、追加導線（チップ）をメタ行に表示
- 展開状態は localStorage の `dtask_expanded` に永続化（リロード後も維持、削除済みIDは自動クリーンアップ）

## プロジェクト管理

- 専用モーダルで作成・削除（内部実体は category。データモデルは [data-model.md](./data-model.md) 参照）
- カラーピッカーで色指定（カード上のアクセントになる）
- **アクティブプロジェクトの可視化**: サイドバーでプロジェクトを選択するとヘッダーにバッジ表示。バッジの ✕ クリックでフィルター解除
- **自動付与**: アクティブプロジェクトが選択されている状態で `＋ タスク追加` / FAB を開くと、モーダルのプロジェクト欄が自動で選択済みになる（クイック追加バーも同様に既存挙動で付与）
- 「すべて」を選べばプロジェクト横断ビューになる

## フィルタ・ソート

実装は [utils/filter.js](../utils/filter.js) / [utils/sort.js](../utils/sort.js)。

### フィルタ
| 種別 | 値 |
|---|---|
| プロジェクト | プロジェクトID（内部 categoryId） |
| 優先度 | `high` / `medium` / `low` |
| ステータス | `todo` / `inprogress` / `done` |
| 完了非表示 | boolean |
| プリセット | `today`（今日が期限 ＋ 期限切れ未完了。完了確認のため当日完了済みも含む） / `week`（7日以内が期限） / `overdue`（期限切れかつ未完了） |
| 検索 | フルテキスト（タイトル・説明・タグ部分一致）／`#xxx` でタグ完全一致 |

すべて AND 結合。

### ソート
- `manual` — 手動順（`order` フィールド、D&Dで変更）
- `created` — 作成日降順（新しい順）
- `deadline` — 期限昇順（未設定は最後）
- `priority` — 優先度順（high → medium → low）

> **完了タスクは選択ソートに関わらず常に末尾に配置**（[utils/sort.js](../utils/sort.js) の `sortTasks` 内で処理）。

## 定期タスク (Recurrence)

`recurrence.type = daily | weekly | monthly` を設定したタスクは、完了時に次回タスクを自動生成（[app.js](../app.js) `spawnNextIfNeeded` → `spawnNextRecurrence`）。`skipRecurrence` で今回分をスキップ可能（次回分は残る）。

- **どの経路で完了にしても同じ規則**：✓ボタン・スワイプ・⋮メニュー・Kanbanセレクト・Kanban D&D・編集モーダルのいずれでも、「未完了→完了」になったときに1件だけ生成する
- **重複しない**：完了→未完了→完了と戻しても、前回生成した次回分（`spawnedNextId`）が残っていれば作らない。スキップも同様（#351 以前に完了したタスクは `spawnedNextId` を持たないため、それを戻して再完了したときに限り1回重複しうる）
- **毎月の月末**：翌月に同じ日が無ければ月末に詰め、その次は元の日に戻る（`anchorDay`）

> **設計判断 (#351)**: 以前は生成処理が ✓ と ⋮ の経路にしか無く、Kanbanセレクト・D&D・編集モーダルで完了にすると次回分が作られなかった。ステータス変更の全経路から `spawnNextIfNeeded(task, prevStatus)` を呼ぶ形に集約した。重複防止を「完了済みフラグ」でなく次回分IDの実在確認にしたのは、ユーザーが次回分を削除した後に完了し直した場合は再生成されるべきだから。

## ドラッグ&ドロップ

- カードを掴んで並び順を変更（手動ソート時のみ意味あり）
- **デスクトップのみ有効**（タッチ環境ではスワイプ操作と衝突するため）

## キーボードショートカット

実装：[app.js](../app.js) の `handleKeyboardShortcut`

| キー | 動作 |
|---|---|
| `N` | クイック追加バーにフォーカス |
| `/` | 検索バーにフォーカス |
| `?` | キーボードショートカット一覧モーダルを表示 |
| `Ctrl+Z` / `Cmd+Z` | 直近のUndoを実行（60秒以内・最大5件） |
| `Esc` | 開いているモーダルを閉じる／入力からフォーカスを外す |

ヘッダー右側の `?` アイコンをクリックでも同じモーダルが開く。

注意事項：
- 入力中（INPUT / TEXTAREA / SELECT / contentEditable）は `N` / `/` / `?` / `Ctrl+Z` は無効化（`Ctrl+Z` はブラウザのネイティブテキストUndoに任せる）
- `Ctrl+Z` 以外の `Ctrl` / `Cmd` / `Alt` 付き押下はブラウザ標準動作を優先（`Shift` は `?` 入力で使うため除外）
- モーダル表示中は `Ctrl+Z` も無効
- `Esc` は入力中・モーダル表示中でも常に有効

## Undo / トースト

- 削除など破壊的操作の直後にトースト表示
- 5秒以内に「元に戻す」をクリックで取り消し可能
- 「すべて表示」ボタン付きのトースト（見えない追加の通知・7秒）もある（→ [今日やること](#今日やることホームビュー33)）
- ホバー中・フォーカス中はトーストを消さない（キーボードでボタンへ移動する時間を確保）
- トースト消失後も **`Ctrl+Z` / `Cmd+Z`** で直近 60秒以内・最大5件のUndoを実行可能（スタック方式で連続Undo対応）

## 同期状況インジケータ

画面上部に現在の Firestore 同期状態を表示。スマホ幅ではヘッダーに収めるためアイコンのみ表示し、文言は読み上げ用に視覚的に隠す。`local` は「オフライン（📵）」と区別できるよう別アイコン（💾）・別背景にする（#353）。アイコンは `aria-hidden`。

> **設計判断 (#353)**: スマホ幅のヘッダーに全ボタン（メニュー・ロゴ・表示切替・同期・テーマ・?）を収めるため、同期表示は短縮、375px 未満はロゴを「d」マークのみにする（320/360/375/390px で右端と横スクロール幅を実測）。不採用案：ヘッダーを2段にする（縦の表示領域が減る）、テーマ切替をサイドバーへ移す（既存の動線が変わる）。

| 状態 | 表示 |
|---|---|
| `idle` | 何も表示しない |
| `syncing` | 「同期中…」 |
| `saved` | 「✓ 保存済み」（2秒で自動消去） |
| `error` | 「⚠ 保存失敗 [再試行]」 |
| `offline` | 「📵 オフライン」 |
| `local` | 「💾 未同期（この端末に保存中）」— 起動時にクラウドを読めず端末内だけで動いている間（起動直後から表示）、およびオフライン中の編集後（#349）。クラウドが読めた時点でローカル変更をマージして同期する |

## アクセシビリティ

スクリーンリーダー・キーボード操作・コントラストの最低基準を満たすことを目的とする。

### ARIA / セマンティクス

- すべてのモーダルは `role="dialog"` / `aria-modal="true"` / `aria-labelledby` を付与
- トグル状態のあるボタン（リスト/ボード切替、テーマ、プロジェクト絞り込みチップ、クイック追加チップ、ハンバーガー）は `aria-pressed` / `aria-expanded` で現在状態を伝達
- 装飾的アイコン（カラードット、絵文字アイコン、SVG、進捗バー）は `aria-hidden="true"` で読み上げから除外
- フォームの `<label>` は `for=` で input と関連付け（クリックでフォーカス可、SR で正しく読み上げ）
- タスクの完了チェックは `<button aria-pressed>`（旧 div）で、タスクごとに `aria-label` にタイトルを含めて文脈を明示
- 編集・削除・スキップなどアクションボタンも `aria-label` にタスクタイトルを含める

### キーボード操作

- Tab で主要なボタン・入力欄を順に巡回（独自フォーカス順は設定していない）
- `:focus-visible` のアウトラインをカード操作系（task-check / btn-action / subtask-inline-title 等）に追加
- `:focus-within` でタスクカードのアクション群（編集・削除等）を可視化（hover と同条件）
- インライン編集の `subtask-inline-title` は `role="button"` + `tabindex="0"` で Enter/Space により活性化
- ショートカット一覧は `?` キー（[キーボードショートカット](#キーボードショートカット) 参照）

### コントラスト

- 補助テキスト色 `--text-sub` を `#6B7280` → `#525965` に変更し、白系背景（`#F2F3F5`）に対しても WCAG AA（4.5:1）を満たす
- ダークモードの `--text-sub: #9AA0AC` は `--bg: #0F1117` に対し約 8:1 で AA 達成

### 定量監視

- Lighthouse Accessibility スコアは CI の `lighthouse` ジョブで定点観測（閾値 ≥ 0.95、警告のみでブロックはしない）。詳細は [testing.md](./testing.md) を参照

- スワイプの「端の控えめなアフォーダンス」（初回ヒントは実装済み・#111）

## XSS 対策

外部入力をDOMに挿入する箇所はすべて [utils/html.js](../utils/html.js) の `escHtml` を経由。
