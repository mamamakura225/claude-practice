# 要件定義

何を・誰のために作るか。ふるまいの詳細は [features.md](./features.md)、方式は [architecture.md](./architecture.md)。

## 目的

個人が日々のタスクを軽快に追加・整理し、**どの端末からでも同じ状態で**扱えること。

| 項目 | 内容 |
|---|---|
| 利用者 | 個人（単一ユーザー） |
| 端末 | デスクトップ／モバイル（操作系を出し分け） |
| 認証 | なし（Firestore セキュリティルールで制御） |

## 機能要件

- **ビュー**：リスト／Kanban（未着手・進行中・完了）。起動時は「今日やること」（今日締切＋期限切れ未完了）を表示し、今日分を全て終えたら達成画面。ビュー形式は前回値を復元
- **タスク**：追加（クイック追加バー／詳細モーダル）・編集・削除・完了・並べ替え。どの操作もドラッグ／スワイプ無しで完結できる（⋮メニュー）
- **属性**：期限・優先度・プロジェクト・タグ・サブタスク・繰り返し（毎日／毎週／毎月、スキップ可）
- **整理**：絞り込み（プロジェクト・優先度・ステータス・今日／今週／期限切れ）、検索（全文・`#タグ`）、並べ替え
- **操作補助**：キーボードショートカット、Undo（トースト＋`Ctrl+Z`）
- **表示**：同期状況、ライト／ダーク、文字サイズ（標準／大）

## 非機能要件

| 区分 | 要件 |
|---|---|
| データ・同期 | 端末間でリアルタイムに同期する。オフライン・障害時もUIは起動し、端末内で操作を続けられる。**未同期中の操作でクラウドの既存データを失わない** |
| プライバシー | エラー監視・利用計測は任意（鍵が無ければ無効）。送るのは操作種別と頻度のみで、タスクの内容は送らない |
| セキュリティ | 外部入力は必ずエスケープしてDOMへ入れる |
| アクセシビリティ | キーボードのみ・タッチのみで全操作できる。表示中の文字はライト／ダークとも WCAG AA。タップ領域は 24px 以上 |
| 品質 | 純粋ロジックは単体テスト、主要フローは E2E。CI が通ったときだけデプロイ |

## スコープ外

- 複数ユーザー・共有
- 数百件を超える規模（単一ドキュメント全件同期の再設計が必要）
- モーダルのフォーカストラップ
